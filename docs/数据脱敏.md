# 数据脱敏（上云前）

| 属性 | 内容 |
|---|---|
| 文档类型 | 技术方案 |
| 适用场景 | 使用云端大模型时的数据防泄漏 |
| 维护状态 | 生效 |
| 最后整理 | 2026-11-09 |
| 代码位置 | `backend/app/services/data_guard.py` |

## 1. 解决什么问题

`doc-nexus-ai` 会把用户内容送到模型端点。当端点是**公网云模型**（通义、DeepSeek、OpenAI 等）时，
对话里出现的客户名、手机号、身份证、单价金额等会离开本机，构成数据泄漏风险。

本方案在**出网前**统一脱敏，并对无法脱敏的出口（图片、音频）默认拦截。

## 2. 五条出网路径（都要管）

只改聊天主链路是不够的——用户数据实际从 5 条路径流向模型：

| # | 出口 | 位置 | 送去的内容 | 处理方式 |
|---|---|---|---|---|
| 1 | 聊天 / 智能体主链路 | `pi_runtime/model_proxy.py` `prepare_model_proxy_request` | 完整 messages、system prompt | 脱敏 + 响应还原 |
| 2 | 会话标题 | `chat_title_service.py` | 对话原文 | 脱敏 |
| 3 | 个人记忆抽取 | `user_memory_extractor.py` | 整段对话原文 | 脱敏 |
| 4 | 文档向量化 | `pgvector_store.py` | 切块后的正文 | 一致性匿名化 |
| 5 | 图片理解 | `vision_fallback.py` | 图片 | **默认拦截** |

> 音频（`asr.py` 转写）、语音合成（`tts.py`）同样无法脱敏，按图片同一策略处理。

**关键插入点是路径 1 的 `prepare_model_proxy_request`**：它已经把请求体解析成 dict
并重新序列化，是全链路唯一能改到「即将出网字节」的地方。

## 3. 判定「什么是云端」

`is_cloud_endpoint(base_url)` 按顺序判定：

1. `localhost` / `127.0.0.1` / `::1` / `0.0.0.0` → 本机，**不脱敏**
2. 私网 IP（`10.x` / `172.16-31.x` / `192.168.x` / 回环 / 链路本地）→ 内网，**不脱敏**
3. `.local` / `.internal` / `.lan` / `.localdomain` 后缀 → 内网，**不脱敏**
4. 命中 `DOC_NEXUS_DATA_MASK_TRUSTED_HOSTS` 白名单 → 可信，**不脱敏**
5. 其余（含所有公网域名）→ **云端，脱敏**

域名默认按云端处理（宁可多脱），内网域名必须靠白名单显式声明。

## 4. 脱敏规则

### 4.1 模式化 PII

| 类型 | 占位符 | 说明 |
|---|---|---|
| 身份证 | `〔ID_CARD_1〕` | 18 位，末位可为 X |
| 银行卡 | `〔BANK_CARD_1〕` | 16–19 位连续数字 |
| 手机号 | `〔PHONE_1〕` | 中国大陆 1[3-9] 开头 11 位 |
| 邮箱 | `〔EMAIL_1〕` | — |
| 金额 | `〔MONEY_1〕` | **必须带单位**（元/万/%/¥）才替换 |

金额规则带单位是刻意设计：否则订单号 `SO20261109001`、数量 `200件` 会被误伤。

### 4.2 敏感字段名

键名命中即**整值替换**（含数字），覆盖：
客户、供应商、往来单位、联系人、收货人、负责人、经手人、业务员、
电话、手机、传真、邮箱、地址、开户行、行号、账号、税号、身份证、
单价、价格、金额、成本、工资、底薪、计件、底价、报价、毛利、利润、应收、应付、余额、折扣、优惠。

> 实现见 `data_guard.py` 的 `_SENSITIVE_KEY` 正则，新增词条只改这一处。

这是**最后一道防线**：即使没配词表、自由文本里认不出公司名，只要它在明确字段里就会被盖住。

### 4.3 业务词表

`DOC_NEXUS_DATA_MASK_TERMS`（逗号分隔）用于自由文本里的公司/产品名。
建议从主数据导出客户、供应商简称填进去。长词优先替换，避免「华东铝业」被「华东」截断。

### 4.4 占位符编号

同一请求内，**同一原文得到同一占位符**：

```
用户：客户〔TERM_1〕 手机〔PHONE_1〕 单价〔MONEY_1〕
```

这样模型仍能推理「这两处说的是同一个人」，而不是看到一堆无差别占位符。

## 5. 三种策略

`DOC_NEXUS_DATA_MASK_MODE`：

| 值 | 行为 | 适用 |
|---|---|---|
| `mask`（默认） | 脱敏后照常调云端 | 常规使用 |
| `block` | 检测到敏感数据即**拒绝上云**，返回 403 并提示切本地模型 | 高密级场景 |
| `off` | 完全关闭（行为回到改造前） | 排障、基线对比 |

图片另走 `DOC_NEXUS_DATA_MASK_MEDIA_POLICY`：`block`（默认）/ `allow`。

## 6. 配置

```bash
# 脱敏模式
DOC_NEXUS_DATA_MASK_MODE=mask            # mask | block | off
# 业务词表（客户/供应商简称）
DOC_NEXUS_DATA_MASK_TERMS=华东铝业,中天精工
# 内网网关白名单（公网域名托管的内网服务）
DOC_NEXUS_DATA_MASK_TRUSTED_HOSTS=gw.corp.example.com
# 图片/音频：云端默认拦截
DOC_NEXUS_DATA_MASK_MEDIA_POLICY=block   # block | allow
```

默认值即安全值，不配也安全。

## 7. 回答还原

请求侧脱敏后，模型回答里出现的是占位符。服务端在响应流上自动换回真实值：

- 逐 chunk 处理，末尾若出现半个 `〔` 就留在缓冲等下一块，**不破坏流式体验**
- 流结束时 flush 残留缓冲
- 用量统计（token）仍吃**原始** chunk，还原不影响计费准确性
- 未知占位符原样保留

## 8. 失败处理

**fail-closed**：脱敏过程中任何异常都**不发请求**，绝不「脱敏失败就发原文」。

`block` 模式命中时抛 `CloudEgressBlocked`，在 `harness.py` 转成 403 并记录审计日志
（只记 provider / model / 原因，不记原文）。

## 9. 测试

`backend/tests/test_data_guard.py`，29 个用例覆盖：

- 端点分级（7 个私网地址 + 4 个公网地址 + 白名单覆盖）
- 五类 PII 脱敏、占位符稳定性、嵌套 payload 遍历、敏感键名兜底
- 金额单位防误伤（订单号/数量不被盖）
- 三种策略行为
- 图片媒体策略默认拦截
- **端到端**：云端端点出网字节确无明文；本地端点字节完全不变


## 10. 已知限制

1. **图片/音频无法脱敏**，只能拦截或放行，粒度是整个能力而非内容。
2. **自由文本里的公司名**需要配词表才认得出；不配时靠「敏感字段名」兜底，
   纯叙述性文本（如「帮我看看华东铝业那个单子」）在无词表时可能漏出。
3. **`anonymize_text`（向量化）不还原**：向量库只有脱敏后的文本，
   检索回来的片段也是脱敏的——这是有意的，避免落盘即泄漏。
4. **端点未配置时脱敏不生效**：`is_cloud_endpoint("")` 返回 False，
   因为没有任何数据出网。这不构成漏洞。
5. 脱敏只覆盖出网方向。**模型返回内容不检**——供应商侧的合规由服务商协议负责。

## 11. 当前基线测试状态

改造前后用 `DOC_NEXUS_DATA_MASK_MODE=off` 做对照，失败清单**逐条相同**（28 个），
证明本次改造零回归。这 28 个失败是仓库既有问题，按根因分四类：

| 类别 | 数量 | 根因 |
|---|---|---|
| 缺 builtin skills | 10 | `writing-bid`、`writing-proposal`、`writing-quote`、`writing-report`、`find-skills`、`the-news` 未随包提供，`app/builtin_skills/` 只有 5 个 |
| compose / 脚本与仓库不一致 | 7 | `docker-compose.yml` 无 `writing-dispatcher` 服务、无 `DOC_NEXUS_DATA_DIR` 挂载；`scripts/start-local.sh` 不存在 |
| 代理 read 超时断言过期 | 3 | 测试仍断言 `timeout.read is None`，实现已改为 180s（防 SSE 挂死） |
| 其他零散 | 8 | 依赖 LinkMind 引导、媒体任务澄清、认证锁定等外部/时序相关用例 |

这些与脱敏改造无关，未在本方案中处理。
