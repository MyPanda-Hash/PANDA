# 轻 MES 前端面板设计

| 属性 | 内容 |
|---|---|
| 文档类型 | 前端设计 |
| 适用场景 | 前端面板设计 |
| 维护状态 | 生效 |
| 最后整理 | 2026-09-01 |
| 文档导航 | [文档中心](../README.md) |

本文定义 SQL 模式下的前端面板结构和交互。`PanelxList`、`PanelxForm` 及 `/panelx/...` 是项目内部通用面板命名，不代表外部 PanelX 平台集成。

## 1. 运行链路与职责

```text
路由 /panelx/list/:panelCode 或 /panelx/form/:panelCode
  -> core/views 通用渲染器
  -> core/panel-runtime.js 稳定契约
  -> business/engine.js SQL 接口适配
  -> /api/px/*
  -> Spring Boot + PostgreSQL
```

| 位置 | 职责 | 禁止事项 |
|---|---|---|
| `frontend/src/core/views/` | 通用列表、表单、参照、选单、审批和导入组件 | 导入 `business` 或保存面板种子数据 |
| `frontend/src/core/panel-runtime.js` | 声明并校验通用视图所需能力 | 实现 MES 或 PLM 业务规则 |
| `frontend/src/business/engine.js` | SQL 接口、参照展平、按钮名兼容和面板动作适配 | 保存前端 Mock 配置或演示行 |
| `frontend/src/business/menus.js` | 菜单和面板入口 | 绕过角色可见面板过滤 |
| `frontend/src/views/` | 门户、Dashboard 和专属业务视图 | 复制通用面板渲染逻辑 |

应用入口通过 `installPanelRuntime()` 安装适配器，`core/views` 只调用 `usePanelRuntime()`。当前适配器仍是 SQL 后端实现，但通用视图不再静态依赖 MES 业务层。目录级说明见 [Core 通用引擎说明](../../frontend/src/core/README.md)。

## 2. 页面形态

| 形态 | 入口 | 用途 |
|---|---|---|
| 单据列表 | `/panelx/list/:panelCode` | 查询、单据翻页、明细浏览和工具栏动作 |
| 单据表单 | `/panelx/form/:panelCode` | 新建、编辑、参照选择、明细维护和审批 |
| 单单据档案 | 同一组通用路由 | 一张 `form_data` 承载整份档案明细 |
| 报表 | 通用列表或专属视图 | 只读查询、汇总和导出 |

单据列表从上到下固定为：

1. 工具栏：按 `buttonGroups` 分组，右侧显示单据翻页、编号和状态。
2. 查询或表头区：字段由 `queryFields` 或表单元数据驱动。
3. 明细区：按 `gridTabs` 和 `detail.tabs` 渲染明细、汇总及合计。
4. 表尾：单据类显示备注、制单、审核和时间信息。

表格至少保持五行稳定高度；不足用占位行补齐，超出后在表体滚动。动态数据、加载状态和按钮状态不得改变工具栏、网格或翻页器的尺寸。

单据列表模式（`tablePages[0].listMode = "document"`）下不渲染上述第 2/3 步：列表只按 `gridTabs[0].columns` 展示表头主信息，`新增` 打开空白 `PanelxForm` 详情页，双击行按 `?code=` 打开已有单据；保存、选单、行级关联等明细动作只在详情页出现。

## 3. 配置映射

运行时配置的唯一来源是 PostgreSQL `panel_config.config`，结构基线在 `backend/src/main/resources/db/migration/`。前端不维护同名配置副本。

| 配置路径 | 页面用途 |
|---|---|
| `metadata.panelName` | 页签、标题和弹窗名称 |
| `metadata.panelCategory` | 单据、档案或报表行为 |
| `metadata.singleDoc` | 单单据档案模式 |
| `metadata.buttonGroups[]` | 工具栏分组，结构为 `{name, actions}` |
| `metadata.panelPageDto.tablePages[0].queryFields` | 查询字段 |
| `metadata.panelPageDto.tablePages[0].listMode` | `document`：列表只显示表头主信息，新增/双击进入表单页 |
| `metadata.panelPageDto.tablePages[0].gridTabs` | 列表明细和汇总列 |
| `dataSchema.fields` | 表头或档案字段 |
| `detail.tabs[]` | 明细键、字段、计算和汇总定义 |
| `selectConfig` | 选单来源、表头映射和明细映射 |
| `selectConfigs` | 按选单动作名映射多个来源配置 |

`detail.tabs[].key` 必须与接口返回的 `detail.<key>` 完全一致。修改配置后同时校验列表、表单、参照弹窗和选单弹窗，不能只看一个入口。

## 4. 字段与参照

| 数据类型 | 默认控件 |
|---|---|
| 文本、自动编号 | 输入框；自动编号只读 |
| 整数、小数、金额 | 数字输入或右对齐数值列 |
| 日期、日期时间 | 日期控件 |
| 是否 | 开关或复选框 |
| 下拉框 | 配置 `options` 的选择器 |
| 参照 | `RefPickDialog`，从另一个 SQL 面板读取 |
| 图片 | 图片单元格或上传控件 |

业务字段能对应基础档案时必须使用参照定义：`refPanel`、`refField`、`displayField`、`filter`、`refMap`、`refColumns` 和可选 `refMulti`。只有没有对应档案时才使用固定 `options`。

参照字段是动态形态：数据源 ≤ 20 行渲染为下拉直选（远程搜索），> 20 行渲染为 `RefPickDialog` 弹窗搜索定位；行数由 `engine.refRowCount` 判定，跨阈值时形态自动切换，两条路径的取数条件（含“已审核”过滤）保持同一口径。

单单据档案的记录位于明细中，适配器根据 `metadata.singleDoc=true` 先拉取单据，再展平首个明细页签并应用筛选；不得在前端维护单单据面板编码清单。包含审核或提交审批动作的单据参照只返回已审核来源单。

页面自己需要「可选班组 / 可选设备 / 可选工作中心」这类档案选项时，统一调用 `engine.loadArchiveRows(panelCode)`：它按面板配置判定两种存法并展平成「一行一个档案」。直接拿 `queryFormDataList` 的 `list` 当选项，在单单据档案上只能取到单据头（如备注明细挂在 `detail.equips`），下拉会是空的。

计算字段必须同时声明 `computed=true` 和对应的 `calc` 规则。财务字段通过 `engine.roundDecimal(value, round)` 统一舍入，列表、表单和新增弹窗不得各自使用 `Math.round` 或 `toFixed`。明细包含“现存量”时，在选择存货、修改仓库、打开单据和执行“现存量查询”后调用 `engine.fillCurrentStock`，以库存状况表实时刷新。

## 5. 工具栏与状态

- 分组结构只能使用 `{name, actions}`。**主按钮 = `primaryActionOf(group, isDisabled)`**：审批组按单据状态取当前可用的那个动作，其它组固定取第一个动作；除主按钮外的动作放入下拉。按钮文字：审批组显示动作名（`提交审批`/`审批通过`/`弃审`），其它组显示组名。
- `isDisabled(action)` 同时控制视觉和行为。`onButton`、`onGroupAction` 入口必须在请求前拦截禁用动作。
- 普通审核面板使用“审核/弃审”；启用审批流的面板只保留一个“审批”组，配置里首动作必须是“提交审批”，其后为审批通过、审批驳回、审批情况和弃审。
- **审批主按钮跟随状态**（2026-11-03）：草稿→`提交审批`、审批中→`审批通过`、已审核→`弃审`、无状态流转可做（如已中止）→`审批情况`。审批中把`审批驳回`作为并列的第二决策露出（危险色，`approvalSecondaryOf`），因为它是唯一有两个决策的状态；下拉只列**当前可用**动作，不再摆一排灰项。这样三个主要审批动作都是"一次点击直达"，不会出现"主按钮是灰的、能点的全藏在隐藏下拉里"。
- 面板自带「审核」组时（销售出库单这类直接审核面板），`ensureAuditAction` 不再往「审批」组复制一份审核，避免渲染出两个「审核」入口。
- 前端会归一数据库中的旧审批按钮配置，但服务端仍是状态与权限的唯一真源。审批通过和驳回按钮是否可见受角色审批权限限制。
- 按钮权限过滤发生在渲染层：`business/permissions.js` 的 `filterButtonGroups` 用 `user.panelPerms`（登录态带回）按按钮名→权限码映射过滤；不在映射表的动作（如“表格调整”）不受权限控制；旧会话无 `panelPerms` 时不拦截。
- 无 `price` 权限的角色，表头与明细中匹配 `单价|金额|价税|售价|成本价|报价` 的字段只读（`priceFieldLocked`），OCR 回填同样跳过这些字段。
- 未实现动作不显示（2026-11-03，`core/action-support.js` 的 `filterSupportedActions`）：面板配置里的 `buttonGroups` 带着大量 T+ 按钮名，后端 `PxService.callButton` 的 switch 只实现了其中一部分，其余会抛「未定义按钮规则：xxx」。所以渲染前按一张**动作支持表**过滤——`FRONTEND_ACTIONS`（前端自己实现：扫描填单/表格调整/字段管理/导入/预览/查询…）+ `BACKEND_ACTIONS`（= callButton 的 switch 分支）+ `EXTRA_ACTIONS`（`PanelActionHandler` 注册，当前只有「变更」）；报表专属动作（导出/打印/发送邮件/退出）只在 `reportMode` 下显示；`选X` 需要配了 `selectConfig`。动作全被过滤掉的组整组消失。
- 支持表与后端的一致性由 `tools/action-support-audit.mjs` 守住：解析 `PxService.callButton` 的 `case` 与 `PanelActionHandler` 注册，双向比对 `action-support.js`，任何一边漂移即失败（`verify-project` 会跑）。新增后端按钮时先加 switch 分支，再登记到前端表，否则前端不显示。
- 收纳组（`更多`/`工具`/`设置`/`智能`，`isCatchAllGroup`）的名字只是分类，点组名本身没有明确动作：这类组的主按钮**只展开菜单、不执行第一个动作**。否则过滤掉未实现动作后，「更多」的首个动作会变成「导入」这类重动作，点一下像误触。
- **暂不显示的按钮（留着以后再补）**：配置里还保留这些 T+ 动作名，只是当前不渲染。补功能时按「后端加 switch 分支（或注册 `PanelActionHandler`）→ 前端表登记 → 加测试」三步走，界面自动恢复，不用改视图代码。

  | 动作 | 影响面板数 | 补做要点 |
  |---|---|---|
  | `下载导入模板` | 21 | 成本最低：用现有 xlsx 能力导出「列名 + 一行示例」，与 `ImportDialog` 配套 |
  | `放弃` / `草稿` | 16 | 先定语义（放弃草稿=删除还是作废），需要后端状态机 |
  | `附件` / `消息` | 16 | 要文件存储与消息中心 |
  | `现存量查询` / `变更历史` / `联查` | 18 / 16 / 18 | 现存量可复用 `STOCK_STATUS`；变更历史要审计表；联查是关系导航 |
  | `移动控件位置` / `调整控件宽度` / `工具栏设置` | 19 | 字段布局自助配置，需新表 + 拖拽界面（「字段管理」已覆盖"加字段"） |
  | `设置默认功能` / `引入常用单据` / `保存为常用单据` | 56 / 19 / 16 | 常用单据模板，需一张收藏表与"按模板建单" |
  | `直接打印` / `打印模板设置` / `打印情况` / `明细标签打印` | 20 / 20 / 8 / 10 | 打印模板引擎；当前列表页「打印」组只保留浏览器打印（`预览`） |

- 保存、删除、审批、生单等最终规则以后端为准，前端校验只用于即时反馈。

### 左侧单据栏（多单据面板的单据切换）

- 只在**单据类面板且当前列表多于 1 张单据**时出现（`showDocRail`）：报表面板没有「当前单据」概念，BOM 面板已有父件/子件视图与父件分页，都叠不加这一栏；窄屏（<1024）自动隐藏，宽度让给明细区。
- 侧栏镜像**当前页单据列表**（不再额外请求）：点行把 `curIdx` 切过去，与顶栏「第 x/y 张」、主表预览、明细区共用同一份数据。行模型带**原始下标**（`core/views/doc-rail-rows.js`，纯函数有单测），过滤后点第 2 行仍落到 `list[2]`，不会切错单。
- 表头列式（2026-11-04，对齐「采购订单选择」）：表头固定为 单号 | 日期 | 主要字段 | 审核状态，一行一张单；单元格单行、超长省略，悬停 `title` 看全值。中间列按面板挑一个最能把单据区分开的表头字段（`core/views/doc-rail-rows.js` 的 `PANEL_MIDDLE_FIELDS`）：请购单=请购人，采购订单/到货单/采购入库单/采购退货单/采购发票/检验单=供应商，销售单=客户，领料申请=领料申请人，派工/成品报检=加工单号；未登记的面板自动取行里的 客户/供应商/委外供应商/往来单位，全空则只留三列。取不到值时单元格显示「-」，列本身不隐藏——列位置稳定，翻页不会左右跳。
- 追踪路线图（`BusinessOverview` 的「单据流程路线」）里，**动作类环节不画节点框，标在流转箭头上**：`MANU_ORDER --生产领料--> MATERIAL_OUT`（`EDGE_PROCESS_LABELS`，渲染成箭头上方 10 号灰底小字）。排产节点按批次展开分支，分批报工的汇报单也逐张列分支。
- **下游单据状态做成单据栏里的筛选，不占侧栏列、也不占主区高度**：面板可在配置里声明 `metadata.panelPageDto.tablePages[0].headerFilters`（`[{dataName, label, placeholder, options}]`），列表页把它交给 `DocSelectRail`，渲染在「单据列表」搜索框下面一排下拉（`update-filter` 事件 → 写进 `condition` → 立刻查询）。成品报检单声明了「入库单」：**转入库单 / 未转入库单 / 入库单审批中 / 入库单已审批 / 入库单已驳回**。按这类筛选查过后，切回页签会自动重查一次，下游在别处审批/驳回后结果会跟着变。侧栏本身不再加业务列（380px 塞 6 列会把加工单号折成三行），主区也不放固定筛选条。
- 状态列用状态标签（圆角 4、1px 边框；ok/done/pending/danger/draft 五色，与项目状态色一致）。**单据栏默认收起**（进面板先给主区让宽度，不再持久化展开状态，`mes.doc-rail.collapsed` 已停用）；点开时**直接铺到最宽 560px**（`watch(collapsed)` 里 `width = MAX_WIDTH`），不用再拖一下；展开后可拖拽收窄到 340px；单号、日期用等宽数字（`tabular-nums`）。
- 两种搜索各管一段：输入框打字只过滤**本页**（瞬时、不发请求），命中范围是本行所有可见列（单号/日期/中间列/状态）而不是只搜单号；回车或点「全库」把关键字交给后端重查整个列表并回第 1 页。清空输入 = 取消搜索。
- 底部分页「‹ 第 x/y 页 › 每页 n 张」按后端 `totalSize` 算，与顶栏同口径；空态给下一步动作（有关键字→清除搜索，没单据→新建单据）。
- 可收起（32px 竖条，只留展开按钮与张数）；**默认收起**，点开展开到最宽 560px；不写 `localStorage`——每个面板进来都从收起开始。
- 外观按 Ant Design v6 token 取值：白底 + 1px 分隔线、无阴影（0 层卡片）、控件高 32（翻页按钮 24=controlHeightSM）、圆角 6（标签 4=borderRadiusSM）、间距 8/16、正文 14/22、次要信息 12（fontSizeSM）、分隔线 `#f0f0f0`（colorSplit）、悬停 `rgba(0,0,0,0.02)`（colorFillQuaternary）、选中主色浅底 + 左侧 2px 主色条。颜色一律走项目 CSS 变量（`--t-*`），暗色主题自动跟随。
- 为了让它有确定高度：`.panelx-list` 改为 `height:100%`（父级 `.portal-content` 有确定高度），`.body-outer` 收口 `overflow:hidden`，明细区 `.body` 自己滚。效果是「备注」页尾永远贴在底部、单据栏在栏内滚动，不再把整页顶出屏幕。

### 评审口径小结（列表/单据页）

- 一个面板同时只有一套"选单据"手段：有左侧单据栏时，顶栏逐张翻页箭头保留（渐进定位），但不再新增第三套列表。
- 单据栏只管"切哪张"，不承载编辑动作；涉及状态流转的操作仍在工具栏。

### 已审批印章（全审批面板通用）

- 判据统一在 `core/doc-status.js` 的 `isDocApproved(row)`：`单据状态 ∈ {已审核, 生产中, 已完工, 已关闭}` 或表头 `审批状态 ∈ {已审批, 已通过}`（兼容历史数据）。直接审核（草稿→已审核）与审批流（草稿→审批中→已通过，落盘同为已审核）两类链路一把尺子；弃审/驳回回草稿即消失。数据值比较，不进 `tt()`。
- `PanelxList`：已审批单据在首个明细块的页签行内盖斜置绿章（`.approved-stamp`，多块只盖一处；2026-11-03 起改为行内标签，此前绝对定位会压住「明细/汇总」页签）；携带单据字段的行加 `row-approved` 浅绿底色。
- `PanelxForm`：标题行右侧同款印章（独立页与 `VoucherFormDialog` 弹窗内嵌共用，仅编辑态显示）。

### 表格调整（用户级列定制）

- 工具栏“更多”组注入“表格调整”（`ensureColumnPrefsAction`，引擎提供 `saveColumnPrefs` 可选方法时才显示）。
- `ColumnPrefsDialog` 提供 ▲▼ 调序、显示勾选和栏名别名；“恢复默认”提交空 `columns`。
- 保存走 `engine.saveColumnPrefs`，成功后清空配置缓存重取 `getPanelConfig`：列序/显隐由后端在读取出口叠加，别名经 `metadata.columnAliases` 注入；数据键、合计和导出取值仍用中文列名，仅表头与 CSV 表头显示别名。
- 定制按用户隔离（`px_column_pref`），不影响 `panel_config.config` 原文。

### 列头筛选（明细表格与主表预览）

- 明细表格与主表预览（`mainTable`）的每个列头右侧有一个漏斗图标，点开出输入框，边打边过滤本列；生效后列头显示「筛选词 ×」，点 × 清除。图标默认透明、悬停列头才显形，不干扰阅读。
- 只过滤**当前视图的行**（内存过滤），不改后端查询条件、不写库、不影响其他用户；筛选状态存在组件内 `colFilters`（键 = 区块:页签:列），切页签/切单据/查新不变。
- 合计按**筛选后**的行算：筛出「铝棒」时合计就是铝棒那一批，数字才和眼睛对得上；翻页条同时显示「共 N 行 · 已筛选 M 列 · 清除筛选」。一条都没命中时显示「共 0 行」，仍留清除入口。
- 匹配语法（`core/views/column-filter.js`，纯函数有单测）：普通文本 = 包含（不区分大小写）；`=值` / `!=值` 精确比较；`>n` `>=n` `<n` `<=n` 数值比较（忽略千分位）。数值比较时两侧都要能取到数字，非数字格不参与——宁可漏一行，也不把空值当 0 混进合计。
- 与「查询」区互不干扰：查询是服务端条件（换的是数据集），列头筛选是前端视图过滤（数据集不变）。

### 参照带出列（`参照字段.属性`）

- 列名写成 `参照字段.属性`（如销售订单的 `存货名称.品牌`、单据表头的 `部门.负责人`）表示「按参照值去档案里读一个属性」，不是明细行自己的数据。
- 显示期解析（`core/views/ref-carry.js`，纯函数有单测）：行内已有该键且非空 → 用行内值（用户手改过就以手改为准）；否则按 source 字段的值（`存货名称`/`部门`）去参照面板的档案索引里查一行，取 `属性` 显示。
- 档案索引由引擎 `archiveIndex(panelCode, keyField)` 取一次并缓存 60 秒（`engine.clearArchiveCache()` 可主动清）。所以**选单带过来、导入、生单生成、历史数据**的行也能显示品牌，不要求必须经过参照挑选；也不需要回填存量数据。
- 这类列是档案属性的镜像，**只读**：要改请到档案里改（存货品牌在存货档案里维护）。源字段不是参照字段时按普通文本列处理，不做解析。

### 字段管理（面板自助加字段）

- 工具栏「更多」组注入「字段管理」（`ensureFieldManageAction`）：引擎提供 `addCustomField` 且当前用户在本面板有 `edit` 权限时才显示，服务端 `addCustomField`/`retireCustomField` 会再判一次同样的权限。
- `FieldManagerDialog` 列出本面板**表头字段 + 各明细页签字段**（标「内置/自定义」），可按位置过滤；可新增字段（位置、字段名、类型、下拉词表、列宽、必填），自定义字段可停用（内置字段只能改面板配置）。
- 类型限 文本/下拉框/日期/是否/小数/整数；字段名不能含空格与 `. % ( ) /`（点号会被当成参照带出列）；同位置不允许重名（内置字段也算）。
- 保存只登记元数据（`px_custom_field`），不写 `panel_config.config`、不动表结构：面板数据本来就存在 `form_data` 的 `data`/`detail_data` JSON 里，加字段只是让读取出口多合并一条字段定义。
- 合并规则：表头字段进 `dataSchema.fields` 并追加到 `formPages.fieldNames` 白名单（不在白名单里显示不出来）；明细字段进 `detail.tabs[].fields`，第一个明细页签还追加到 `gridTabs[0].columns`（首块列取的是它）。
- 停用只删元数据：业务数据（JSON 键）保留，重新加同名字段即恢复显示；新增/停用都写 `px_field_log` 审计。
- 边界：自定义字段不进「查询」区（服务端查询条件仍是配置字段），不支持参照/附件类型，不参与结构化表（`manu_order` 等有物理列的表仍按「预留扩展列」规则走）。

### 明细区表格高度与翻页

- 明细区不再固定 5 行高度。每页行数可选 10/20/50（`ROWS_PER_PAGE_OPTIONS`），默认 10；选择只存组件内 `view[blockId:size]`，不落库、不影响其他用户。
- 表格高度 = 表头 32 + 每页行数 × 33 + 合计行 32。绑定的是 `max-height` 而不是 `height`：内容装得下就不出表内滚动条，装不下才滚，避免「31 行高算成 33」这类 2px 误差硬压出滚动条。
- 行数补到 `min(每页行数, 10)` 个占位行：每页 20/50 而数据不足时不会补一屏空白，否则翻页条会被挤出屏幕。
- 翻页条 `.dg-pager` 贴在表格下方：共 N 行 / 每页 X 行 / 第 x/y 页 ◀▶；只有超过一页才出现箭头。文案全部走 `tt()`。
- 合计行（`show-summary`）按**整块全部行**计算（`sumMethodOf` → `computeSums`），翻页后不会变成单页小计。
- 切换明细/汇总页签回到第 1 页；「新增数据」追加到末行后自动跳到最后一页。
- 计算逻辑抽在 `core/views/list-grid-paging.js`（纯函数，`frontend/test/list-grid-paging.test.js` 覆盖行高、页数收敛、切片与占位）。

### 单据入口统一走列表页（PanelxList）

- **一个单据只有一个样子**：所有入口（左侧菜单、业务总览流程图、生单跳转、选单）最终都落在 `/panelx/list/{panelCode}`，不再跳 `/panelx/form/`。列表页有单据栏、列头筛选、表头内联编辑、批量翻页，能力比表单页全；两套并存会让同一张单据长得不一样（2026-11-04 收敛）。
- 定位参数：`?code={单号}`（外部入口，如业务总览、生单跳转）与 `?focus={单号}`（选单的旧即时语义）。`load()` 里两者都读，定位到对应行并切换当前单据。`?code=` 保留在地址栏（刷新仍定位同一张单）；`?focus=` 用完即清。
- 返回按钮：只有带 `?from=/xxx`（外部入口）时才在工具栏右侧出现「返回」，点了 `tabs.close(当前页签)` 后回来源页。菜单直接打开的面板不带 `from`，不显示返回。
- **keep-alive 复用**：`PortalLayout` 用 `<keep-alive :max="20">` 缓存面板页，同一面板第二次进入 `onMounted` 不再执行。`onActivated` 里判断「带 `?code=`/`?focus=` 或面板编码变了」就重新 `load()`（`loadedPanelCode` 记上次加载的面板），否则从业务总览连点两张单会停在上次那张。
- `/panelx/form/:panelCode` 路由保留，但不再作为单据入口；`VoucherFormDialog`（列表页双击「修改」）仍是弹窗形态。

### 表头字段栅格（列表页与表单页同口径）

- 表头字段区走 CSS Grid：列表页 `.fields.header-fields` 用 `repeat(auto-fill, minmax(200px, 1fr))`，表单页 `.fields.udl-fields` 用 `minmax(240px, 1fr)`，控件宽 100%，**列等宽并铺满容器**。1440 下列表 5 列、表单 4 列；768 下 3 列 / 2 列；375 下 1 列（三档 `scrollWidth == clientWidth`）。
- 此前是 `inline-block` + 固定 160px 控件：宽屏下字段挤在左边、宽度参差（单据编号 320、客户 192、普通字段 160），每行尾部留大片空白。
- 控件统一 32px 高：输入框、下拉、日期选择器同高（日期选择器默认 27px，会让同一行参差，需要 `min-height: 32px` + 日期编辑框 `height: 32px`）。
- **表头控件的 `v-if` 链必须连续**：中断会让同一字段同时命中两条分支、渲染两个控件。2026-11-03 修的正是这类问题——`isRefSelect(r)` 分支误写成 `v-if`（应为 `v-else-if`），导致每个文本字段渲染两个输入框，字段被撑宽、行高不齐，看起来像"字段挤在左边"。

### 明细区工具条（只放能执行的动作）

- 明细/主表区块右上角工具条（`PanelxList` 的 `blockIcons()`）只列真正能执行的动作：「复制到剪贴板」把整块按制表符复制；「另存为EXCEL模板」用 SheetJS（`xlsx`，按需 `import()`，不进首屏 chunk）导出当前区块的 **.xlsx**——Sheet 名取当前页签名（非法字符替换、截 31 字符），表头取列显示名（含列别名），数值列（小数/整数类型）写成数字单元格，空值写空串。
- 「现存量提取」只在区块确实有「现存量」列时出现：`engine.fillCurrentStock` 要求行内有 `现存量` 且有存货编码/名称才回填，没有该列的区块摆这个按钮只会「刷新 0 行」。
- 未实现的 T+ 动作（Ctrl+V 列粘贴、从剪贴板粘贴、批量修改、销售订单查询、存货中心、更多）不占位：既不渲染按钮，也不保留兜底提示。要恢复某个动作，先把它实现再放回工具条。
- 右键菜单（`ctxItems`）只保留已实现项：定位（回显当前行身份键）、复制到剪贴板、另存为EXCEL模板。
- 表单页明细工具条（`PanelxForm`）只保留「新增数据」与条件出现的「现存量提取」。
- 判据：点了没有任何真实副作用、只弹一句「暂未实现」的按钮，一律不进界面——占位按钮既误导用户，也让「哪些功能真有」不可读。

### 选单入口（有无来源决定显示）

- 「选单」需要面板配了 `selectConfig`（单来源）或 `selectConfigs`（多来源）才有来源可选：后端把 `selectConfig` 提到面板配置**顶层**（不在 `metadata` 里），判断用 `button-groups.js` 的 `hasSelectConfig(config)`，两处都查。
- `ensureSelectAction(groups, supported)`：`supported=false` 时整组隐藏「选单」组，并从其他组里摘掉「选单」动作，过滤后变空的组一并去掉。列表页与表单页同一条规则。
- 当前无来源、因此不显示选单入口的单据面板：采购订单（`PU_ORDER`）、其他入库单（`OTHER_IN`）、其他出库单（`OTHER_OUT`）；有来源的（销售订单、销货单、销售出库单、采购入库单、生产加工单等）照常显示。
- 「智能选单」是另一个动作（按库存/需求自动选料），与选单入口无关，不受此规则影响。

### 物料清单（BOM）父件/子件主从视图

- `BOM` / `BOM_FWD` / `BOM_REV` 三个面板走 `BomMasterDetail`：上方父件表、下方子件表，点父件行换子件。
- 只读浏览（已审核 BOM、正反向查询）时，父件表列出**所有单据的父件**（`flattenDocDetailRows` 把列表页每张单据的 `detail.children` 摊平），不再用「第 N 张单据」逐张翻；顶栏那组单据翻页箭头在这三个面板隐藏。
- 父件表自带分页：共 N 项 / 每页 10·20·50 / 第 a/b 页，分页是**服务端**分页（改每页条数即重查列表）。表格高度按本页实际项数算，不足一页时不留大片空白。
- 父件行身份是「单据编号#父件编码」（`rowIdentity`）：两张 BOM 都挂同一个父件时，点哪张只显示那张的子件，不会把两单的行混在一起。分页模式下父件表多一列「单据编号」，便于区分。
- 点父件行同时把当前单据切过去（`select-master` → `curIdx`），表头「单据：xxx」与子件始终一致。
- 编辑草稿（`BOM` + 草稿态）不启用这套：父件表只维护当前单据，保存/校验仍按单张单据走（`bomMasterRef.validate()`）。

### 界面语言（tt() 显示层翻译）

- 语言切换入口在顶栏（`stores/locale.js`），`Alt+L` 循环切换；`el-config-provider` 同步 Element Plus 组件文案，`html lang` 与标题同步更新。`loadAvailable` 在登录拿到 JWT 后由顶栏补拉，失败不置位以便重试。
- 翻译原则：除单据填写内容（业务数据值、数据键、payload）外的一切界面文案都翻译——按钮、菜单、组织架构等设置页、表尾审核信息、分页、弹窗、提示消息、tooltip、占位符。
- `tt()` 只包显示位：表头、查询/表单标签、页签、弹窗标题、按钮组名与动作名、状态徽标、菜单标题、表尾（制单人/审核人/审核日期等）、分页（共 N 条、第 X 页）、工具条图标（复制到剪贴板/现存量提取等）、序号/操作列、空态、`ElMessage`/`ElMessageBox` 文案。铁律：`v-model` 值、选项 `value`、查询 payload、`callButton` 的 `buttonName`、`单据状态 === '已审核'` 等字符串匹配、`row['存货编码']` 等数据键一律不翻译。
- 含动态值的消息用分段拼接，动态值不进 `tt` 参数：`tt('已删除') + ' ' + n + ' ' + tt('行')`；整句无插值才整句包。状态枚举值保持原文常量，仅渲染位 `tt()`；类数组（按钮组、ctxItems）保持中文原文，渲染处包装。
- 词条三级来源：静态包 `i18n/locales/en.js`（`biz.*`，中文原文即键，覆盖全部界面文案与登录页——登录前无 JWT 取不到机翻）优先；缺口由 `tt()` 渲染时自动收集（`i18n/index.js` recordMiss），去抖 500ms 批量请求 `/api/locale/dict`（阿里云机翻 + 库表词典）补齐并 merge——**对所有语言生效，不依赖各页面手动预取**；merge 后自增 `dictVersion`（ref），渲染函数/computed 内的 `tt()` 天然响应、自动重渲。按「locale+键」去重防止机翻失败的键反复请求；翻译服务不可用时 `tt()` 回退中文原文。
- 静态包禁止重复键（esbuild 构建告警可检出）；同一中文词只取一个译名（如「首页」统一 Home）。

### 顶部待办、消息与预警

- `NoticeCenter` 只消费 `/api/portal/badge` 和 `/api/portal/notice/list` 的当前账号数据，不在前端维护演示待办、审批消息或库存阈值。
- 待办窗口展示当前账号有权审批的“审批中”单据；消息窗口展示当前账号提交单据的审批通过/驳回结果；预警窗口展示库存状况表中 `现存量(主) < 500` 的仓库库存行。
- 每次打开窗口重新请求对应列表，角标每 60 秒刷新；角标表示当前实时记录数，不标注为持久化未读数。
- 列表项展示标题、业务摘要和时间。详情中的“去审批”“查看单据”“查看库存”使用后端返回的 `targetPath`，单据同时携带 `focus=formNo` 定位，不拼装另一套业务路由规则。
- 通知请求失败时保留空状态并允许下次打开重试；组件卸载时必须清理轮询定时器。

典型状态关系：

```text
普通审核：草稿 -> 审核 -> 已审核 -> 弃审 -> 草稿
审批流程：草稿 -> 提交审批 -> 审批中 -> 审批通过 -> 已审核
                                  \-> 审批驳回 -> 草稿
```

## 6. 新建、保存与删除

- 新增先调用后端创建草稿，由后端生成单号、日期和默认值。
- 保存必须携带 `编号`；明细保存为完整 `detail`，不能用空值覆盖未加载的明细。
- 非草稿单据默认只读，允许的变更必须由状态矩阵明确开放。
- 删除明细行与删除整张单据是不同动作，确认文案必须明确目标。
- 单单据档案只有一张表单，新增和导入操作写入其明细数组，不能创建多张档案单据。

## 7. 选单、生单与弹窗

- 选单是拉式操作：单来源使用 `selectConfig`，多来源使用以动作名为键的 `selectConfigs`，选择已审核来源单并按 `headerMap`、`detailMap` 带入数据。
- 多来源配置可增加 `condition`，前端与固定的已审核条件合并。每个动作必须使用自己的来源、明细键和字段映射，禁止复用首个动作的配置。
- 生单是推式操作：来源单据调用后端按钮动作，后端落库后返回 `gotoPanel` 和新编号；前端跳转到目标面板列表页并用 `?code={新编号}` 定位到生成单据（草稿可继续内联编辑），同时保留来源单据页签，方便对照或回到原单。
- 列表双击使用 `VoucherFormDialog` 打开当前单据；参照、选单、审批历史、导入和 BOM 明细各使用独立对话框。
- 弹窗关闭或保存后只刷新相关数据，不重置整个门户页签状态。
- Excel 导入按表头名称精确匹配字段；没有匹配列时拒绝导入，预览确认后再写入。

## 8. 视觉和可用性

- 使用安静、密集、可扫描的制造业工作界面，禁止卡通文案、Emoji、装饰动画和无业务意义的渐变。
- 表头字段采用稳定网格；标签、输入框、必填标记和错误提示不能互相遮挡。
- 数量、单价、金额右对齐，日期和编号保持可完整识别的列宽。
- 图标按钮使用项目图标库并提供 tooltip；文字按钮只用于明确命令。
- 空状态、加载失败和权限不足使用中性业务文案。
- 自定义页面（我的桌面、组织架构、排产批次看板、工序报工）根节点挂 `class="adx"`，颜色/圆角/间距只取全局语义层 `--d-*`（`frontend/src/styles/index.css`），不写死色值：主色 `--d-primary`（品牌绿）、完成 `--d-ok`、告警 `--d-warn`、正文 `--d-text` 三级、边框 `--d-border*`、浅底 `--d-fill-soft`。页面容器 = 白底 + 1px 边框 + 圆角 8（0 层不加阴影），指标用一条容器四格靠 1px 分隔线分层，空列必须给主行动。teleport 到 body 的下拉项不在 `.adx` 作用域内，那里用挂在 `:root` 的 `--t-*`。
- 状态色按语义分配：正常完成（已报满）用中性灰或成功绿，只有真正被阻挡（等前置工序、缺料）才用告警橙——不要把正常终态画成告警。
- 工序报工列表按**生产加工单分框区**（1px 线框，桌面一行两个、窄屏一列），框内一批一行、行间 1px 分隔线，不用通栏大表；排产批次看板则是三列 Kanban，两边共用同一套状态词（可报工 / 已报满 / 待首检 / 首检不合格；看板「未开工」列另有 待排产）。
- 排产批次看板三列口径按**流程阶段**分，不按「报了几件」分：未开工 = 还没排产的工序（数据来自 `/px/pendingPlanBoard`，虚线框 + 可排数量，卡片写「待排产」）；生产中 = 已审核的排产批次且剩余 &gt; 0（含可报工、待首检）；完工 = 剩余为 0。KPI 四格同步改成 生产中批次 / 已完工批次 / 待排工序（可排件数）/ 报工完成率。
- 生产领料（`/mes/materialIssue`）按批次领料：容器/指标条/表格同一套 `.adx` 口径，表格列依次是 批次 → 工序 → 批次数量 → 材料 → 整单需用 → 批次需用 → 已领 → 剩余可领 → 出库单 → 出库状态 → 操作。操作列直接反映单据状态：**领料 / 重新领料（已驳回）/ 等审批 / 待提交（补提交旧草稿）/ 已领满**，出库单号可点进单据；领料弹窗三段（批次信息 → 材料数量 → 领料人·仓库），领料人默认填当前操作者账号。
- 报工弹窗固定三段：**批次信息**（批次号/加工单/车间设备/批次÷已报）→ **首检块**（状态词 + 一句话说明 + 动作）→ **数量区**（合格/不合格两个数字框 + 合计行，超出剩余时整行转红）。首检未通过时数量区与「确认报工」都不出现，只给「生成首件报检单」（调 `firstInspectByBatch`，已有单则返回原单号）与「去首件检验」（跳 `FIRST_INSPECT?code=单号` 并开页签）。

## 9. 新面板接入清单

1. 在 SQL `panel_config` 和初始化脚本中增加配置，不向 `engine.js` 添加 Mock 数据。
2. 确认面板分类、表头字段、明细键、查询字段、按钮组和状态选项。
3. 需要参照时登记来源面板、筛选和字段映射。
4. 需要选单或生单时，同时实现后端校验和落库逻辑。
5. 需要审批时登记审批面板和角色权限，验证完整状态闭环。
6. 验证列表、表单、参照、选单、导入、窄屏和无数据状态。
7. 有自定义入口的页面，按 [面板入口清单](面板入口清单.md) 同步菜单、列表按钮、业务总览节点、页内弹窗和直链，并运行 `node tools/entry-audit.mjs`。
8. 运行 `node tools/verify-project.mjs`。

## 10. PLM 复用边界

PLM 复用的是配置驱动的列表、表单、明细页签、参照、选单、导入、权限和动作入口，不复用 MES 的菜单、面板编码、库存刷新、生单映射或状态文案。PLM 页面仍通过同一 `PanelRuntime` 契约访问 SQL 后端。

| 层级 | 可直接复用 | PLM 必须单独定义 |
|---|---|---|
| 渲染 | 字段控件、表格、明细、查询、弹窗、错误态 | 产品结构树、可视化对比等专属视图 |
| 配置 | `panel_config` 配置格式 | 产品、文档、BOM、变更等面板配置 |
| 交互 | 保存入口、参照、选单、权限控制 | 签入签出、修订、发布、基线、ECR/ECO 动作 |
| 数据 | `/api/px/*` 协议和统一响应 | PLM 结构化表及领域接口 |

在需求确认前不预置 PLM 字段和状态。新增 PLM 动作时先定义对象、状态前置条件、权限、事务结果和审计要求，再接入按钮；不能根据现有 MES 按钮名称反推业务规则。

历史页面规范、T+ 抓取记录和旧面板笔记仅保留在本地 `docs/archive/`，不上传代码仓库，只用于追溯设计来源。

## 权限动作：generate 独立（2026-11-12）

按钮权限矩阵由 11 项扩到 12 项，「生成XX」这类生单按钮单独走 `generate`：

| 动作 | 能做什么 | 典型授权对象 |
|---|---|---|
| add | 在本面板新建单据 | 计划员（加工单）、销售（订单） |
| **generate** | 从本面板把单据推到下游（生成领料/出库/入库/销货…） | 仓管（领料申请→材料出库）、销售（订单→销售出库）、质检（加工单→成品报检） |

拆分原因：两者共用 add 时，仓管为了生成领料出库必须同时拿到「新增加工单」的权限，等于越权。
生单同时校验**来源面板**与**目标面板**的 generate。
