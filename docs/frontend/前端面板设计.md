本文定义 SQL 模式下的前端面板结构和交互。`PanelxList`、`PanelxForm` 及 `/panelx/...` 是项目内部通用面板命名，不代表外部 PanelX 平台集成。

## 1. 运行链路与职责

```text
路由 /panelx/list/:panelCode 或 /panelx/form/:panelCode
  -> core/views 通用渲染器
  -> business/engine.js SQL 接口适配
  -> /api/px/*
  -> Spring Boot + MySQL
```

| 位置 | 职责 | 禁止事项 |
|---|---|---|
| `frontend/src/core/views/` | 通用列表、表单、参照、选单、审批和导入组件 | 写死某个业务面板的字段或种子数据 |
| `frontend/src/business/engine.js` | SQL 接口、参照展平、按钮名兼容和面板动作适配 | 保存前端 Mock 配置或演示行 |
| `frontend/src/business/menus.js` | 菜单和面板入口 | 绕过角色可见面板过滤 |
| `frontend/src/views/` | 门户、Dashboard 和专属业务视图 | 复制通用面板渲染逻辑 |

当前 `core/views` 仍通过 `@/business/engine` 使用项目适配器，因此 `core` 是可复用方向，不是已经独立发布的无依赖包。目录级说明见 [Core 通用引擎说明](../../frontend/src/core/README.md)。

## 2. 页面形态

| 形态 | 入口 | 用途 |
|---|---|---|
| 单据列表 | `/panelx/list/:panelCode` | 查询、单据翻页、明细浏览和工具栏动作 |
| 单据表单 | `/panelx/form/:panelCode` | 新建、编辑、参照选择、明细维护和审批 |
| 单单据档案 | 同一组通用路由 | 一张 `form_data` 承载整份档案明细 |
| 报表 | 通用列表或专属视图 | 只读查询、汇总和导出 |

单据列表从上到下固定为：

1. 工具栏：按 `buttonGroups` 分组，右侧显示单据翻页、编号和状态。
2. 查询或表头区：字段由 `queryFields` 或表单元数据驱动。
3. 明细区：按 `gridTabs` 和 `detail.tabs` 渲染明细、汇总及合计。
4. 表尾：单据类显示备注、制单、审核和时间信息。

表格至少保持五行稳定高度；不足用占位行补齐，超出后在表体滚动。动态数据、加载状态和按钮状态不得改变工具栏、网格或翻页器的尺寸。

## 3. 配置映射

运行时配置的唯一来源是 MySQL `panel_config.config`，初始化基线在 `backend/src/main/resources/db/init.sql`。前端不维护同名配置副本。

| 配置路径 | 页面用途 |
|---|---|
| `metadata.panelName` | 页签、标题和弹窗名称 |
| `metadata.panelCategory` | 单据、档案或报表行为 |
| `metadata.singleDoc` | 单单据档案模式 |
| `metadata.buttonGroups[]` | 工具栏分组，结构为 `{name, actions}` |
| `metadata.panelPageDto.tablePages[0].queryFields` | 查询字段 |
| `metadata.panelPageDto.tablePages[0].gridTabs` | 列表明细和汇总列 |
| `dataSchema.fields` | 表头或档案字段 |
| `detail.tabs[]` | 明细键、字段、计算和汇总定义 |
| `selectConfig` | 选单来源、表头映射和明细映射 |

`detail.tabs[].key` 必须与接口返回的 `detail.<key>` 完全一致。修改配置后同时校验列表、表单、参照弹窗和选单弹窗，不能只看一个入口。

## 4. 字段与参照

| 数据类型 | 默认控件 |
|---|---|
| 文本、自动编号 | 输入框；自动编号只读 |
| 整数、小数、金额 | 数字输入或右对齐数值列 |
| 日期、日期时间 | 日期控件 |
| 是否 | 开关或复选框 |
| 下拉框 | 配置 `options` 的选择器 |
| 参照 | `RefPickDialog`，从另一个 SQL 面板读取 |
| 图片 | 图片单元格或上传控件 |

业务字段能对应基础档案时必须使用参照定义：`refPanel`、`refField`、`displayField`、`filter`、`refMap`、`refColumns` 和可选 `refMulti`。只有没有对应档案时才使用固定 `options`。

单单据档案的记录位于明细中，`engine.queryRefRows` 会先拉取单据，再展平首个明细页签并应用筛选。包含审核动作的单据参照只返回已审核来源单。

## 5. 工具栏与状态

- 分组结构只能使用 `{name, actions}`；组名执行首个动作，其余动作放入下拉菜单。
- `isDisabled(action)` 同时控制视觉和行为。`onButton`、`onGroupAction` 入口必须在请求前拦截禁用动作。
- 审核组统一承载审核、提交审批、审批通过、审批驳回、审批情况和弃审；按钮是否可见还受角色审批权限限制。
- 未实现动作使用中性提示，不发送伪请求，也不生成临时数据。
- 保存、删除、审批、生单等最终规则以后端为准，前端校验只用于即时反馈。

典型状态关系：

```text
草稿 -> 审核 -> 已审核 -> 弃审 -> 草稿
草稿 -> 提交审批 -> 审批中 -> 审批通过 -> 已审核
                         \-> 审批驳回 -> 草稿
```

## 6. 新建、保存与删除

- 新增先调用后端创建草稿，由后端生成单号、日期和默认值。
- 保存必须携带 `编号`；明细保存为完整 `detail`，不能用空值覆盖未加载的明细。
- 非草稿单据默认只读，允许的变更必须由状态矩阵明确开放。
- 删除明细行与删除整张单据是不同动作，确认文案必须明确目标。
- 单单据档案只有一张表单，新增和导入操作写入其明细数组，不能创建多张档案单据。

## 7. 选单、生单与弹窗

- 选单是拉式操作：目标单据通过 `selectConfig` 选择已审核来源单，并按 `headerMap`、`detailMap` 带入数据。
- 生单是推式操作：来源单据调用后端按钮动作，后端落库后返回 `gotoPanel` 和新编号，前端跳到目标面板并刷新。
- 列表双击使用 `VoucherFormDialog` 打开当前单据；参照、选单、审批历史、导入和 BOM 明细各使用独立对话框。
- 弹窗关闭或保存后只刷新相关数据，不重置整个门户页签状态。
- Excel 导入按表头名称精确匹配字段；没有匹配列时拒绝导入，预览确认后再写入。

## 8. 视觉和可用性

- 使用安静、密集、可扫描的制造业工作界面，禁止卡通文案、Emoji、装饰动画和无业务意义的渐变。
- 表头字段采用稳定网格；标签、输入框、必填标记和错误提示不能互相遮挡。
- 数量、单价、金额右对齐，日期和编号保持可完整识别的列宽。
- 图标按钮使用项目图标库并提供 tooltip；文字按钮只用于明确命令。
- 空状态、加载失败和权限不足使用中性业务文案。

## 9. 新面板接入清单

1. 在 SQL `panel_config` 和初始化脚本中增加配置，不向 `engine.js` 添加 Mock 数据。
2. 确认面板分类、表头字段、明细键、查询字段、按钮组和状态选项。
3. 需要参照时登记来源面板、筛选和字段映射。
4. 需要选单或生单时，同时实现后端校验和落库逻辑。
5. 需要审批时登记审批面板和角色权限，验证完整状态闭环。
6. 验证列表、表单、参照、选单、导入、窄屏和无数据状态。
7. 运行 `node tools/verify-project.mjs`。

历史页面规范、T+ 抓取记录和旧面板笔记仅保留在本地 `docs/archive/`，不上传代码仓库，只用于追溯设计来源。
