# 自定义页面入口清单

| 属性 | 内容 |
|---|---|
| 文档类型 | 前端设计 |
| 适用场景 | 修改自定义页面或看板 |
| 维护状态 | 生效 |
| 最后整理 | 2026-11-11 |
| 文档导航 | [文档中心](../README.md) |

`/panelx/list/:panelCode`、`/panelx/form/:panelCode` 之外的页面（工作台、看板、独立打印页）每个都可能有多个入口。改一个页面时，**它的每个入口都要跟着改**：菜单能进、列表按钮能进、业务总览节点能进，三处看到的必须是同一套界面和数据。

2026-11-11 的教训：工单排产改成分产品分区 + 一键排产，只改了独立页，列表里「排产」按钮打开的弹窗没改，用户从列表进去看到的还是老平铺表。根因不是忘记，是没人知道这个页面有两个渲染入口。

## 1. 规则

1. 改页面前先在本文件第 2 节找到它的**全部入口**，逐个改完再验证；新增入口要补登记，删除入口要划掉登记。
2. 同一份业务数据在多处渲染时，抽出共用组件或在同一文件共用同一套状态与模板，禁止两处各写一套表头和列。
3. 入口只能用路由跳转或复用同一个组件；不允许为「另一个入口」单独复刻一遍界面。
4. 入口的目标路径必须真实存在，新增或改名页面时同一改动内更新路由、菜单和所有跳转点。
5. 改完运行 `node tools/entry-audit.mjs`：校验本表与路由互相覆盖、所有站内跳转目标有路由。

## 3. 与通用面板的关系

`/panelx/*` 面板的入口由 `panel_config` 的按钮、`business/menus.js` 的菜单项和选单/生单映射共同决定，改动时按 [前端面板设计](前端面板设计.md) 第 5 节与第 9 节核对，不登记在本表。本表只管自定义页面。

## 4. 校验

- `node tools/entry-audit.mjs`：路由页面必须在本表登记、本表页面必须有路由、站内跳转字面量必须有对应路由。
- 校验失败通常意味着新增了页面没登记入口，或删改页面后留下了死链。
