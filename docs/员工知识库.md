# 员工知识库（仅管理员）

> 代码：`backend/app/models/employee_profile.py`、`backend/app/services/employee_profiles.py`、
> `backend/app/api/employee_profiles.py`
> 迁移：`alembic/versions/20261117_0109_employee_profiles.py`
> 前端：群聊页顶栏「员工知识库」按钮（仅管理员可见）

## 1. 它是什么

把系统里**真实发生过的操作**统计成员工画像，每周蒸馏一次，形成可直接阅读的
「职能卡片」；同时把项目讨论沉淀成「项目经验」资料。

**只有管理员能看**：接口 `_require_admin` + 服务层 `require_admin` 双重校验，
前端按钮对普通用户隐藏。这是后台行为数据，不该对本人或同事可见。

## 2. 数据来源（全部可复算）

| 数据 | 表 | 用来算什么 |
|---|---|---|
| 操作轨迹 | `audit_events` | 操作次数、类型分布、活跃天数 |
| 个人会话 | `chat_sessions` / `chat_messages` | 提问与产出量 |
| 群聊发言 | `project_group_messages` | 协作活跃度、参与项目 |
| 待办 | `group_todos` | 派单数、完成数 |
| AI 派单认领 | `assistant_events` | 认领次数、响应中位时长 |

**所有数字都能从原始表重算**，画像里不存任何未经统计的猜测。

## 3. 职能部门卡片的字段

```
姓名 · 周期（11-09 ~ 11-12）
活跃 3 天   会话 1   群聊 4   待办 1/2   认领 1   响应中位 2h
摘要：本周期…（模型或规则生成）
轨迹：活跃 3 天；个人会话 1 个 / 6 条消息；群聊发言 4 条；主要操作：登录 3、触发 AI 分析 8…
标签：生产计划 · 任务执行
优势 / 风险 / 关注
```

**周期选择**：默认「本周至今」，周一定时任务用「上一个完整周」。
刚上线时用完整上周会导致所有人都显示零活动（实测踩过）。

## 4. 防编造

模型只看到统计数字，不给它岗位信息以外的猜测空间。三道约束：

1. **零活动的人不调模型**：模型会照着岗位名编「销售」「质检」这类标签。
   现在零活动直接输出「本周期没有系统内的操作或协作记录」，标签为空。
2. **只有派单没有动作的人也不调模型**：模型只能猜，退回规则版。
3. **有派单未完成必须点出来**：这本身就是最重要的结论，不能被当成"无数据"吞掉。

## 5. 项目经验资料（自动沉淀）

字段：「问题 / 处理 / 经验 / 标签 / 贡献人 / 来源群」。

**沉淀时机**：每周一蒸馏员工画像后，顺带把上周的项目群讨论提炼成经验条目。
也可手动触发：`POST /admin/employees/experiences:extract?days=7`。

**什么算可沉淀的结论**（四类，命中任意一类即可）：

| 类型 | 例子 |
|---|---|
| 问题解决 | 孔位超差 → 换模具并试模 |
| 分工确定 | 周四出 120 件、周五补 80 件，李计划盯交期 |
| 决策形成 | 图纸以 v3 为准 |
| 经验纠正 | 新模具上线前必须试模验证公差 |

只有纯寒暄、纯系统通知、纯重复内容才跳过。

**两道省调用门槛**：

- 消息数 < 4 的群不处理
- **人类消息 < 2 条的群不处理**（全是 AI 通知的调度台没有讨论价值）

**去重**：同群同标题不重复沉淀，每周跑一次不会堆重复条目。

实测输出：

```
【交期无缓冲需提前统筹】  来源：销售一部
  问题：宏远机械 200 件 A 型机架要求周五交货，排产周四出 120 件、周五补 80 件，
        没有缓冲余量；上批抽检孔位偏 0.3mm，本批折弯公差尚无实测数据。
  处理：明确李计划跟进周四 120 件下线与周五补足 80 件，孙质检加严抽检并出具实测数据…
  经验：交期卡在节点且无余量时，应指定单一交期统筹人，并提前拿到质量实测数据再排产。
  标签：交期管理 · 质量抽检 · 分工确定
```

## 5.2 证据约束晋升（借鉴 skill-cairn）

参考开源项目 [allexyuan/skill-cairn](https://github.com/allexyuan/skill-cairn)（积微）的
「用证据约束知识晋升」模型，给每条经验补齐证据字段：

| 字段 | 含义 | 对应 cairn |
|---|---|---|
| `topic` | 同类经验的归组键（小写 slug） | `topic` |
| `status` | `unverified` / `verified` / `stale` | 同名受控状态 |
| `reusable` | 是否可跨场景复用 | `reusable` |
| `not_applicable` | 什么情况下不该照搬 | `## When not to use` |
| `source_count` | 独立来源数 | 晋升门禁输入 |

**自动沉淀的经验默认 `unverified`**：模型总结不等于验证过，这是最重要的一条纪律。

### 晋升门禁（四条件全过）

| 条件 | 默认门槛 |
|---|---|
| 同类经验条数 | ≥ 3 |
| 已验证条数 | ≥ 2 |
| 独立来源数 | ≥ 2 |
| 标记可复用 | ≥ 1 |

和 cairn 的理由一致：**重复出现不等于正确**——一个反复犯的错也会反复出现，
所以还要求验证 + 独立来源 + 可复用标记。

界面上第三个页签「晋升候选」直接展示每项的达标进度：

```
交期无缓冲需提前统筹          1 条经验 · 0/4 项达标
  ✗ 同类经验条数    1 / 3
  ✗ 已验证条数      1 / 2
  ✗ 独立来源数      1 / 2
  ✗ 标记可复用的条数 0 / 1
  尚未满足晋升门槛
```

### 语义去重

用字符 n-gram + Jaccard 相似度找可能重复的经验（中文按字符切，零依赖）。
`GET /admin/employees/duplicates?threshold=0.55` 返回相似对，供人工合并。

### 接口

```
PATCH /admin/employees/experiences/{id}   改证据状态 / 标可复用 / 补适用范围
GET   /admin/employees/promotions         各 topic 的晋升达标情况
GET   /admin/employees/duplicates         疑似重复条目
```

**没有做**（与 cairn 的差异）：没有导出 `SKILL.md` 草稿、没有独立的 Markdown 知识库目录、
没有配置化的受控标签集。cairn 面向「生成 Skill 文件」，这里面向「在 MES 里管理经验库」。

## 5.1 界面：全屏面板（非弹窗）

改成了**整页面板**，不是弹窗——画像有 7 个区块，弹窗塞不下。骨架按设计库
`PAGE-TEMPLATES.md` §6 详情页的「复杂布局」：页头 + 页签 + 左列表/右详情。

| 区域 | 内容 |
|---|---|
| 页头 | 返回按钮（Esc 也可退出）、标题、「仅管理员」标记、右上「生成本周画像」 |
| 页签 | 职能卡片（带计数）/ 项目经验（带计数） |
| 左列 | 280px 列表，选中项高亮；经验页签下多一个搜索框 |
| 右详情 | 自适应多栏（`minmax(360px, 1fr)`），概览与摘要卡横跨整行 |

**数值**（取自设计库 token）：控件高 32、圆角 6、正文 14/22、间距 8pt 网格
（8/16/24）、卡片白底 + 1px 边框 0 层阴影、数字 `tabular-nums` 右对齐。

**响应式**：1440 四栏、1180 以下回落单栏、900 以下切成
「列表 → 点进详情」两级（详情页隐藏列表，返回按钮回列表）。

图标取自设计库 `ArrowLeftOutlined` / `UserOutlined` 的 SVG 路径，不自造。

## 6. 接口

```
GET  /admin/employees                    画像列表（?user_id= 过滤）
POST /admin/employees/{user_id}:distill  为某人生成/刷新本周画像
POST /admin/employees:distill-all        批量生成（全员）
POST /admin/employees/experiences:extract 手动触发经验沉淀（?days=7）
GET  /admin/employees/experiences        项目经验（?keyword= 搜索）
```

`with_model=false` 时只用规则结论，不调模型（快、无成本）。

## 7. 定时任务

每周一 `ASSISTANT_REPORT_HOUR`（默认 9 点）后，在主动监控循环里自动蒸馏全员。
进程内按日期去重，重启不会重复跑。

## 9. 已知限制

1. **画像只反映系统内行为**：不在系统里干活的人会显示零活动，
   这不等于没工作，卡片上写的是「需确认是否在岗」而不是下结论。
2. **响应时长用中位数**，避免偶发长尾拉偏。
3. **认领时间用 `updated_at` 近似**，因为事件表没有单独的认领时间字段。
4. 项目经验只做自动提炼，没有手工新增/编辑入口（要改只能改库）。
