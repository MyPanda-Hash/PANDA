本文只保留当前必须遵守的开发、验证、文档和安全规则。功能演进过程、旧模式和一次性排障记录只保留在本地归档，不入库，也不作为实现依据。

## 1. 技术基线

| 范围 | 技术 |
|---|---|
| 前端 | Vue 3、Vite、Element Plus、Pinia、Vue Router |
| 后端 | Spring Boot 3、MyBatis-Plus、Spring Security、JWT |
| 数据库 | MySQL，默认本地端口 3308 |
| 构建 | Node.js、JDK 17+、项目内 Maven 3.9.9 |

系统只有一条数据链路：浏览器 -> Spring Boot -> MySQL。不得重新加入 Mock、外部 PanelX 直连、PanelX 代理或运行模式开关。

## 2. 目录与依赖

| 目录 | 所有权 |
|---|---|
| `frontend/src/core/` | 通用面板视图和网络基础能力 |
| `frontend/src/business/` | MES 接口适配、菜单和业务编排 |
| `frontend/src/layout/`、`views/` | 门户壳和专属页面 |
| `backend/.../controller/` | HTTP 协议层 |
| `backend/.../service/` | 业务规则和事务 |
| `backend/.../mapper/`、`entity/` | 数据访问 |
| `backend/src/main/resources/db/` | 初始化和可重复数据库变更 |
| `tools/` | 构建、检查、抓取和维护工具 |

通用组件不得写死业务面板字段、编码或种子数据。当前 `core/views` 允许通过统一的 `business/engine` 适配器访问业务能力；新增耦合必须集中在适配边界，不能在多个组件中各自实现接口规则。

## 3. 开发规则

- 先读取当前文件和工作区状态，保留已有未提交改动。
- 优先修改权威源：运行配置在 SQL，业务规则在后端，展示规则在前端通用组件。
- 新抽象必须消除真实重复或明确匹配现有边界；一次性补丁脚本不作为长期实现。
- 面板字段、明细键、按钮名和状态值是跨端契约，改动时同时检查数据库、后端和前端消费者。
- 中文文件统一 UTF-8 无 BOM；代码标识和路径保持稳定，避免无意义批量重命名。
- 界面文案使用中性业务语言，不加入 Emoji、卡通化提示或装饰性动画。

## 4. 本地运行

```powershell
# 数据库初始化
mysql -uroot -p < backend/src/main/resources/db/init.sql

# 当前 PowerShell 会话注入凭据
$env:SPRING_DATASOURCE_PASSWORD = '<数据库密码>'
$env:MES_JWT_SECRET = '<至少 64 位随机密钥>'

# 后端
backend\build.bat
backend\run.bat

# 前端开发服务
Set-Location frontend
npm install
npm run dev
```

构建产物齐全时可运行 `start-project.bat`，它检查 MySQL 3308、后端 jar 和前端 `dist`，然后启动后端 8080 与前端预览 4173。

## 5. 验证矩阵

| 改动 | 最低验证 |
|---|---|
| Markdown | `node tools/docs-audit.mjs` |
| 前端 JS/Vue | 前端生产构建；共享逻辑需要对应交互回归 |
| 后端 Java/SQL | Maven 打包；写接口覆盖成功和失败路径 |
| 面板配置 | 列表、表单、参照、选单、审批和初始化 SQL |
| 跨端或部署改动 | `node tools/verify-project.mjs` |

统一提交前命令：

```powershell
node tools/verify-project.mjs
git diff --check
```

测试数据写操作优先使用结构化 API 或 Node 脚本。PowerShell 管道处理中文请求体时必须明确 UTF-8，避免编码污染后写入数据库。

## 6. 质量红线

- 禁止对源码做未经限定的全局字符替换；批量修改后必须构建并检查差异。
- 编号生成禁止使用 `COUNT + 1`，必须取最大序号、查重并依赖唯一键兜底。
- 页面未加载完整明细时禁止保存，后端也不得用缺失的 `detail` 清空原数据。
- 禁用按钮必须同时阻止事件和请求，不能只改颜色或鼠标样式。
- `export ... from` 不会创建本地绑定；文件内部使用同一符号时必须显式导入。
- 页签身份包含 `path + query`，切换或恢复时不能丢失单据编号。
- 报表、档案和业务单据的查询形态不同，禁止用一套平铺假设处理全部面板。

本地归档文件保持历史原貌，可以包含过时路径和结论；引用归档时必须明确它不是当前实现依据，也不能把归档内容重新提交到仓库。

文档格式与可达性由 `tools/docs-audit.mjs` 检查。代码旁工具说明见 [项目工具说明](../../tools/README.md)；T+ 取证方法见 [抓取工具说明](../../tools/tplus-grab/README.md)。

## 8. 安全要求

- 禁止提交真实密码、Token、Cookie、私钥、数据库备份凭据和生产主机身份信息。
- 示例统一使用 `<数据库密码>`、`<服务器地址>`、`<Token>` 等占位符。
- 生产环境必须轮换默认管理员密码、数据库密码和 JWT 密钥。
- 数据库备份、SQL 导入和全量部署前先确认目标环境，并保留可恢复备份。
- 对用户、角色、审批和删除逻辑的修改必须同时验证未授权路径。

## 9. 完成标准

一项改动只有在以下条件满足后才算完成：

1. 行为与对应主题文档一致。
2. 无残留旧模式分支、临时脚本或重复配置源。
3. 相关成功、失败、无数据和权限状态已验证。
4. 文档链接和构建检查通过。
5. 未覆盖或回退工作区中的其他改动。
