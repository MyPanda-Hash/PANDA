本文定义采购管理的目标流程、面板职责、关键字段、动作、状态和校验，并给出分阶段实现顺序。金蝶产品实测差异见 [金蝶星辰实证研究](金蝶星辰实证研究.md)，面板全景见 [面板全景与五合一对照](面板全景与五合一对照.md)。系统保留现有面板编码，不按金蝶 FormId 重命名；金蝶单据名只作为功能对照。

## 1. 目标流程

金蝶标准采购链按是否启用收料、质检分为三条路径：

```text
A 有收料有质检：采购申请 → 采购订单 → 收料通知 → 检验单 → 采购入库 → 采购发票 → 应付 → 付款
B 有收料无质检：采购申请 → 采购订单 → 收料通知 → 采购入库 → 采购发票 → 应付 → 付款
C 无收料无质检：采购申请 → 采购订单 → 采购入库 → 采购发票 → 应付 → 付款
```

采购退货分两类：

- 检验退料：货物未入库，从收料通知/检验结果退回，不产生库存出库。
- 库存退料：货物已入库，从采购入库单退回，产生库存出库并冲减应付。

### 1.1 金蝶业务流程图实测（2026-11-06）

金蝶 AI 星辰采购流程把同一组单据画成两条泳道：

- 先收发票，后收货：采购申请 → 采购订单 → 采购发票（入库）→ 付款单；采购发票（入库）可单票勾稽到采购入库单，采购订单也可直接入库；采购入库单 → 采购退货单 → 采购发票（退货）→ 付款退款单。
- 先收货，后收发票：采购订单 → 收料通知单 → 采购入库单（收料入库），或采购订单 → 拣验货单 → 采购入库单（拣验入库）；采购入库单 → 采购发票（入库）确认应付 → 付款单；采购入库单 → 采购退货单 → 采购发票（退货）确认应退 → 付款退款单。

本系统映射：采购申请 = `PU_REQ`，收料通知 = `ARRIVAL_IN`，拣验货 = `INSPECTION`，采购入库 = `PURCHASE_IN`，采购退货 = `PURCHASE_RETURN`，采购发票 = `PU_INVOICE`；付款与退款共用 `RECEIPT_PAYABLE`（正数付款、负数退款），当前不单独建「付款退款单」面板。

采购发票分入库发票与退货发票两个方向，按表体行级来源与入库/退货单勾稽。财务采用「票到确认」：采购入库只写库存事务、不确认应付；采购发票审核按价税合计确认应付；采购退货单审核确认红字应付；红字发票只做税务与勾稽，不重复记账。三单匹配（订单、入库、发票）以发票表体的行级来源和勾稽关系为依据。

## 2. 单据与面板映射

| 金蝶单据 | 本系统面板 | 现状 | 主要缺口 |
|---|---|---|---|
| 采购申请单 | `PU_REQ` | 可用 | 已下单/未下单数量反写、计划订单投放、费用采购类型 |
| 采购订单 | `PU_ORDER` | 可用 | 下推到货、订单变更、价目表取价、累计入库/开票 |
| 收料通知单 | `ARRIVAL_IN` | 部分 | 到货/接收/拒收/检验数量、累计入库/退货、快速收料、紧急放行 |
| 检验单 | `INSPECTION` | 部分 | 检验结果回写、让步/报废/判定退货、抽样方案 |
| 采购入库单 | `PURCHASE_IN` | 可用 | 库存退料入口、累计入库、发票勾稽 |
| 采购退料单 | `PURCHASE_RETURN` | 部分 | 检验退料已通，库存退料待补 |
| 采购发票 | `PU_INVOICE` | 部分 | 真实单据形态（表头 + 表体行级来源）、行级选单、一票多单/一单多票、勾稽、红字信息表 |
| 应付单/付款单 | `finance_voucher`、`RECEIPT_PAYABLE` | 可用 | 票到确认、三单匹配、付款退款、预付 |

## 3. 面板功能规格

### 3.1 采购需求分析 `PU_REQ_ANALYSIS`

- 定位：只读分析，按生产加工单材料需求、现存量、已请购、已出库计算建议请购数量。
- 字段：存货、规格、计量单位、需用数量、现存量、已请购、已出库、建议请购数量。
- 动作：查询、刷新、退出；后续增加“生成请购单”把选中行写成请购单草稿。
- 校验：只读；生成请购单时必须已选行且建议数量大于 0。

### 3.2 请购单 `PU_REQ`

- 表头：单据日期、单据编号、业务类型、建议供应商/编码/简称、部门、请购人、需求日期、项目、到货地址、备注。
- 明细：存货编码/名称、规格型号、采购单位、数量、数量2、需求日期、单价、税率%、含税单价、金额、含税金额、现存量。
- 动作：新增、保存、删除、提交审批/审批通过/审批驳回/弃审、生成采购订单、选销售订单。
- 状态：草稿、审批中、已审核、已中止。
- 校验：来源行数量必须大于 0；已审核才能下推采购订单；已下单数量回写后，未下单数量不得为负；同一条请购明细可按剩余未下单量**分批下单**，不得超量。

### 3.3 采购订单 `PU_ORDER`

- 表头：单据日期、单据编号、供应商/编码、项目、到货地址、交货日期、合同号、币种、汇率、付款方式、发货状态、数据来源。
- 明细：物料编码/名称、规格型号、单位、数量、数量2、单价、金额、税率%、含税单价、含税金额、仓库、预计到货日期、现存量。
- 动作：选单（选请购单）、生成到货单、生成采购入库单、生成采购发票、订单变更、提交审批/审批/弃审。
- 状态：草稿、审批中、已审核、已中止、已关闭。
- 校验：选单只显示已审核且未完全下推的请购单；同一条请购明细只能下推到采购订单（不得与其它下游面板混用），可按剩余量分批下单；已审核才能下推；变更单审核并生效后才更新原订单。采购订单直开发票属于财务口径，不占用订单行的到货/入库额度，同一订单行仍可继续生成到货单或采购入库单。
- 直接入库（路径 C）：零收料/零质检的业务可直接生成采购入库单，不经过到货与检验；同一订单行一旦已有到货单（或其他非财务下游单据），直入被拒，两条履约路径按订单行互斥。

### 3.4 收料通知 `ARRIVAL_IN`

- 定位：非库存单据，不更新即时库存；有质检时作为报检来源，无质检时直接下推采购入库。
- 表头：单据日期、单据编号、供应商/编码、采购订单号、仓库、到货日期、检验状态、数据来源。
- 明细：存货编码/名称、规格型号、采购单位、到货数量、到货拒收数量、实收数量、检验方式、抽检比例、检验数量、合格数量、让步接收、报废、累计入库数量、累计退货数量。
- 动作：选采购订单、生成检验单、生成采购入库单、生成退货单、快速收料、紧急放行。
- 状态：草稿、已审核、已中止；已审核才可下推。
- 校验：实收数量 = 到货数量 - 到货拒收数量；检验数量不得超过到货数量；累计入库 + 累计退货不得超过实收数量；同一来源行不得重复入库；**同一订单行可按剩余未到货量分批生成到货单**（不同履约下游面板互斥；采购发票不参与互斥）。
- 入库门禁：非免检物料必须先完成检验，不能从到货单直接生成采购入库单；免检物料需把明细「检验方式」设为「免检」。
- 混装到货：同一张到货单可同时含免检行与需检行。「生成检验单」只为非免检行建检验单，并把检验方式/抽检比例带入；免检行仍从到货单直接入库。已由有效检验单接手的行，到货单直接入库时跳过，不再整单报错。表头「检验状态」只按需检行判断，需检行全部检完即为已检。

### 3.5 检验单 `INSPECTION`

- 表头：单据日期、单据编号、业务类型、检验类别、检验部门、检验员、供应商、仓库、采购订单号、加工单号、来源单号。
- 明细：存货、规格、批号、仓库、检验方式、抽检比例、计量单位、报检数量、**应检数量**、检验数量、检验结果判定、合格数量、不合格数量、**验收退回数量**、让步接收数量、报废数量、**不合格原因**、**让步接收含税单价**、检验方案、检验项目、**记录样本明细、样本明细个数**。
- 兼容口径：「判定退货数量」保留为内部字段（历史单据与老报表），主表列对外显示「验收退回数量」，两者由不合格处理页签同步且数值一致。
- 生单方式（2026-11-05 确认）：**保持手工生单**，审批通过后不自动创建下游；由用户执行「生成采购入库单/生成采购退货单/生成产成品入库单/生成委外入库单」。
- 不合格处理页签：关联明细行号、处理方式（退回/返工/让步接收/报废）、处理数量、不合格原因。
- 检验项目页签（2026-11-06）：关联明细行号、检验项目编码/项目、检验内容、检验标准、标准上下限、检验结果、单项判定（合格/不合格）、检验时间/检验员、备注；任一单项判定不合格时，主行检验结果判定不能为合格。
- **批次处置标记（2026-11-05）**：明细增加 处置方式（合格接收/让步接收/降价接收/部分退回/全批退回/返工/返修/挑选接收/报废）、处置数量、结算方式（原价/折价/索赔/免费补货/退款）、折价率%、折价金额、调整后单价、责任归属（供应商/运输/我方/待定）、处置状态（待确认/已确认/已执行/已结算/已结案）、复检要求/结果。
- 动作：确认处置、生成采购入库单、生成采购退货单、审核/弃审。
- 联动：上方检验行判为不合格（不合格数量>0 或判定≠合格）后，「不合格处理」页签自动生成关联行，带入关联明细行号、存货编码/名称、仓库与不合格原因，处理数量默认等于不合格数量（多条处置时不再自动覆盖）；恢复合格时移除该行处置。主行填写的「不合格原因」在保存时自动带下到处理行。
- 处置门禁：处置状态为「待确认」时禁止生成入库/退货/发票；「确认处置」或审核/审批通过后置为已确认。检验数量、合格/不合格数量、判定、处置方式、折价率、复检结果或不合格处理页签发生变化并保存草稿时，原确认自动失效并回退为「待确认」，必须重新确认；仅备注等展示字段变化不触发。
- 处置一致性：全批退回的退回数量必须等于检验数量（含合格品）；判定为全批退回时处置方式必须为全批退回，避免「判全退却只退部分」；部分处置的退回数量等于不合格数量。
- 抽检：到货行的检验方式/抽检比例带入检验单；检验数量默认等于报检数量（按整批处置），检验员可按实际抽样改写，改写后来源占用仍按报检数量计算，防止同一批到货生成第二张检验单。
- 让步接收含税单价：折价率>0 时按原含税单价 ×（1 − 折价率）回写；纯让步接收行（无合格品）采购入库按该单价结算，合格+让步混行仍按原价，避免合格部分被折价。
- 降价接收：折价率必须 0-100，调整后单价 = 原单价 ×（1 − 折价率），采购入库与发票按折后价结算。
- 校验：报检数量 ≥ 应检数量 ≥ 检验数量；合格 + 不合格 = 检验数量；退回数量不得超过可退数量；判定值必须为 合格/让步接收/部分报废/全批报废/全批退回。
- 返工/返修门禁：处置为返工/返修时，必须复检结果为「合格」才允许生成采购入库单。

### 3.6 采购入库单 `PURCHASE_IN`

- 表头：单据日期、单据编号、供应商/编码、仓库、采购订单号、到货单号、检验单号、入库类别、数据来源。
- 明细：存货、规格、仓库、实收数量、单价、金额、税率、含税单价、含税金额、批号；来源面板/来源单号/来源行号/来源数量随生单写入，用于反写累计与追溯。
- 动作：生成采购退货单（库存退料）、生成采购发票、审核/弃审。
- 状态：草稿、审批中、已审核、已中止。
- 校验：已审核才能下推；库存退料数量不得超过入库数量；审核时写库存事务，不产生应付/凭证（票到确认，应付由采购发票审核确认）。
- 来源守卫：来料检验只能生成采购入库单；成品检验/委外检验必须走产成品入库/委外入库，防止同一张检验单串到错误的入库链。

### 3.7 采购退货单 `PURCHASE_RETURN`

- 两类来源：
  - 检验退料：来源检验单，未入库，不产生库存事务。
  - 库存退料：来源采购入库单，产生库存出库并冲减应付。
- 表头：单据日期、单据编号、供应商/编码、仓库、退货日期、退货原因、来源单号。
- 明细：存货、规格、仓库、数量、实收数量、单价、金额、批号、来源行号（列表页按明细网格展示）。
- 动作：选单、提交审批/审批通过/审批驳回/审批情况/弃审、生成采购发票（采购退货）。
- 审批：2026-11-05 起对齐其他采购单据走审批流（不再直接审核）；审批通过才产生库存出库与 `AP_RETURN`。
- 库存方向：检验退料（来源检验单、未入库）审批通过**不产生库存事务**，避免把从未入库的货扣成负库存；库存退料（来源采购入库单/带入库单号）审批通过产生 OUT 出库。
- 金额：退货行按本次退货数量 × 来源单价/含税单价折算金额、税额、价税合计，不整行复制来源金额；部分退货不会把金额/税额放大。
- 校验：已审核才能下推；退货数量不得超过来源可退数量；红字发票由本单据「生单」生成，财务侧不再重复冲减。

### 3.8 采购发票 `PU_INVOICE`

- 定位：采购发票是独立单据，按真实 ERP 形态由**表头 + 表体**组成。表头记票面与结算汇总，表体行记开票明细与行级来源；一张发票可覆盖多张入库/退货单（一票多单），同一入库单行也可分批开多张票（一单多票）。来源不再由表头「入库单号」单值承载。
- 页面形态：采购发票入口为列表页，列表只显示单据日期、单据编号、业务类型、供应商、开票类型、发票号码、开票日期、价税合计、勾稽状态、单据状态等表头主信息；点「新增」或双击列表行进入单据详情页，在同一页维护表头与表体，保存后返回列表。
- 开票路径：同一张采购发票承载两种开票时序——先票后货（采购订单预开票，收货后按入库单行勾稽）与先货后票（采购入库后按入库单开票）；采购退货走红字发票。两条路径共用现有表头/表体与行级来源字段，不新增独立单据类型。流程图用「采购订单 → 采购发票」虚线和「采购发票 → 采购入库单」虚线表示先票后货的货到入库/勾稽，用「采购入库单 → 采购发票」实线表示先货后票。
- 业务类型：`采购发票`（蓝字正票）、`采购发票(退货)`（红字票）。状态沿用草稿、审批中、已审核、已中止。
- 来源：采购入库单（蓝字正票）、采购退货单（红字）、采购订单（预开票/直运，仅财务口径，不占用到货/入库额度）。前两类按表体行级选单，采购订单直开按订单行生成。
- 表头：
  - 单据日期、单据编号、业务类型、供应商/供应商编码、部门、业务员、备注。
  - 发票类型：增值税专用发票、增值税普通发票、数电专用发票、数电普通发票（简称专票/普票/数电专票/数电普票）。纸质专票/普票填写发票代码与 8 位发票号码；数电票没有发票代码，发票号码为 20 位。
  - 发票代码、发票号码：按供应商 + 发票代码 + 发票号码唯一，同一张发票不允许重复登记。
  - 开票日期：票面开票日期，允许与单据日期不同（补录历史票）。
  - 来源单据号：本次开票涉及的第一张源单编号，一票多单时保留首单号便于检索；完整来源关系记在表体行。
  - 不含税金额、税额、价税合计：表头合计等于表体行合计，价税合计 = 不含税金额 + 税额；行税额按不含税金额 × 税率% 计算并四舍五入到分，表头不再二次摊派尾差。
  - 勾稽状态：未勾稽、部分勾稽、已勾稽。
  - 红字信息表编号、原发票号：红字发票必填；原发票号指向被冲销的蓝字发票，行级对应关系见「原发票行号」。
- 表体：
  - 存货编码/存货名称、规格型号、计量单位。
  - 数量：本次开票数量；蓝票为正，红票为负。
  - 单价：不含税单价，恒为正数，红票不取负单价。
  - 税率%、金额（不含税）、税额、价税合计：金额 = 数量 × 单价，税额 = 金额 × 税率%，价税合计 = 金额 + 税额；红票金额、税额、价税合计为负。
  - 源单类型：采购入库单、采购退货单、采购订单。
  - 源单编号、源单行号：指向具体来源单据的明细行，是占用、勾稽与追溯的唯一依据。
  - 入库数量：源单行的可开票基数。采购入库行取实收数量，采购退货行取退货数量，采购订单行取订单数量（预开票额度）。
  - 已开票数量：源单行累计已勾稽的开票数量；红票行即累计已开红票数量。
  - 未开票数量：入库数量 − 已开票数量。
  - 红票行另带原发票号、原发票行号，指向被冲销的蓝票明细行，与表头原发票号一致。
- 录入：
  - 手工新增：表头票面信息与表体行可手工录入，用于费用、补录等无入库来源的行；这类行不占用入库额度、不参与入库勾稽。有入库来源的存货行按行级选单带入。
  - 行级选单：按表头供应商查询该供应商已审核且未开票数量大于 0 的采购入库单/采购退货单行，可跨多张单据勾选，逐行填本次开票数量；带入存货、规格型号、计量单位、单价、税率、源单类型/编号/行号、入库数量、已开票数量、未开票数量。选单按行，不按整单。
  - 一票多单：一次选多张入库/退货单的多行生成一张发票，表头金额为各行合计。
  - 一单多票：同一源单行按未开票数量分批开票，蓝票累计开票数量不得超过入库数量；最后一张开完后未开票数量为 0。
  - 数量门禁：本次开票数量 ≤ 未开票数量；已审核但未勾稽的发票行按源单行反查计入占用量，避免勾稽前重复开票。红票行同时受「退货数量 − 已开红票数量」和「原蓝票数量 − 已红冲数量」约束。
- Excel 导入：
  - 模板列：发票代码、发票号码、开票日期、供应商、业务类型、来源单据号、入库单号、存货、数量、单价、税率、税额、价税合计、来源面板、来源单号、来源行号。
  - 一行对应一条发票明细；按发票号码 + 供应商分组生成采购发票草稿，组内行汇总为表头金额/税额/价税合计。
  - 红字行（业务类型 = `采购发票(退货)`）数量、税额、价税合计必须为负数，单价为正；导入后仍按发票唯一、来源已审核、未开票数量充足等规则校验。
- 勾稽：
  - 勾稽报表（当前形态）：`PURCHASE_INVOICE_MATCH` 采购发票勾稽表按发票行列出发票行、来源入库单行、入库数量、已开票数量、未开票数量与勾稽状态，用于一票多单、一单多票的逐行核对。当前独立勾稽「工作台」以报表形式提供，不做三栏配对界面；发票行已在表体带来源面板/来源单号/来源行号，报表按来源字段关联，不另建配对表。
  - 勾稽状态按表头汇总：全部来源行未开票为未勾稽，部分数量已开票为部分勾稽，全部来源行开完为已勾稽；保存时由来源行未开票数量派生并回写源单行已开票/未开票数量。
  - 勾稽不改变发票金额、税额与审批状态；红票行与退货行对应，同时受原蓝票可冲数量约束。采购订单直开票行入库前不参与入库勾稽，入库后按入库行补勾稽。
  - 后续再做批量勾稽动作：手工配对/拆分配对、已勾稽数量锁定、弃审前先取消勾稽。
- 红字：
  - 数量、金额、税额、价税合计为负，单价为正；业务类型为 `采购发票(退货)`。
  - 必须关联原蓝票行（原发票号 + 原发票行号）与红字信息表编号，原蓝票必须已审核。
  - 同一原蓝票行累计红冲数量（绝对值）≤ 蓝票开票数量；允许多次部分红冲，冲完为止。
  - 无蓝票、退货未入库（检验退回）禁止开红票，此类退货按负数应付或退货不开发票处理。
  - 红字发票只做税务与勾稽，不产生 AP/凭证，也不写库存事务。
- 应付（票到确认）：
  - 采购入库审核只写库存事务，不产生 AP、不生成凭证。
  - 蓝字采购发票审核按价税合计确认应付（`AP`，来源单据为采购发票）；一票多单时 AP 按供应商汇总，行级来源供三单匹配与勾稽使用。
  - 采购退货单审核产生 `AP_RETURN`（红字应付）；红字发票审核不重复记账。
  - 货到票未到不入账应付，月末按「入库未开票」报表（未开票数量、未开票金额）列示，不做暂估凭证。
- 动作：新增、保存、删除、选单（行级选采购入库单/采购退货单/原蓝票）、Excel 导入、提交审批/审批通过/审批驳回/审批情况/弃审、打印/导出；勾稽核对走 `PURCHASE_INVOICE_MATCH` 报表，批量勾稽/取消勾稽动作后续补。应付由审核自动产生，不再单独「生成应付」。
- 校验：发票代码 + 发票号码按供应商唯一；蓝票数量必须大于 0，红票数量必须小于 0；源单必须已审核且未开票数量充足；表头金额等于表体行合计；红票缺原蓝票、缺红字信息表编号或超额红冲一律拒绝。
- 变更（2026-11-04）：T+ 兼容的进货单 `PU_IN` 已废弃，发票来源从进货单改为采购入库单/采购退货单。
- 变更（2026-11-06）：发票改为真实单据形态（表头 + 表体行级来源），支持行级选单、一票多单、一单多票与勾稽；财务改为票到确认。

### 3.9 应付与付款

- 票到确认：采购入库审核只写库存事务，不产生 `AP`、不生成凭证；蓝字采购发票审核按价税合计产生 `AP` 与凭证，来源单据为采购发票。
- 退货：采购退货单审核产生 `AP_RETURN`（红字应付）；红字发票只做税务/勾稽，不再重复产生 `AP`/凭证。
- 未开票入库：不在账上确认应付，按「入库未开票」报表（未开票数量、未开票金额）跟踪，不做暂估凭证。
- 付款：`RECEIPT_PAYABLE` 付款单，支持核销/反核销。
- 后续：三单匹配（订单/入库/发票）、付款退款单、预付款。

- `PU_INVOICE` 真实单据形态（2026-11-06）：表头补发票类型（专票/普票/数电专票/数电普票）、发票代码、发票号码、开票日期、来源单据号、不含税金额、税额、勾稽状态、红字信息表编号；表体补源单类型/源单编号/源单行号/入库数量/已开票数量/未开票数量，表头金额改为表体行合计。
- 行级选单与一票多单/一单多票（2026-11-06）：按供应商查询已审核且未开票数量大于 0 的采购入库/退货行，跨单勾选并逐行填本次开票数量；同一源单行可分批开票，蓝票累计开票 ≤ 入库数量。
- 发票勾稽状态（2026-11-06）：勾稽状态由来源行的未开票数量派生，未开票=未勾稽、部分开票=部分勾稽、全部开完=已勾稽；保存时回写源单已开票/未开票数量，不改变发票金额与审批状态。
- 票到确认（2026-11-06）：采购入库审核不再产生 AP/凭证；蓝字采购发票审核按价税合计产生 AP 与凭证；采购退货单审核产生 `AP_RETURN`；红字发票只做税务/勾稽，不重复记账；未开票入库按「入库未开票」报表跟踪，不做暂估凭证。
- 发票勾稽报表（2026-11-06）：新增 `PURCHASE_INVOICE_MATCH` 采购发票勾稽表，按发票行列出发票行、来源入库单行、入库数量、已开票数量、未开票数量与勾稽状态，支撑一票多单/一单多票核对；当前独立勾稽工作台以报表形式提供，发票表体已带来源字段，批量勾稽动作后续再做。

- 历史 AP 清理脚本（2026-11-06）：票到确认上线后，先备份 `finance_voucher`/`accounting_entry`，再删除来源面板为 `PURCHASE_IN` 的 AP 与会计分录；执行后应付只剩 `PU_INVOICE`/`OUTSOURCE` 来源，不再保留入库环节的重复应付。

## 6. 验收

1. 采购订单选请购单：已审核请购单可见，生成采购订单，来源字段齐全。
2. 采购订单生成到货单：已审核订单可生成到货单，数量、供应商、订单号带入。
3. 到货单生成采购入库单：已审核到货单可生成入库单，实收数量正确。
4. 采购入库单生成采购退货单：已审核入库单可生成退货单，审核后库存减少、`AP_RETURN` 产生。
5. 采购入库单生成采购发票：已审核入库单可生成正票（数量取实收数量、税额/价税合计正确）；采购退货单可生成红字发票（业务类型=采购发票(退货)）。
6. 数量为 0、来源未审核、重复生成、超量生成均被拒绝并给出明确提示。
7. 前端 `npm test`、`npm run build` 通过；后端 Maven 打包通过。
8. 来料处置：检验行标记不合格并确认处置后才能生成入库/退货；未确认时生单被拒绝并提示行号。
9. 全批退回：退回数量等于检验数量（含合格品）；降价接收：入库按折后单价、发票按折后金额。
10. 红字发票：由已入库且已开蓝票的采购退货单生成「采购发票(退货)」——数量/金额/税额/价税合计为负、单价为正、原发票号=蓝票号；未入库/未开蓝票的退货被拒绝开红票；审核不产生重复 AP/凭证。
11. 检验退料：检验单退回 2/10 件生成采购退货单，金额/税额/价税合计按 2 件折算；审批通过后库存不变（无 OUT 事务），库存退料审批通过才减少库存。
12. 混装到货：免检行 + 需检行同单时，生成检验单只含需检行；需检行检验完成后，免检行仍可从到货单生成采购入库单，已检验行不重复入库。
13. 来源守卫：成品检验单执行「生成采购入库单」被拒绝并提示改走产成品入库；来料检验单执行「生成产成品入库单」被拒绝。
14. 处置失效：检验单确认处置后修改合格/不合格数量并保存，处置状态回退「待确认」，未重新确认时生单被拒绝；仅改备注仍保持已确认。
15. 检验单字段：到货单生成检验单后，表头带出采购订单号/检验部门，明细带出应检数量/批号/含税单价；不合格处理页签退回数量回写为验收退回数量，主行不合格原因自动带下。
16. 应检校验：应检数量小于检验数量时提交/确认处置被拒绝并提示行号；应检数量大于报检数量同样被拒绝。
17. 让步结算：纯让步接收行（无合格品）生成采购入库时按让步接收含税单价结算；合格+让步混行仍按原价。
18. 发票表头字段：发票类型可选专票/普票/数电专票/数电普票；发票代码、发票号码、开票日期、来源单据号、不含税金额、税额、价税合计、勾稽状态、红字信息表编号齐全；同一供应商重复登记相同发票代码 + 发票号码被拒绝。
19. 行级选单：按供应商查出多张未开票入库单行，跨单勾选后生成一张发票（一票多单），每行带入源单类型/编号/行号/入库数量/已开票数量/未开票数量；本次开票数量超过未开票数量被拒绝。
20. 一单多票：同一入库单行分两次开票，累计开票等于入库数量且未开票数量递减到 0；第三次开票被拒绝。
21. 发票勾稽：按来源行未开票数量派生勾稽状态，状态由未勾稽经部分勾稽到已勾稽；保存后源单已开票/未开票数量回写正确；核对通过 `PURCHASE_INVOICE_MATCH` 报表按发票行查看。
22. 票到确认：采购入库审核后无 AP/凭证；蓝字发票审核后产生 AP 与凭证；采购退货单审核产生 `AP_RETURN`；红字发票审核不产生 AP/凭证，也不写库存事务。
23. 红票负数：红字发票数量/金额/税额/价税合计为负、单价为正；缺原蓝票或红字信息表编号被拒绝；同一原蓝票行累计红冲超过蓝票数量被拒绝；无蓝票/未入库退货禁止开红票。
24. 勾稽报表：`PURCHASE_INVOICE_MATCH` 按发票行显示来源入库单行、入库数量、已开票数量与未开票数量；一票多单/一单多票的未开票数量与源单行一致。
25. Excel 导入：按模板导入多行后按发票号码 + 供应商生成采购发票草稿，发票代码、发票号码、开票日期、供应商、业务类型、来源单据号、入库单号、存货、数量、单价、税率、税额、价税合计、来源面板、来源单号、来源行号完整；红字行数量/税额/价税合计为负，非负数被拒绝。
26. 历史 AP 清理脚本：执行前已备份 `finance_voucher`/`accounting_entry`；执行后 `PURCHASE_IN` 来源的 AP 与会计分录为 0，应付只剩 `PU_INVOICE`/`OUTSOURCE` 来源。
