## 2. 模块全景（左侧导航 22 项）

金蝶的模块划分按"经营场景 → 进销存 → 财税 → 生产 → 基础"组织，不是按 ERP/MES/WMS 这类系统名切分。

```text
经营层：快捷应用、老板参谋、协同助手
零售层：零售资料、门店管理、会员管理、门店营销、门店商城、订货商城
业务层：销售管理、采购管理、库存管理、应收应付
生产层：生产管理、受托加工、委外管理
财税层：账务处理、财务报表、出纳管理、资产管理、工资管理、费用报销
基础层：基础资料、系统设置、自定义中心
```

**对比本系统**：本系统用"智能供应链 / 新生产 / 质量管理 / 基础设置"四大类，缺少独立的**应收应付**、**账务处理**、**财务报表**、**出纳管理**、**资产管理**、**工资管理**、**费用报销**七个模块。这七个正是财务闭环的全部内容。

## 3. 业务全景图的分层逻辑

金蝶把业务全景图分成五块，箭头表示依赖方向：

```text
批发经营 / 数字零售 / 数智生产  ← 三个业务入口
            ↓
        智能进销存  ← 采购、销售、库存、应收应付、质检
            ↓
         智慧财税  ← 财务处理、税务处理、资产管理、出纳、工资、费用报销
```

**核心洞察：质检管理被放在"智能进销存"里，不是独立系统。** 金蝶不认为质量是独立模块，而是进销存的组成部分。本系统把 QMS 单独列为一级菜单，从业务归属上更清晰，但要注意质量数据必须回写到库存与应付，不能自成孤岛。

## 4. 五条主流程（实测完整单据序列）

### 4.1 采购流程

金蝶把采购分成**两条并行路径**，这是本系统完全没有的设计：

```text
路径 A：先收发票，后收货
  采购申请 → 采购订单 → 采购发票(入库) → 付款单
                    ↓
              采购入库单 → 采购退货单 → 采购发票(退货) → 付款退款单

路径 B：先收货，后收发票
  采购申请 → 采购订单 → 收料通知单 → 拣验货单 → 采购入库单
                                                    ↓
                                            采购发票(入库) → 付款单
                                                    ↓
                                      采购退货单 → 采购发票(退货) → 付款退款单
```

**关键发现**：
1. 金蝶有 `收料通知单` 和 `拣验货单` 两张本系统没有的单据。收料通知单是仓库收货指令，拣验货单是质检+入库合并操作。
2. 采购发票有"入库"和"退货"两种业务类型，同一张单据承担两个方向。
3. 付款单/付款退款单是独立单据，不在发票上直接记录。
4. **单票勾稽**是一个明确的业务动作（发票与入库单对账），本系统无此概念。

### 4.2 销售流程

同样两条并行路径，外加委托代销：

```text
路径 A：先开发票，后发货
  销售预测单 → 销售报价单 → 销售订单 → 销售发票(出库) → 收款单

路径 B：先发货，后开发票
  销售预测单 → 销售报价单 → 销售订单 → 发货通知单 → 拣验货单
                                          → 销售出库单 → 销售发票(出库) → 收款单

退货：销售换货申请单 / 销售退货申请单 → 销售退货单 → 销售发票(退货) → 收款退款单

委托代销：委托代销 → 委托代销结算 → 委托代销退货 → 委托结算退货
```

**关键发现**：
1. 有 `销售预测单`（本系统无），它是 MRP 的输入源之一。
2. 有 `发货通知单`（本系统无），销售订单与出库单之间的指令层。
3. **换货和退货是两个不同申请单**，本系统只有退货。
4. 委托代销是完整的第三方业务链（本系统无）。

### 4.3 库存流程

金蝶的库存流程按"入库业务 / 出库业务 / 期末处理"三段组织：

```text
入库业务：采购入库单、销售退货单、其他入库单、生产退料单、调拨入库单、
         盘盈单、委托代销退货、产品入库单
出库业务：调拨出库单、销售出库单、盘亏单、委托代销、生产领料单、
         采购退货单、其他出库单、产品退库单
期末处理：盘点单 → 移仓单 → 组装单 → 拆卸单 → 业务结账 → 出库成本核算 → 期末成本核算 → 期末结账
```

**关键发现**：
1. **调拨拆成入库单和出库单两张**，本系统是单张 `TRANSFER`。
2. **盘盈单和盘亏单是独立单据**，不是盘点单的一个状态。本系统 `STOCK_CHECK` 是单张。
3. 有 `组装单` 和 `拆卸单`（本系统无），这是把散件组装成成品或反向拆解的库存操作。
4. **期末成本核算和期末结账是库存流程的终点**，不是财务模块的事。成本在库存侧算完再传给财务。

### 4.4 应收应付流程

这是金蝶财务的精华，单据按"业务来源 → 应收/应付 → 收款/付款"三层组织：

```text
应付侧来源：采购订单、委外加工单、委外加工费、受托结算单、采购发票、
           其他支出单、预付款、采购费用、采购订金、预付加工费
应付科目：应付账款、其他应付款

应收侧来源：销售订单、受托加工订单、受托加工发票、零售结存单、
           委托代销结算、销售发票、其他收入单、预收款、销售费用、
           销售订金、预收加工费
应收科目：应收账款、其他应收款

收付动作：付款单、收款单、核销单、资金转账
```

**关键发现**：
1. **应收应付不是从发票单向生成的**，来源有 10+ 种业务单据。这意味着"业务单据 → 应收应付"是一个配置化的映射表，不是硬编码。
2. **核销单**是独立单据（本系统无），用于应收与收款、应付与付款的勾稽。
3. **预收款/预付款**是独立单据，不是发票的负数。
4. 委外、受托加工都有各自的应收应付路径。

### 4.5 质检流程

```text
采购质检：采购订单 → 收料通知单 → 质检单 → 拣验货单 → 采购入库单
                                                    ↓
                                              退料通知单

委外质检：委外加工单 → 收料通知单 → 质检单 → 委外产品入库单 → 退料通知单
生产质检：生产任务单 → 质检单 → 产品入库单

质检结果处理：合格、让步接收、报废品直接入库/直接拣验
              反写合格、不良情况
              判退的不良品退回供应商
              返修的不良品继续生产
```

**关键发现**：
1. **质检单是独立单据**，不是"报检单+检验单"两段式。本系统用了 4 种报检单 + 2 种检验单共 6 个面板，金蝶只有 1 张 `质检单`。
2. 质检结果有三种：合格、让步接收、报废。本系统只有合格/不合格二元。
3. **反写机制**：质检单把合格数量和不良情况反写到来源单据（收料通知单、委外加工单、生产任务单），而不是新建下游单据。
4. 质检单挂在不同来源单据上，就自动变成采购质检/委外质检/生产质检，不需要三套面板。

## 5. 对本系统蓝图的修正建议

### 5.1 必须修正的判断

| 原判断 | 实测结论 | 影响 |
|---|---|---|
| QMS 应独立成一级模块 | 金蝶把质检放在进销存内，但本系统独立更清晰 | 保持独立，但强制质检结果回写库存与应付 |
| 采购链 `到货单 → 检验单 → 采购入库单` | 金蝶是 `收料通知单 → 质检单 → 拣验货单 → 采购入库单` | 补 `收料通知单`、`拣验货单` 两张单据 |
| 质检用 4 报检 + 2 检验 | 金蝶用 1 张质检单挂多来源 | 建议合并为 1 张 `质检单`，用来源类型区分 |
| 调拨单一张搞定 | 金蝶拆入库单/出库单 | 调拨拆两单，便于分别核算 |
| 盘点单一张搞定 | 金蝶拆盘盈单/盘亏单 | 盘点结果分单，符合会计处理 |
| 成本核算在财务 | 金蝶在库存流程末尾 | 成本核算归 WMS，结果传 ERP |

### 5.2 本系统缺失的单据清单

按优先级：

| 优先 | 单据 | 所属 | 理由 |
|---|---|---|---|
| P0 | 收料通知单 | WMS | 采购收货的指令层，缺它则采购订单直接跳到入库 |
| P0 | 质检单（统一） | QMS | 替代现有 6 个面板，减少重复 |
| P0 | 核销单 | ERP | 应收应付闭环的必需动作 |
| P1 | 发货通知单 | WMS | 销售订单到出库的指令层 |
| P1 | 盘盈单 / 盘亏单 | WMS | 替代单一盘点单 |
| P1 | 调拨入库单 / 调拨出库单 | WMS | 替代单一调拨单 |
| P1 | 预收款单 / 预付款单 | ERP | 资金流前置 |
| P2 | 组装单 / 拆卸单 | WMS | 散件与成品的转换 |
| P2 | 销售预测单 | ERP | MRP 输入 |
| P2 | 销售换货申请单 | ERP | 区别于退货 |
| P3 | 委托代销全链 | ERP | 第三方业务 |

### 5.3 本系统结构上的优势（应保持）

1. **配置驱动的面板**：金蝶的每个单据是独立开发的页面，本系统用 `panel_config` 统一驱动。新增单据的成本远低于金蝶。
2. **面板编码即业务语义**：本系统的 `PURCHASE_IN`、`SALE_OUT` 等编码直接对应单据类型，金蝶用中文名 + 内部 ID。对二次开发更友好。
3. **质量模块独立**：虽然金蝶把质检塞进进销存，但独立模块在权限和职责上更清晰。

## 6. 七个业务模块的完整菜单（实测）

以下菜单直接从系统导航展开抓取，是金蝶功能的完整清单。

### 6.1 采购管理

```text
采购单据：采购申请、采购订单、采购发票、采购入库、采购退货、质检单、退料通知单
采购功能：以销定购、智能补货、采购询比价 - beta、采购对等核销
采购报表：采购明细表、采购汇总表、采购发票明细表、采购发票汇总表、
         采购订单汇总表、采购订单跟踪表、采购付款一览表、采购日报、
         采购价格分析表、期末暂估余额表、质量分析表
```

**关键发现**：
1. **以销定购**是一个独立功能——销售订单直接驱动采购，这是本系统缺的"销售驱动采购"路径。
2. **智能补货**是安全库存驱动的自动补货建议。
3. **采购询比价**（beta）说明金蝶在补供应商比价环节。
4. **采购对等核销**：采购退货与采购发票的核销，本系统无此概念。
5. **期末暂估余额表**：货到票未到的暂估应付，这是财务月结的关键。

### 6.2 销售管理

```text
销售单据：销售预测单、销售报价、销售订单、销售订单变更单、销售出库、
         销售退货、销售退货申请、销售换货申请、销售发票、销售对等核销
委托代销：委托代销、委托代销结算、委托代销退货、委托结算退货
销售报表：销售明细表、销售汇总表、销售发票明细表、销售发票汇总表、
         委托商品跟踪表、销售订单跟踪表、销售订单汇总表、采购销售汇总表、
         销售排行表、销售收款一览表、销售利润表、销售价格分析表、
         发出商品明细表、发出商品汇总表、销售订单全流程跟踪表
```

**关键发现**：
1. **销售订单变更单**是独立单据——订单变更不改原单，留审计链。本系统无此设计。
2. **发出商品明细表/汇总表**：先发货未开票的商品单独核算，这是收入确认的关键，本系统无。
3. **销售利润表**：销售收入 - 成本 - 费用，说明金蝶在销售模块就能出毛利。
4. **销售订单全流程跟踪表**：一张表串起订单→出库→发票→收款，这是本系统最该学的。

### 6.3 库存管理

```text
仓存单据：其他入库、其他出库、移仓单、调拨出库、调拨入库、盘点单、
         盘盈单、盘亏单、形态转换单、生产领料单、生产退料单、
         产品入库单、产品退库单
拣验货：  仓存拣验货、拣验货单、拣验工作台、拣验汇总表、拣验货配置
报表：    调拨差异处理表
```

**关键发现**：
1. **形态转换单**：本系统无。物料形态变化（如铝锭→铝棒）在同一物料上做数量转换。
2. **拣验货是一个子系统**，有工作台、汇总表、配置三件套，不是一张单据。本系统 `PICK_ORDER` 只有一张单据。
3. **调拨差异处理表**：调拨在途差异的处理，本系统无。
4. 移仓单（同仓内货位移动）与调拨单（跨仓）是两个不同单据。本系统只有 `TRANSFER` 一个。

### 6.4 应收应付

```text
应收单据：收款、收款退款、预收款、预收退款、其他收入、其他收入退款、
         其他往来单、应收票据
应付单据：付款、付款退款、预付款、预付退款、其他支出、其他支出退款、
         付款申请单、资金转账单
核销：    自动核销方案、自动核销执行日志、手动核销、智能收款、智能付款
对账：    客户对账单、供应商对账单、历史客户对账单、历史供应商对账单、
         客商匹配对账单、合并收款记录、对账函模板、历史对账函、待收款清单
计提：    坏账准备计提、坏账损失、现金银行流水、财务账龄分析表
```

**关键发现**：
1. **应收应付是一个完整子系统，有 34 个功能点**。本系统完全空白。
2. **核销有自动方案 + 手动核销两条路径**，自动核销还有执行日志。
3. **对账函模板**：给客户/供应商发对账函是标准流程，本系统无。
4. **坏账准备计提**：按账龄计提坏账，这是会计准则要求。
5. **付款申请单**是独立单据，付款要审批，本系统无。

### 6.5 生产管理（含完整 MRP）

```text
生产数据：BOM维护、BOM批量修改、BOM正向查询、BOM子件反查、BOM对比、BOM成本查询
计划：    物料需求建议、计划订单、物料需求运算结果查询、齐套分析、
         物料供需明细表、物料供需汇总表、物控工作台、计划工作台
生产单据：生产任务单、生产任务变更单、领料申请单、生产领料单、生产退料单、
         材料报废单、生产汇报单、产品入库单、产品退库单、质检单
其他：    生产发料工作台、工程变更单、模拟报价、班组
```

**关键发现**：
1. **这是一套完整的 MRP II**：物料需求建议 → 计划订单 → 生产任务单，配齐套分析、供需明细、物控工作台。
2. **工程变更单在生产管理里，不在独立的 PDM 模块**。金蝶没有独立 PDM，BOM 变更直接走生产管理的工程变更单。
3. **BOM 有六种操作**：维护、批量修改、正向查询、子件反查、对比、成本查询。本系统只有 `BOM`、`BOM_FWD`、`BOM_REV` 三个。
4. **模拟报价**：按 BOM 成本模拟报价，本系统无。

### 6.6 委外管理

```text
委外单据：委外加工单、委外发料单、委外退料单、材料报废单、质检单、

```

**关键发现**：委外是完整的独立子系统，有发料工作台和足缺料分析。本系统 `OUTSOURCE_*` 四个面板远不够。

### 6.7 账务处理（业财一体化的核心）

```text
凭证：    录凭证、生成凭证、定时生成凭证、查凭证、凭证附件
配置：    科目关联设置、业务凭证模板、外部单据列表、智能核算中心、AI记账中心
账表：    明细账、科目余额表、总分类账、凭证汇总表、费用明细表、多栏账、
         核算项目多栏账、核算项目明细账、核算项目明细表、核算项目组合表、
         核算项目综合表、核算项目余额表、数量金额明细账、数量金额总账
分析：    财务账龄分析表、调汇历史信息表
```

**关键发现（最重要）**：
1. **业务凭证模板 + 科目关联设置是业财一体化的两个配置点**。业务单据按模板生成凭证，模板里的科目按关联设置取数。
2. **定时生成凭证**：凭证可以批量、定时生成，不是逐单点击。
3. **外部单据列表**：非系统产生的单据也能进凭证。
4. **核算项目**是一套独立的维度体系（12 个账表围绕它），支持按项目、部门、客户等多维度核算。
5. **调汇历史信息表**：外币业务的汇兑损益处理。

## 7. 对五合一蓝图的修正结论

### 7.1 关键认知修正

| 原蓝图判断 | 金蝶实测 | 修正 |
|---|---|---|
| PDM 是独立系统，前移到主数据上游 | 金蝶没有独立 PDM，BOM 和工程变更单都在生产管理里 | PDM 可以保留为独立模块，但 BOM 维护/变更必须与生产管理共用同一套数据 |
| QMS 独立一级模块 | 质检单挂在各业务模块内（采购/生产/委外都有质检单入口） | 保留独立 QMS，但质检单要能从三个业务模块发起 |
| 财务需要建总账、凭证、应收应付 | 金蝶的财务有 34 个应收应付功能 + 24 个账务处理功能 | 一期只能做最小闭环，完整财务是长期工程 |
| MRP 是"计划中枢" | 金蝶的 MRP 有 8 个功能点（需求建议、计划订单、齐套、供需、物控台、计划台） | MRP 单独成期，工作量远超预估 |
| WMS 缺作业层 | 金蝶的拣验货本身就是一个子系统（5 个功能点） | WMS 作业层要按子系统设计，不是加几张单据 |
