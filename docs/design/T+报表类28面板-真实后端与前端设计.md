## 1. 真实 T+ 页面结论

T+ 报表不是单据表单页。实测报表页具有以下共同结构：

- 顶部工具栏：查询、打印、导出、发送邮件、刷新、退出。
- 工具栏下面是查询区；日期型查询通常成开始日期/结束日期或期间控件，仓库、存货、客户、供应商、生产车间等是参照或下拉条件。
- 主体是只读网格，数量、单价、金额和比例列右对齐；表尾有合计行和分页。
- 收发存汇总表和库存台账使用分组表头，不应退化成一行平铺文本。
- 报表不存在新增、审核、删除、单据翻页和明细维护；双击报表行不打开单据表单。

直接拼接 T+ 单据 URL 会被演示站按当前账套/菜单重定向，因此入口判断以真实抓取资料和 T+ 门户菜单为准，不把一次 URL 重定向误判为报表缺失。

## 3. 前端页面设计

### 3.1 统一工作区

`frontend/src/core/views/PanelxList.vue` 根据 `metadata.report=true` 进入报表模式：

1. 顶部灰色工具条保留查询、打印、导出、发送邮件、刷新、退出六组 T+ 操作。
2. 查询区按配置动态渲染，日期字段使用日期控件，下拉字段使用可筛选下拉框，普通字段使用可清空文本框；仓库、存货、客户、供应商和人员字段使用 `RefPickDialog` 从 `WH`、`INV`、`PARTNER`、`EMP` 基础档案加载真实参照数据。
3. 标题行显示报表名称和当前期间；右侧显示总行数、当前页/总页和首页/上一页/下一页/末页图标操作。
4. 主表显示当前分页全部报表行，不使用单据列表的“当前单据 + 明细联动”模式。
5. 表格固定序号列，数值列右对齐，超长列显示省略提示，宽表支持横向滚动。
6. 表尾使用 Element Plus summary 行；导出生成 UTF-8 BOM CSV，打印使用浏览器打印样式隐藏查询工具区。
7. 报表不显示单据底部备注、制单人、审核人和明细维护操作。

### 3.2 分组表头

`STOCK_SUMMARY` 的列组为：

- 期初结存：期初数量、期初平均单价、期初金额
- 本期入库：本期入库数量、入库平均单价、本期入库金额
- 本期出库：本期出库数量、出库平均单价、本期出库金额
- 期末结存：期末结存数量、期末平均单价、期末结存金额

`STOCK_LEDGER` 的列组为：

- 收入：收入数量、收入单价、收入金额
- 发出：发出数量、发出单价、发出金额
- 结存：结存数量、结存平均单价、结存金额

其他 26 个面板使用单级表头，但列顺序与真实 T+ 报表资料和菜单名称保持一致。

## 4. 后端实现

### 4.1 配置

`ReportPanelRegistry` 在 Spring Boot 启动时幂等同步 28 条 `panel_config`：

- `metadata.report=true`，分类为“报表”。
- `panelPageDto.tablePages[0].queryFields` 定义查询区。
- `gridTabs[0].columns` 定义真实 T+ 列顺序。
- `gridTabs[0].columnGroups` 定义库存汇总/库存台账的多级表头。
- `buttonGroups` 只保留报表可用操作，不向报表暴露新增、删除、审核。
- 参照查询字段使用 `dataType=参照`、`refPanel`、`refField`、`filter` 和 `refColumns` 描述真实基础档案来源；客户/供应商均包含“性质=两者”的往来单位。

因此新环境只要正常启动应用即可补齐报表配置；当前运行库已由 53 条面板配置增加到 81 条，其中报表 28 条。

### 4.2 查询口径

`ReportQueryService` 从现有 `form_data` 读取业务单据和明细，不创建报表专用假数据：

- 入库/出库明细：展平 `PURCHASE_IN`、`FINISH_IN`、`OTHER_IN`、`SALE_OUT`、`MATERIAL_OUT`、`OTHER_OUT` 明细。
- 入库/出库统计：按报表对应维度聚合数量、金额、成本和平均单价。
- 库存状况：期初余额 + 有效入库 - 有效出库，按仓库/存货计算现存量和结存金额。
- 收发存汇总：按查询期间计算期初、本期入库、本期出库和期末结存。
- 库存台账：按日期排序，逐笔滚动计算结存数量、结存金额和平均单价。
- 销售订单执行：关联销售订单、销售出库单和生产加工单，计算出库执行率和生产进度。
- 生产/工序/工资：分别从生产加工单产品、加工工序和工序汇报单聚合。
- 返修报表：仅显示存在待返修数量或返修状态的工序行；当前种子数据没有待返修数量时显示 0 行是正常结果。

所有报表统一支持 `condition`、`keyword`、`pageNo`、`pageSize`，返回 `{ totalSize, list }`，与现有 PanelX 列表 API 契约一致。
