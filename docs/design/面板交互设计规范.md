# 轻MES 面板交互设计规范（点击填写 / 弹窗 / 选单）

> 2026-08-14 定稿。本规范定义轻MES 所有单据面板（Panelx 体系）的交互行为标准，
> 后续新增设计面板（库存报表/账表/其他模块）一律沿用本规范，不再各自实现。

## 1. 面板形态总览

| 形态 | 路由 | 组件 | 用途 |
|---|---|---|---|
| 单据列表 | `/panelx/list/:panelCode` | PanelxList.vue | 查询区 + 工具栏 + 明细/汇总双网格 |
| 单据表单 | `/panelx/form/:panelCode` | PanelxForm.vue | 工具栏 + 表头 + 明细子页签 + 表尾 |
| 报表（只读） | 待定（报表页） | （后续） | 查询条件框 + 报表网格 + 导出 |
| 账表（只读） | 待定（账表页） | （后续） | 同上 |

面板配置统一由 `frontend/src/panelx/engine.js` 提供（mock 模式），
`getPanelConfig / getNewFormPermMatrix / getFormDescriptor / queryFormDataList / callButton` 为引擎接口。

## 2. 点击填写（表单交互）标准

### 2.1 表头字段
- 布局：3 列网格（`.fields`），字段按配置顺序排列
- 字段类型映射（`dataType`）：
  - `文本` → el-input
  - `小数/整数` → el-input-number（无步进按钮）
  - `下拉框` → el-select（filterable + allow-create + clearable）
  - `日期` → el-date-picker（YYYY-MM-DD）
  - `是否` → el-switch
  - `图片` → el-image（无图显示"图"占位）
- 必填：label 后红色 `*`（`isRequired`），保存前校验（`validate()`）
- 自动编码字段（`autoCode`）：新增时引擎预填（如 RK-2026-08-0001），表单内**只读**
  （仅当表头含「是否手工修改单据编码」勾选时草稿可改——T+ 语义）
- 只读规则：编辑态（`code` 存在）且状态非草稿时全部禁用

### 2.2 表体明细
- 结构：`detail.tabs[]`，每 tab 一个明细网格
- 子页签：每个明细 tab 内固定「明细 / 汇总」双子页签
  - 明细：el-table，可增行/删行（编辑态）
  - 汇总：`summaryItems` 配置的合计项表格
- 列类型：下拉框/是否/图片/小数/文本（与表头一致）
- 计算链：`calc` 配置（如 `金额 = 数量 × 单价`、`含税金额 = 数量 × 含税单价`），
  输入变化实时重算（`applyCalc`，支持四则运算表达式）
- 合计行：数值列底部合计（`summarize`）
- 子表（expand）：`subTable` 配置，展开行维护（如工序材料）

### 2.3 点击填写交互细节
- 输入框统一 `@keyup.enter` 不提交（表单内回车不触发意外保存）
- 明细行删除：编辑态行尾删除图标（红色）
- 选择类字段值变更后立即触发计算链与合计刷新
- 文本超长列 `show-overflow-tooltip`（列表页）

## 3. 弹窗标准

### 3.1 消息反馈
| 场景 | 组件 | 样式 |
|---|---|---|
| 操作成功 | `ElMessage.success('「X」执行成功')` | 顶部绿色 |
| 校验失败 | `ElMessage.warning(msg)` | 顶部黄色 |
| 未实现功能 | `ElMessage.info('演示环境暂未实现「X」，界面与 T+ 保持一致')` | 顶部蓝色 |
| 接口错误 | `ElMessage.error(engine.errMsg(e))` | 顶部红色 |
| 危险确认 | `ElMessageBox.confirm(...)` | 居中确认框 |

### 3.2 确认弹窗
- 删除单据：`确认删除单据 {单据编号}？`（type=warning）
- 新增切换（未保存草稿）：`当前单据尚未保存，切换新增将丢弃修改，是否继续？`
- 未实现按钮：一律 info 提示，不阻塞页面

### 3.3 拉式选单弹窗（配置驱动，核心交互）
- 入口：工具栏「选单」组（表单页）或列表页「选单」按钮
- 前提：面板配置存在 `selectConfig`；无配置则 info 提示未实现
- 弹窗结构（PanelxForm.vue 统一实现）：
  - 标题：`selectConfig.title`
  - 提示：`selectConfig.tip`
  - 网格列：`selectConfig.columns`（动态渲染）
  - 多选：checkbox 列，底部「确定生单（N 行）」
- 数据来源：`engine.queryFormDataList({ panelCode: selectConfig.source, condition: { 单据状态: '已审核' } })`
  （对齐 T+ 选单前提：已审核且未中止）
- 确认带入：
  - 表头：`selectConfig.headerMap[]`（from 来源字段 → to 当前表头字段；fixed 为固定值）
  - 明细：`selectConfig.detailMap[]`（from → to），写入第一个明细 tab
  - 来源单号：`selectConfig.sourceNoField`（未配置时回填「来源单据」）
- 带入后：`applyCalc()` 重算 + success 提示行数

### 3.4 配置示例
```js
// 销售出库单 → 选销售订单（engine.js SALE_OUT）
selectConfig: {
  source: 'SO_ORDER',
  title: '选销售订单',
  tip: '仅显示已审核且未中止的销售订单，选中后明细带入销售出库单（对齐 T+ 选单前提）',
  columns: ['单据编号', '单据日期', '客户', '业务员', '预计交货日期', '存货名称', '数量', '销售单位'],
  headerMap: [
    { from: '客户', to: '客户' },
    { from: '结算客户', to: '结算客户' },
  ],
  detailMap: [
    { from: '存货名称', to: '存货名称' },
    { from: '存货编码', to: '存货编码' },
    { from: '销售单位', to: '计量单位' },
    { from: '数量', to: '数量' },
  ],
}
```

## 4. 工具栏标准

- 分组渲染：`buttonGroups[]`（name + actions），主按钮 + 下拉（多动作时）
- 快捷键提示：`SHORTCUTS`（Alt+S 保存 / Alt+\\ 保存新增 / Alt+G 保存打印 / Alt+P 直接打印 / Alt+Z 放弃…）
- 按钮可用性（`isDisabled`）按单据状态：
  - 保存/保存新增/保存为草稿：仅草稿可编辑
  - 删除：仅草稿
  - 审核：草稿→已审核；弃审：已审核→草稿
  - 中止执行/整单中止：已审核/生产中/已完工
  - 草稿（恢复）：已中止
- 未实现按钮：engine `UNIMPLEMENTED` 集合，点击 info 提示（界面照 T+ 展示）

## 5. 列表页标准

- 查询区：`queryFields` 配置驱动，3 列网格，查询/重置按钮
- 网格：明细/汇总双子页签；右键菜单（定位/复制到剪贴板/另存为EXCEL模板/批量修改/…/更多）
- 行双击/操作列「查看」→ 表单页
- 行内新增（`新` 图标）→ 行内编辑保存
- 分页：10/20/50 条

## 6. 新增面板接入清单（后续所有设计面板沿用）

1. `engine.js`：新增面板配置（复用 `invPanel` 工厂或同构对象），注册进 `panelOf` 注册表；
   如需选单补 `selectConfig`；如需推式生单在 `callButton` 加分支
2. `engine.js`：演示数据加入对应 `*_SEED`（或独立数组），`flattenFor/nextNoFor` 注册
3. `menus.js`：菜单挂 `panelCode`（path 形如 `/panelx/list/XXX`）
4. 报表/账表类：沿用查询框 + 只读网格 + 打印/导出/发送邮件工具栏（T+ `/v2/bap/report` 形态）
5. 交互零新增：点击填写/弹窗/选单全部由 PanelxList/PanelxForm 通用组件承载

## 7. 与真实 T+ 的对齐要点

- 选单前提：仅已审核且未中止的来源单据（实测 SA03 语义）
- 自动编号：单据编号 = 前缀-yyyy-MM-dd+2位当日序号（如 MO-2026-08-1701），规则见 §9 单据编号标准
- 表尾：制单人/审核人/审核日期/审核时间/打印次数/修改人/变更人/变更日期（配置或组件默认）
- 未实现项提示文案统一：「演示环境暂未实现「X」，界面与 T+ 保持一致」

## 8. 审批流标准（2026-08-17 定稿）

> 生产加工单等单据面板走「提交审批 → 审批中 → 审批通过/审批驳回」的人工审批流，全程留痕。
> 原「审核」直接过审按钮已由审批流取代（工具栏配置见 §8.4）。

### 8.1 状态机

```
草稿 --提交审批--> 审批中 --审批通过--> 已审核
                  审批中 --审批驳回--> 草稿（修改后可重新提交审批）
已审核 --弃审--> 草稿
```

硬性规则：
- **不允许重复审核**：非草稿状态（已审核/生产中/已完工…）禁止再次提交审批——前端前置校验 + 后端 409 双拦截
- **不允许补填审批意见**：已审核单据点「审核/提交审批」不弹意见框（前端拦截），后端同样拒绝
- **审核人 = 当前登录用户**（JWT → SecurityContext 取），禁止硬编码 admin

### 8.2 数据契约

- 单据状态新增：**审批中**
- 表头 JSON 新增键：`审批状态`（审批中/已通过/已驳回）、`提交人`、`提交时间`
- 审批通过时写：`审核人`（=当前登录人）、`审核时间`、`审核意见`（选填）
- 驳回时写：`审批状态=已驳回`，清除 `提交人/提交时间`
- 弃审时清除：`审核人/审核时间/审核意见`（含 form_data 列 audit_by/audit_time，MyBatis-Plus 需用 LambdaUpdateWrapper.set(null) 显式置空）

审批记录表 `form_approval`（全留痕）：

| 字段 | 说明 |
|---|---|
| panel_code / form_no | 面板码 / 单据编号 |
| action | SUBMIT / APPROVE / REJECT / UNAUDIT |
| result | PENDING / APPROVED / REJECTED |
| node_no | 审批节点（预留多级） |
| operator | 操作人（当前登录用户） |
| opinion | 意见（驳回必填） |
| create_time | 操作时间 |

### 8.3 接口

- `POST /api/px/callButton`，buttonName ∈ {提交审批, 审批通过, 审批驳回, 审批情况}
  - 入参 formData：`{编号, 审批意见?}`
  - 状态校验：提交审批=仅草稿；审批通过=仅审批中；审批驳回=仅审批中且**意见必填**（空意见 409）
- `GET /api/px/getApprovalHistory?panelCode=&code=` → 该单全部审批记录（按时间升序）

### 8.4 工具栏配置

审核组 actions（10 个单据面板已统一）：

```js
{ name: '审核', actions: ['提交审批', '审批通过', '审批驳回', '审批情况', '弃审'] }
```

按钮可用性（isDisabled 按单据状态）：

| 按钮 | 可用状态 |
|---|---|
| 提交审批 | 仅草稿 |
| 审批通过 | 仅审批中 |
| 审批驳回 | 仅审批中 |
| 审批情况 | 任意状态 |
| 弃审 | 仅已审核 |

### 8.5 前端交互

- **提交审批 / 审批通过**：ElMessageBox.prompt 确认框（显示单号 + 当前状态）+ 意见输入（选填）
- **审批驳回**：prompt 意见（**必填**，前端 inputValidator + 后端二次校验）
- **审批情况**：ApprovalHistoryDialog 弹窗展示记录（动作标签：SUBMIT=提交审批 / APPROVE=审批通过 / REJECT=审批驳回；结果：PENDING=审批中 / APPROVED=已通过 / REJECTED=已驳回；含操作人/意见/时间）
- 非对应状态点击 → warning 提示且**不弹框**（前端前置校验，避免"补填意见"路径）

### 8.6 多级审批扩展（预留）

`form_approval.node_no` 已预留。将来多级审批（部门→经理→总经理）按 node_no 扩展状态机与记录即可，前端弹窗天然支持多节点展示。

## 9. 单据编号标准（2026-08-17 定稿）

> 覆盖所有单据类面板（生产加工单 MO-…、销售订单 SO-…），新增单据面板一律沿用。

### 9.1 格式

```
前缀 - yyyy-MM-dd + 2位当日序号
```

- 示例：生产加工单 `MO-2026-08-1701`、销售订单 `SO-2026-08-1701`
- 前缀按面板：生产加工单 `MO-`、销售订单 `SO-`（其他单据面板按需扩展，如 `RK-`/`CP-`…）
- 同一天按创建顺序 `01、02、03…`；**每天从 01 重新排**；年份+日期在号内，跨天不会撞号

### 9.2 单据号不允许重复（三重保障）

| 层 | 措施 |
|---|---|
| 1. 生成防撞 | `generateFormNo` 用**精确查重循环**：按 `前缀+yyyy-MM-dd` 生成候选号后，`eq` 精确查询该号是否已存在，存在则序号 +1 直到空号。**禁止用 `like` 模糊计数**（历史事故：新旧格式混存时计数错乱导致撞号） |
| 2. 数据库兜底 | `form_data` 唯一索引 `uk_panel_formno (panel_code, form_no)`——任何途径（并发/手改）都插不进重复号 |
| 3. 回填一致 | 单据级行 `form_no` 与表头 JSON 的编号字段保持一致（生产加工单=`锭号`、销售订单=`单据编号`） |

### 9.3 生成时机

- 新增单据（`callButton` 新增流程/保存）→ 后端 `generateFormNo` 自动生成并预填表头
- 推式生单（销售订单 → 生成生产加工单）→ `createMoFromSo` 同样走 `generateFormNo`
- 前端**不做**编号生成，只读展示；autoCode 字段仅勾选「是否手工修改单据编码」时草稿可改

### 9.4 联动规范

- 列表按**单据级行**返回（一单一行），编号不重复展示（见 页面开发规范.md 数据契约）
- 单据重排号时，审批记录 `form_approval.form_no` 需同步更新

## 10. 单据流转（生单 / 选单）标准（2026-08-17 定稿）

> 工厂正常生产环节：**销售订单 →（生成）生产加工单 →（生成）工序汇报单 / 产成品入库单**。
> 本文档以「销售订单 → 生产加工单」为主示例（已实测验证），其余链路沿用同一套配置契约。

### 10.1 流转链路总览

```
销售订单(SO_ORDER) --选单/生单--> 生产加工单(MANU_ORDER) --选单/生单--> 产成品入库单(FINISH_IN)
                                                    |----选单(detailRows)--> 工序汇报单(PROCESS_REPORT)
```

- **拉式选单（pull）**：目标单（生产加工单）表单点「选单」→ 弹窗列出来源单（销售订单）→ 勾选 → 表头/明细按映射带出 → 保存生成
- **推式生单（push）**：来源单（销售订单）点「生单 ▾ → 生成生产加工单」→ 后端直接创建目标单 → 前端 `gotoPanel` 跳转

### 10.2 前提规则

- 来源单必须 **已审核**（对齐 T+ 选单前提：已审核且未中止）——选单弹窗查询条件固定 `{单据状态:'已审核'}`
- 目标单生成后为**草稿**，可修改后走审批流（§8）

### 10.3 配置契约（selectConfig，DB panel_config 与 MOCK_CONFIG 保持一致）

```js
selectConfig: {
  source: 'SO_ORDER',              // 来源面板码
  title: '选销售订单（生单）',       // 弹窗标题
  tip: '仅显示已审核且未中止的销售订单…',
  columns: [...],                  // 弹窗网格列（字段名数组）
  headerMap: [{ from, to }...],    // 来源表头 → 目标表头（fixed 可写固定值）
  detailMap: [{ from, to }...],    // 来源明细行 → 目标第一个明细 tab
  sourceNoField: 'xxx',            // 可选：来源单号回填目标字段（默认写「来源单据」）
  detailRows: (row) => [...],      // 可选：单据粒度选单时对每张选中单提取明细（如工序汇报单选加工单取工序明细）
}
```

### 10.4 字段映射表（销售订单 → 生产加工单，实测验证）

**表头 headerMap：**

| from（销售订单） | to（生产加工单） |
|---|---|
| 单据编号 | 销售订单号 |
| 单据日期 | 合同号 |
| 客户 | 客户 |
| 客户编码 | 客户编码 |
| 结算客户 | 生产订单客户 |
| 业务员 | 负责人 |
| 预计交货日期 | 预完工日 |

**明细 detailMap（→ 产成品明细 products）：**

| from（销售订单 items） | to（生产加工单 products） |
|---|---|
| 存货编码 | 产品编码 |
| 存货名称 | 产品名称 |
| 规格型号 | 规格型号 |
| 销售单位 | 生产单位 |
| 数量 | 数量 |
| 现存量 | 现存量 |

### 10.5 后端实现位置

- **推式生单**：`PxService.callButton` 增加按钮分支（如「生成生产加工单」→ `createMoFromSo`），生成新单后返回 `{gotoPanel:'MANU_ORDER', 编号}`，前端跳转目标单表单
- **选单数据源**：选单弹窗调 `queryFormDataList({panelCode: source, condition:{单据状态:'已审核'}})`——返回**单据级行**（含 detail），前端展平为明细行勾选
- 新目标单编号走 §9 单据编号标准（`generateFormNo`）

### 10.6 前端实现位置

- 选单弹窗：`PanelxForm.vue` `openSelectDialog / confirmSelect`（headerMap/detailMap 带入 + `applyCalc` 重算）
- 选单入口：列表/表单工具栏「选单」分支（`selectConfig` 存在才可用）
- 生单跳转：列表/表单 `onButton` 统一处理 `res.gotoPanel` → `router.push(/panelx/form/{gotoPanel}?code=编号)`

### 10.7 新增流转链路 Checklist

1. 目标单配置加 `selectConfig`（或来源单生单组按钮）
2. 后端 `callButton` 加生成分支（复用 `createMoFromSo` 模式：读来源单 → 映射 → `generateFormNo` → 保存 → 返回 gotoPanel）
3. 双向验证：选单带出字段、生单跳转、来源单状态前提
4. 字段映射登记进本规范 §10.4（新增链路时追加映射表）

## 11. BOM 联动标准（2026-08-17 定稿）

> 产成品明细与材料明细通过 **BOM 关系** 关联：BOM 存放于**存货面板（INV）**的档案数据中，
> 生产加工单填产品时自动从存货 BOM 带出材料明细。

### 11.1 BOM 存放（存货面板 INV）

- INV 面板表单增加 **「BOM子件」** 明细子表（detail.tabs[0]，key=bom），每个存货档案维护自己的 BOM（该存货作为父件/产成品时消耗的材料）
- BOM 行字段契约：

| 字段 | 类型 | 说明 |
|---|---|---|
| 材料编码 | 参照（INV，filter 属性=外购） | 材料存货编码 |
| 材料名称 | 文本 | 参照带出 |
| 规格型号 | 文本 | 参照带出 |
| 计量单位 | 下拉框 | 件/kg/套/升 |
| 定额需用数量 | 小数 | 单位产品的材料用量 |
| 损耗率% | 小数 | 备损 |

- 数据存储：INV 档案的 detail_data.bom 数组（form_data.detail_data 列）
- INV 工具栏需含「保存」组（BOM 编辑后可保存）

### 11.2 生产加工单联动（产成品明细 → 材料明细）

- **触发**：产成品明细行「产品编码」变更（@change，仅响应交互，编辑态加载不重复带入）
- **流程**：
  1. engine.queryFormDataList({ panelCode:'INV', condition:{存货编码: code} }) 取该存货档案
  2. 读 row.detail.bom（BOM 材料数组）
  3. 按材料明细字段结构逐行生成材料行：材料编码/名称/规格/单位/定额需用数量/损耗率%
  4. 材料行写「子件BOM = 产品编码」（记录所属关系）
  5. ElMessage.success('已按 BOM 带入 N 行材料（code）')
- **防重复**：bomLoaded Set 记录已带入的产品编码，同一产品不重复带出
- **计算链衔接**：带出的「定额需用数量」直接参与现有 calc（需用数量=定额需用数量×产品数量÷定额生产数量）
- **推式生单带材料（2026-08-17 补）**：销售订单「生成生产加工单」createMoFromSo 按 INV 物品行 _bom 展开生成材料明细（字段结构同上，含「子件BOM = 产品编码」），不再生成空材料；存量单据可用同一逻辑回填（回填脚本按 编号 UPDATE form_data.detail_data.materials）

### 11.3 新增 BOM 联动 Checklist

1. 存货面板配置加 detail.tabs（key=bom）+「保存」按钮组（参考 §11.1 字段契约）
2. 种 BOM 数据：form_data.detail_data = {"bom":[...]}
3. 生产加工单产成品明细行：产品编码下拉 @change → onDetailChange 分发 → loadBomFor（读 INV BOM 带出材料）
4. 验证：选产品 → 材料自动带出 + 子件BOM 标记 + 保存后重开数据保留

## 12. 删除与存货类别单据标准（2026-08-17 定稿）

### 12.1 删除组双动作

工具栏「删除」组固定两个动作（全部单据面板统一）：

```js
{ name: '删除', actions: ['删除', '删除单据'] }
```

| 动作 | 行为 |
|---|---|
| 删除（主按钮） | 进入**勾选删除模式**：表格出现勾选列 → 勾选明细行 → 再点「删除」→ 确认 → 从当前单据明细中移除所选行并保存（按对象引用精确匹配，支持多选；刷新/翻页退出模式） |
| 删除单据（下拉） | 确认框（显示单号 + 不可恢复警示）→ 整张单据删除（deleteForms）→ 刷新 |

### 12.2 存货（INV）类别单据模型

- **固定 5 张类别单据**，每张单据 = 一个物品类别，物品为其明细行：

| 类别 | 单据编号 | 物品编码前缀 |
|---|---|---|
| 产成品 | CP-001 | CP（CP001…） |
| 原材料 | YL-001 | YL（YL001…） |
| 辅助材料 | FZ-001 | FZ（FZ001…） |
| 包装物 | BZ-001 | BZ（BZ001…） |
| 半成品 | BC-001 | BC（BC001…） |

- **不新建第 6 张单据**：存货「新增」→ 选类别 → 打开对应类别单据，物品在该单据明细中增行
- **自动编号**：类别单据内「增行」自动替补存货编码 = 类别前缀 + 当前最大序号 + 1
- **5 张自愈**：打开类别单据前检查是否存在，缺失则按类别前缀自动补建（invNo：前缀-3位序号），再打开——保持固定 5 张
- **类别固定显示**：列表工具栏单据号旁显示类别标签；表单中「类别」编辑态锁定（创建后不可改）
- **档案可编辑**：类别单据状态为 启用/停用，表单 editable 需允许（增行/改字段/保存），与单据草稿同等对待

### 12.3 相关实现位置

- 删除/删除单据/勾选删除：PanelxList.onButton
- 类别选择 + 自动补建：PanelxList.gotoCategory
- 存货自动编号：PxService.invNo（后端）+ PanelxForm/NewVoucherDialog addDetailRow（前端）
- 删除/保存守卫：草稿/启用/停用 均允许

## 13. 产成品→材料 BOM 联动过滤标准（2026-08-17 定稿）

> 生产加工单表单中，点击「产成品明细」某行 → 下方「材料明细」只显示该产品的 BOM 子件。

### 13.1 交互

- 点击产成品明细行：该行高亮（prod-selected）+ 材料明细块头部显示「当前产品：XXX 的 BOM 子件」
- 材料明细联动过滤：只显示 材料编码 ∈ 该产品 BOM 的材料行
- 未选中任何产品时：材料明细显示全部（默认行为）

### 13.2 过滤规则（优先级）

> 实测修正（2026-08-17）：多产成品共用相同材料时（如 CP001/CP002 都耗 YL002+FZ001），
> 仅按「材料编码」过滤会把多个产品的材料行全部保留、无法区分所属 → 一律先按「子件BOM 标记」精确过滤。

1. **按 子件BOM 标记过滤**（首选）：m[子件BOM] === 产品编码（自动带入/回填/推式生单生成的材料行均带此标记）
2. **按产品 BOM 材料编码兜底**：子件BOM 匹配为空（旧手工行无标记）时，点击时实时查该产品存货 BOM（INV 物品 _bom）→ 材料编码 in 集合
3. 两者都无 → 显示全部（与未选中产品时一致，不误判为空）

### 13.3 实现要点

- 只影响**显示**：明细编辑仍操作完整数据，过滤不删行
- 回填/推式生单生成的材料行必须写「子件BOM = 产品编码」——它是联动过滤的首要依据
- 同一材料被多产品共用时（如 YL002 同时是 CP001/CP002 子件），材料行允许重复出现、各带各自子件BOM
- **默认选中第一个产成品**：打开单据即选中 products[0]（材料明细默认只显示其子件，避免整单全显示），点击其他行再切换
- **点击双路径**：@click.capture（捕获阶段，控件格点击不被吞）+ @row-click（普通单元格，拿数据行）→ 统一走 selectProduct(code)
- **新增材料行归属**：材料明细「新增数据」时自动写 子件BOM = 当前选中产品（addDetailRow）
- **列表页（单据流览）同样联动（2026-08-17 补）**：PanelxList 是一屏一单的流览式列表（工具栏 + 单据翻页器 + 产成品/材料明细块），A 区（产成品明细）行点击 → selectProduct → B 区材料明细过滤；默认选中第一行产成品，翻页切单据自动重置选中；过滤规则与表单页一致（子件BOM 优先、材料编码兜底）
- 汇总行（summarize）与网格同步使用过滤后数据
- 行点击：PanelxForm.onTabRowClick（异步读 INV BOM 编码集合）
- 数据：tabData(tab) 统一出口（materials 特殊处理，其余明细原样）
- 高亮：prodRowCls（选中行浅蓝底）

### 13.4 相关规范

- BOM 存放见 §11（存货面板 _bom）
- 产成品明细选产品自动带出材料见 §11.2（loadBomFor）

## 14. 注意细节与常见坑（2026-08-17 定稿）

### 14.1 业务单据的主入口是「列表页（单据流览）」而非表单页

- **PanelxList 是一屏一单的流览式列表**：工具栏 + 单据翻页器（第 1/N 张 ◁ ◀ ▶ ▷）+ 表头字段区 + 明细区块（如产成品明细、材料明细）。菜单点击业务单据（如 生产加工单 MANU_ORDER）进入的就是它（URL 形如 `#/panelx/list/MANU_ORDER`）。
- **PanelxForm 是编辑/查看的单据页**：进入方式为 列表页双击行、生单跳转 gotoPanel、存货类别跳转等（URL 形如 `#/panelx/form/MANU_ORDER?code=...`）。
- **开发交互功能必须同时覆盖两个入口**。本次 BOM 联动先只做了表单页，用户实际在列表页操作 → 出现"点产成品行材料不联动"。实测教训：改动后**先在用户实际使用的入口验证**，并问清用户看到的 URL。
- 联动逻辑在两处保持一致：过滤规则（子件BOM 优先、材料编码兜底）+ 默认选中第一行 + 点击双路径。

### 14.2 产成品→材料联动实现清单（两入口对照）

| 环节 | 表单页 PanelxForm | 列表页 PanelxList（单据流览） |
|---|---|---|
| 过滤出口 | tabData(tab)，materials 特殊处理 | blockData(b)，activeTab(b).key==='materials' 时过滤 |
| 选中函数 | selectProduct(code)：异步读 INV 物品 _bom → 材料编码集合 | 同左（逻辑复制一份） |
| 点击监听 | @click.capture + @row-click → selectProduct | 同左；@row-click 需带块参数 b，仅 A 区（products）生效 |
| 默认选中 | load() 后选中 products[0] | watch(cur) 选中第一行；翻页/切单自动重置 |
| 新增行归属 | 材料「新增数据」自动写 子件BOM=当前产品 | —（列表页只读浏览） |
| 行高亮 | prodRowCls → .prod-selected（浅蓝底） | rowCls({row}, b) → .prod-selected |

### 14.3 数据契约注意

- 材料行必须写「子件BOM = 产品编码」，四处都要带：自动带入 loadBomFor、推式生单 createMoFromSo、存量回填脚本、UI 新增行。否则多产成品共用材料时（CP001/CP002 都用 YL002+FZ001）按材料编码过滤无法区分 → 全显示。
- 点击事件用 **@click.capture 捕获阶段**（el-input/el-select/el-input-number 控件格内的点击不会被 stopPropagation 吞）+ **@row-click 兜底**拿数据行；tr 定位兼容主表与固定列（.el-table__body-wrapper / .el-table__fixed-body-wrapper）。

### 14.4 界面风格（严禁卡通/花哨，2026-08-17 定稿）

- 代码与界面一律**不允许出现卡通图案、表情符号（emoji）、贴纸、动画装饰等非商务元素**——包括页面文案、按钮、弹窗、空状态、错误提示、代码注释、提交信息。
- 保持 T+ 式专业商务风：素色界面、无多余圆角/渐变/阴影堆砌；装饰性元素只允许**功能性标记**（如 必填红星、材料下级 BOM 红 *），禁止纯装饰性视觉元素。
- 文案用词中性专业（如「加载失败」「暂无数据」），不使用拟人化/卖萌措辞。
- 同步出处：《页面开发规范》四、通用规则「界面风格（严禁卡通/花哨）」。

### 14.5 认证与会话（2026-08-18 定稿）

- **JWT 密钥必须随机**：`application.yml` 的 `mes.jwt.secret` 不允许保留默认占位值（防止伪造 token）；改密钥后所有已签发 token 立即失效，用户需重新登录。
- **token 有效期**：`mes.jwt.expire-hours`（默认 24h）；后端对 无 token/伪造/过期 统一返回 **HTTP 403**（非 401）。
- **前端 401/403 都视为认证失效**：`core/request.js` 拦截器对 401/403 执行 `useUserStore().logout()`（**必须同步内存 store + localStorage**，仅 removeItem 会导致路由守卫因内存 token 弹回 dashboard）+ 跳 `#/login`；注意动态 import store 避免循环依赖（request → user → api → request）。

### 14.6 测试注意

- 验证"点行联动"用**真实鼠标事件**（page.mouse 点单元格实际坐标），不要用 tr.click() 直接派发；产品名称/数量列是 el-input/el-input-number，单元格 textContent 为空，按文本找单元格会落空 → 按表头列定位 input 元素或用 elementFromPoint 确认落点。
- 前端改动后浏览器需强刷（Ctrl+F5）；index.html 响应头 no-cache，但已打开的旧页面不会自动重载。

## 15. 材料下级 BOM 标记与展示弹窗（红 *）（2026-08-17 定稿）

> 材料明细中，若某材料存货自身还有下级 BOM（该存货作为父件也有子件），在该材料明细行「材料编码」右上角标红 * 号；点击该材料明细行 → 小弹窗只读展示其下级子件 BOM。

### 15.1 判定与数据

- 判定依据：INV 全量物品行 `_bom` → 构建映射 `subBomMap[存货编码] = 子件数组`；`hasSubBom(code)` = 该编码子件数组非空。
- 映射加载：两入口组件 `onMounted` 后调用 `loadSubBomMap()`（查一次 INV，缓存到 ref，模板同步判断）。

### 15.2 展示

- **红 * 号**：材料编码单元格右上角（`.mat-cell` 相对定位 + `.mat-star` 绝对定位，红色 `#e60000`，title 提示「该材料有下级子件 BOM，点击行查看」）。
- 列表页（PanelxList）：材料编码列加 slot（`c.prop === '材料编码' && activeTab(b).key === 'materials'`）。
- 表单页（PanelxForm）：材料编码是**参照**列（refPanel=INV），在参照分支内包 `.mat-cell` 加 `*`。

### 15.3 点击交互

- 点击**有 `*` 的材料行** → 打开 SubBomDialog 展示其子件 BOM（只读表格：材料编码/名称/规格/单位/定额需用数量/损耗率%）。
- **无 `*` 的材料行点击不弹窗、不拦截**（表单页参照选择照常）。
- 实现要点：
  - 表单页在 `@click.capture` 捕获阶段处理 materials 分支：命中且有下级时 `openSubBom(row)` 并 `e.stopPropagation()` 阻止参照打开；无下级直接放行。
  - 列表页 `onRowClick(row, b)` 与 `onTableClick(b, e)` 的 B 区 materials 分支：`hasSubBom` 才弹窗。
- 弹窗组件：`SubBomDialog.vue`（只读，props: material 材料行 + bom 子件数组，父组件从 subBomMap 取好传入）。
- **多级 BOM**：`*` 仅表示该材料还有下级，点击弹窗展示其直接子件；更深层级暂不递归展开（预留）。

### 15.4 两入口清单

| 环节 | PanelxList（列表页流览） | PanelxForm（表单页） |
|---|---|---|
| 映射加载 | onMounted → loadSubBomMap | onMounted → loadSubBomMap |
| `*` 号 | 材料编码列 slot | 参照分支内包 .mat-cell |
| 行点击 | onRowClick / onTableClick B 区 | onTableClickCapture materials 分支 + stopPropagation |
| 弹窗 | SubBomDialog 挂载 | SubBomDialog 挂载 |

## 16. 角色权限细分标准（2026-08-18 定稿）

> 多账号分权限：角色表 + 面板授权 + 审批权限。操作员只能看被授权的面板菜单/按钮；管理员（admin 角色）为超级权限。

### 16.1 数据模型

- `sys_role`：id / role_code / role_name / is_admin / remark。内置：admin（管理员 is_admin=1）、operator（操作员）。
- `sys_role_panel`：role_id / panel_code / can_approve（唯一键 role_id+panel_code）——角色可见面板及该面板的审批权限。
- `sys_user.role_id`：用户挂角色（一用户一角色；删除角色后其用户 role_id 置空）。
- **部门（2026-08-18 补）**：`sys_dept`（id / parent_id / dept_name / sort）多级部门树（种子：总部→制造部/销售部/仓库部）；`sys_user.dept_id` 用户归属部门。删除保护：有子部门或有用户的部门不可删（后端 400 拒绝）。

### 16.2 权限规则

- **管理员（is_admin=1）**：可见全部面板、拥有全部审批；角色不可修改/删除；组织架构接口仅 admin 可访问（后端 409 拒绝 + 前端路由守卫）。
- **普通角色**：可见面板 = sys_role_panel 的 panel_code；审批权限 = can_approve=1 的面板。
- **公开权限**：提交审批、查看审批历史（审批情况）对所有登录用户开放；审批通过/审批驳回需要该面板的审批权限。
- 菜单过滤：前端 menus.js 的 `filterMenuTree(tree, visiblePanels, isAdmin)`——面板叶子按 visiblePanels 过滤，分组在子项全不可见时隐藏，非面板固定路由（生产看板等）默认可见；`flatMenus(tree)` 需传过滤后的树（勿传全量，否则顶部搜索泄权）。

### 16.3 接口

| 接口 | 说明 |
|---|---|
| GET /api/auth/perms | 当前用户 {isAdmin, roleCode, visiblePanels, approvePanels}（登录返回中也含） |
| GET/POST /api/sys/role/list·save、DELETE /{id} | 角色 CRUD（仅 admin） |
| GET /api/sys/role/{id}/panels | 全部面板（含 hasApproval）+ 已授权（含 canApprove） |
| POST /api/sys/role/{id}/panels | 保存授权 {panels:[{panelCode,canApprove}]}（仅 admin） |
| GET/POST /api/sys/user/list·save | 用户列表/新增（分配角色、分配部门、启停用，仅 admin） |
| GET /api/sys/dept/tree、POST /save、DELETE /{id} | 部门多级树/增改/删除（仅 admin） |

### 16.4 前端实现位置

- user store：roleCode / isAdmin / visiblePanels / approvePanels（登录时从 user 取，`fetchPerms()` 刷新）。
