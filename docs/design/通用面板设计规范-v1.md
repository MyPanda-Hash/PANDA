# 通用面板设计规范 V1

| 属性 | 内容 |
|---|---|
| 文档类型 | 开发规范 |
| 适用场景 | 通用架构与 SDK |
| 维护状态 | 生效 |
| 最后整理 | 2026-08-24 |
| 文档导航 | [文档中心](../README.md) |

> 目标：定义一个可被多个项目、多个数据源和多个前端框架共同消费的面板协议。
> 本规范从 Light MES 的 `PanelxList`、`PanelxForm`、PanelX 网关和 `PxService` 实际能力中提炼，但不绑定 MES 面板码、中文字段名、T+ 样式或审批流程。

## 1. 设计结论

一个通用面板由四个互相独立的部分组成：

```text
PanelDefinition  面板定义：字段、布局、明细、动作、状态
       |
PanelRuntime     运行时：校验、状态、动作编排、插件生命周期
       |
PanelDataSource  数据源：查询、读取、保存、动作、参照、权限
       |
PanelRenderer    渲染器：Vue/React 等 UI 实现
```

依赖方向必须保持为：

```text
Renderer -> Runtime -> Definition
                    -> DataSource interface

Preset/Plugin -> Runtime extension points
Business app -> Preset + Definition + concrete DataSource
```

核心层不得依赖路由、用户 store、具体 UI 库、具体业务面板码或后端 URL。

## 2. 设计原则

1. **定义与数据分离**：配置只描述面板，不直接发 HTTP 请求。
2. **渲染与业务分离**：渲染器只消费标准契约，不判断 `MANU_ORDER`、`INV` 等业务码。
3. **服务端最终裁决**：前端按钮禁用只改善体验，权限、状态迁移和数据校验必须由服务端复核。
4. **配置可序列化**：远程配置必须是 JSON；禁止函数、`eval` 和任意脚本。
5. **稳定标识与展示分离**：字段使用稳定 `key`，界面使用可国际化 `label`。
6. **能力按包分层**：无框架核心、HTTP 适配器、Vue 渲染器、业务 preset 分包发布。
7. **兼容通过适配器完成**：旧项目字段不污染新协议，由 legacy adapter 转换。

## 3. 标准面板定义

正式 Schema：[`schemas/panel-definition.schema.json`](schemas/panel-definition.schema.json)。
完整示例：[`examples/service-order.panel.json`](examples/service-order.panel.json)。

### 3.1 顶层结构

```json
{
  "schemaVersion": "1.0.0",
  "code": "SERVICE_ORDER",
  "version": "1.0.0",
  "title": "服务工单",
  "kind": "document",
  "identity": {},
  "state": {},
  "fields": [],
  "detailSections": [],
  "views": {},
  "actions": [],
  "extensions": {}
}
```

| 属性 | 说明 |
|---|---|
| `schemaVersion` | 通用协议版本；决定运行时如何解析配置 |
| `code` | 跨环境稳定、全局唯一的面板代码 |
| `version` | 当前面板定义版本，使用 SemVer |
| `title` | 默认显示名；多语言项目可由 i18n 覆盖 |
| `kind` | `document` 单据、`master` 档案、`report` 报表、`settings` 设置 |
| `identity` | 记录主键、显示编号及并发版本字段 |
| `state` | 可选状态机；无状态档案/报表可以不配置 |
| `fields` | 表头/主记录字段的唯一来源 |
| `detailSections` | 0..N 个明细集合 |
| `views` | 列表和表单如何组织上述字段，不重复定义字段语义 |
| `actions` | 声明式动作及可用条件 |
| `extensions` | 命名空间扩展，只允许 preset/plugin 消费 |

### 3.2 身份与并发

```json
{
  "identity": {
    "recordKey": "id",
    "displayKey": "orderNo",
    "versionKey": "version"
  }
}
```

- `recordKey` 是不可变技术主键，不应使用可修改的业务名称。
- `displayKey` 是给用户查看、搜索和打印的业务编号。
- `versionKey` 用于乐观锁。保存时版本不一致必须返回冲突，不允许静默覆盖。

### 3.3 字段定义

```json
{
  "key": "customerId",
  "label": "客户",
  "type": "reference",
  "required": true,
  "reference": {
    "panel": "CUSTOMER",
    "valueField": "id",
    "labelField": "name",
    "map": [
      { "from": "name", "to": "customerName" }
    ]
  },
  "ui": { "span": 1, "placeholder": "选择客户" }
}
```

V1 标准字段类型：

| 类型 | 默认控件 | 数据值 |
|---|---|---|
| `text` | 单行输入 | string |
| `textarea` | 多行输入 | string |
| `integer` | 数字输入 | integer |
| `decimal` | 数字输入 | number |
| `boolean` | switch/checkbox | boolean |
| `date` | 日期选择 | `YYYY-MM-DD` |
| `datetime` | 日期时间选择 | ISO 8601 string |
| `enum` | 下拉/单选 | string/number/boolean |
| `reference` | 参照选择器 | 标量或标量数组 |
| `image` | 图片查看/上传 | attachment object |
| `file` | 附件控件 | attachment object/array |

字段规则：

- `key` 在主字段内唯一；同一明细内也必须唯一。
- `required`、`validation` 是通用校验；服务端必须执行同等或更严格校验。
- `readonly` 是静态只读；状态相关只读使用权限或运行时规则。
- `options` 仅用于稳定小枚举；业务档案必须使用 `reference`。
- `reference.map` 负责选择后带出字段，不在组件中硬编码联动。
- `ui` 只存展示提示，不存业务逻辑。

### 3.4 明细定义

```json
{
  "key": "items",
  "label": "服务项目",
  "required": true,
  "minRows": 1,
  "fields": [],
  "calculations": [],
  "summary": ["quantity", "amount"]
}
```

记录中的 `details.items` 必须与 `detailSections[key=items]` 对应。禁止在展示配置中使用另一个别名。

计算规则使用声明式表达式：

```json
{
  "target": "amount",
  "expression": {
    "op": "multiply",
    "args": [
      { "field": "quantity" },
      { "field": "unitPrice" }
    ]
  },
  "scale": 2
}
```

V1 只允许白名单运算符：`add`、`subtract`、`multiply`、`divide`、`min`、`max`、`round`。运行时不得执行配置字符串。

### 3.5 视图定义

字段语义由 `fields` 和 `detailSections` 定义，`views` 只引用字段 key：

```json
{
  "views": {
    "list": {
      "pageSize": 20,
      "keywordFields": ["orderNo", "customerName", "description"],
      "filters": ["status", "customerId", "ownerId", "createdDate"],
      "columns": [
        { "field": "orderNo", "width": 180, "fixed": "left" },
        { "field": "status", "width": 100 }
      ],
      "detailPreview": ["items"]
    },
    "form": {
      "columns": 3,
      "sections": [
        { "key": "basic", "title": "基本信息", "fields": ["orderNo", "status"] }
      ],
      "details": ["items"]
    }
  }
}
```

渲染器必须提供以下状态：加载、空数据、错误、无权限、只读、编辑、脏数据、保存中、并发冲突。

### 3.6 动作定义

```json
{
  "id": "submit",
  "label": "提交",
  "scope": "form",
  "intent": "primary",
  "placement": { "group": "workflow", "order": 20 },
  "executor": { "type": "dataSource", "operation": "submit" },
  "permission": "serviceOrder:submit",
  "enabledWhen": {
    "field": "$state",
    "operator": "in",
    "value": ["draft", "rejected"]
  },
  "confirmation": { "title": "提交工单", "message": "确认提交当前工单？" }
}
```

| 属性 | 说明 |
|---|---|
| `id` | 稳定动作 ID；后端按 ID 路由，不按显示文案路由 |
| `label` | 默认显示文案 |
| `scope` | `list`、`form`、`row`、`selection`、`global` |
| `intent` | `default`、`primary`、`success`、`warning`、`danger` |
| `placement` | 工具栏分组与排序 |
| `executor` | `builtin` 客户端标准动作或 `dataSource` 服务端动作 |
| `permission` | 权限标识；服务端仍需复核 |
| `visibleWhen` | 声明式显示条件 |
| `enabledWhen` | 声明式可用条件 |
| `confirmation` | 危险/流程动作确认信息 |

显示文案可以变化，但 `id`、`permission`、`operation` 不随语言变化。

### 3.7 状态机

```json
{
  "state": {
    "field": "status",
    "initial": "draft",
    "options": [
      { "value": "draft", "label": "草稿", "tone": "neutral" },
      { "value": "submitted", "label": "已提交", "tone": "info" }
    ],
    "transitions": [
      { "action": "submit", "from": ["draft"], "to": "submitted" }
    ]
  }
}
```

状态机用于 UI 预测和测试，真实迁移由 `dataSource.executeAction` 的服务端实现。服务端返回的新状态是最终结果。

## 4. 标准数据契约

### 4.1 PanelRecord

```json
{
  "key": "01J...",
  "version": 3,
  "state": "draft",
  "values": {
    "orderNo": "SO-2026-0001",
    "customerId": "C001"
  },
  "details": {
    "items": []
  },
  "system": {
    "createdBy": "u001",
    "createdAt": "2026-08-24T10:00:00+08:00",
    "updatedAt": "2026-08-24T10:10:00+08:00"
  }
}
```

业务字段统一放 `values`，明细统一放 `details`，审计字段统一放 `system`。渲染器不得猜测“编号”“单据状态”等固定文案。

### 4.2 查询请求与响应

```json
{
  "panel": "SERVICE_ORDER",
  "keyword": "SO-2026",
  "filters": { "status": ["draft", "submitted"] },
  "sort": [{ "field": "createdDate", "direction": "desc" }],
  "page": 1,
  "pageSize": 20
}
```

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20
}
```

### 4.3 动作请求与响应

```json
{
  "panel": "SERVICE_ORDER",
  "action": "submit",
  "keys": ["01J..."],
  "record": {},
  "params": {},
  "requestId": "client-generated-id"
}
```

```json
{
  "records": [],
  "refresh": "record",
  "message": { "type": "success", "text": "提交成功" },
  "navigation": null,
  "download": null
}
```

`requestId` 用于服务端幂等。创建、生单、审批等动作不应依赖前端重复点击保护。

## 5. PanelDataSource 接口

建议 SDK 核心包定义以下 TypeScript 接口，具体项目实现 HTTP、GraphQL、IndexedDB 或测试内存源：

```ts
export interface PanelDataSource {
  getDefinition(code: string, context?: RuntimeContext): Promise<PanelDefinition>
  getPermissions(code: string, context?: RuntimeContext): Promise<PanelPermissions>
  query(request: PanelQuery): Promise<PageResult<PanelRecord>>
  create(code: string, context?: RuntimeContext): Promise<PanelRecord>
  get(code: string, key: string): Promise<PanelRecord>
  save(code: string, record: PanelRecord): Promise<PanelRecord>
  executeAction(request: PanelActionRequest): Promise<PanelActionResult>
  remove(code: string, keys: string[]): Promise<void>
  resolveReference(request: ReferenceQuery): Promise<PageResult<ReferenceOption>>
}
```

约束：

- SDK 不假定 Axios；适配器负责响应解包和错误归一化。
- `save` 必须携带 `key` 和 `version`；新建记录由 `create` 提供服务器默认值。
- `executeAction` 是业务扩展的唯一服务端入口，渲染器不得维护动作 switch。
- 参照查询统一走 `resolveReference`，不让组件直接访问另一个业务 API。

## 6. Runtime 与插件

### 6.1 Runtime 职责

- 校验定义及数据结构。
- 维护 record、dirty、loading、saving、conflict 状态。
- 计算字段、必填校验和明细汇总。
- 合并服务端权限与声明式可用条件。
- 调用 DataSource，并把标准结果转为 UI 事件。
- 触发插件生命周期。

### 6.2 插件扩展点

```ts
export interface PanelPlugin {
  name: string
  setup?(runtime: PanelRuntime): void
  beforeLoad?(context: HookContext): Promise<void> | void
  afterLoad?(context: HookContext): Promise<void> | void
  beforeSave?(context: HookContext): Promise<void> | void
  afterSave?(context: HookContext): Promise<void> | void
  beforeAction?(context: ActionHookContext): Promise<void> | void
  afterAction?(context: ActionHookContext): Promise<void> | void
}
```

建议的独立插件：审批历史、Excel 导入导出、附件、打印、选单/生单、审计日志。插件只能通过 Runtime API 操作数据，不能访问具体组件内部状态。

### 6.3 Preset

Preset 是一组定义默认值、动作和插件：

- `basePreset`：CRUD、参照、校验、分页。
- `documentPreset`：编号、状态机、明细、审计。
- `approvalPreset`：提交、通过、驳回、历史。
- `mesPreset`：T+ 布局、BOM、生产单据动作。

MES 特例只能进入 `mesPreset`，不能写入 `@panel-sdk/core` 或通用 Renderer。

## 7. SDK 包建议

```text
@panel-sdk/core          Definition 类型、Schema 校验、Runtime、表达式
@panel-sdk/data-http     HTTP DataSource 与错误模型
@panel-sdk/vue           Vue 渲染器；Vue/Element Plus 为 peerDependencies
@panel-sdk/plugin-import Excel 导入导出
@panel-sdk/plugin-flow   审批/工作流
@panel-sdk/preset-mes    Light MES/T+ 业务规则
```

`@panel-sdk/core` 必须能在 Node 单元测试中运行，不依赖 DOM、Vue、Element Plus、路由或 Pinia。

## 8. 与 Light MES 的兼容映射

| Light MES 当前契约 | 通用 V1 |
|---|---|
| `metadata.panelCode` | `code` |
| `metadata.panelName` | `title` |
| `metadata.panelCategory` | `kind`（adapter 映射） |
| `dataSchema.fields[].dataName` | `fields[].key` |
| `dataType=文本/小数/是否/参照` | `type=text/decimal/boolean/reference` |
| `detail.tabs[]` | `detailSections[]` |
| `tablePages[0].queryFields` | `views.list.filters` |
| `gridTabs[].columns` | `views.list.columns/detailPreview` |
| `metadata.buttonGroups` | `actions[].placement.group/order` |
| `编号` | `PanelRecord.key` 或 adapter 的 `identity.recordKey` |
| `单据状态` | `PanelRecord.state` |
| `getPanelConfig` | `getDefinition` |
| `queryFormDataList` | `query` |
| `getNewFormPermMatrix` | `create + getPermissions` |
| `getFormDescriptor` | `get + getPermissions` |
| `callButton` | `save/executeAction` |
| `deleteForms` | `remove` |

迁移期保留 legacy adapter，避免一次性修改所有面板配置和存量数据。

## 9. 当前代码需要移出的特例

根据现有实现，以下逻辑不是通用 Renderer 职责：

- 组件直接 import `@/business/engine`、用户 store 和页签 store。
- 通过中文按钮文案执行 switch。
- 固定读取 `编号`、`单据状态`、`备注`。
- `INV` 参照、BOM 联动、产成品/材料/工序字段判断。
- 审批权限和状态可用性矩阵。
- 路由跳转、页面标题和 MES 页签管理。
- `PxService` 中面板码对应编号前缀、生单和审批面板集合。

迁移方式：分别改为 DataSource 注入、Action Registry、identity/state 定义、plugin/preset 和宿主导航适配器。

## 10. 安全要求

1. 配置不得保存平台密码、Token、数据库凭据或内部服务密钥。
2. 禁止 `eval`、`new Function` 和从配置加载脚本 URL。
3. 表达式只允许 Schema 中的白名单 AST。
4. 服务端必须重新执行字段校验、动作权限和状态迁移校验。
5. 富文本、文件名、下载 URL 和错误消息进入 DOM 前必须安全处理。
6. 每次写操作携带 `requestId`；保存携带 `version`。
7. 日志不得记录密码、Token、完整敏感表单或附件内容。

## 11. 版本规则

- Schema 使用 SemVer；破坏性字段变更升级主版本。
- Definition 自身也有独立 `version`。
- SDK 在加载时验证 `schemaVersion`，不兼容时明确失败，不静默降级。
- Definition 进入生产后不可原地篡改历史版本；发布新版本并记录迁移。
- 扩展字段必须放 `extensions.<组织或包名>`，避免污染标准命名空间。

## 12. 验收清单

- [ ] Definition 通过 JSON Schema 校验。
- [ ] 主字段和每个明细字段 key 唯一。
- [ ] 视图引用的字段/明细全部存在。
- [ ] Action ID 唯一，状态迁移引用的 action 存在。
- [ ] 不含函数、脚本 URL、凭据和业务服务地址。
- [ ] DataSource 合同测试覆盖 query/create/get/save/action/remove/reference。
- [ ] 服务端权限与状态校验不能被直接 HTTP 请求绕过。
- [ ] Vue Renderer 不含具体面板码和业务字段名。
- [ ] 适配桌面和移动端，错误/空/加载/冲突状态可见。
- [ ] 新项目只需安装包、注册 DataSource、加载 Definition，不复制 SDK 源码。
