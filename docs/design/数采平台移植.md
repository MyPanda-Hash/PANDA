## 1. 三个功能

| 功能 | 页面 | 内容 |
|---|---|---|
| IOT 设备配置 | `/mes/dc/config` | 网关台账、设备台账、采集点、数采规则；每人设备五连检查进度 |
| 数据监控 | `/mes/dc/monitor` | 选中设备的采集点当前值、最新 10 条流水、报警列表与处理 |
| 状态统计 | `/mes/dc/stats` | 当前在线/离线、窗口内在线率、按日趋势、按设备时长、报警分布 |

**五连检查**（只看台账字段，不引入「已配」标记，避免假绿）：

| 键 | 名称 | 判据 |
|---|---|---|
| `gateway` | 绑定网关 | `dc_device.gateway_id` 非空 |
| `project` | 数采工程 | `dc_device.project_code` 非空 |
| `scada` | 绘制组态 | `dc_device.scada_drawn = true` |
| `rule` | 数采规则 | 存在启用的 `dc_rule` |
| `debug` | 数据调试 | `dc_device.last_debug_at` 非空（收到真实数据或人工标记） |

`完成度 = 完成项 / 5 × 100`；五项齐备才算接入完成。

## 2. 数据模型（Flyway `V2__dc_platform.sql`）

| 表 | 说明 | 关键约束 |
|---|---|---|
| `dc_gateway` | 数采网关（协议/地址/接入密钥/在线状态） | `code` 唯一；`api_key` 只写不读 |
| `dc_device` | 设备台账（类型/网关/工程/组态/心跳周期/在线状态） | `code` 唯一 |
| `dc_point` | 采集点（编码/单位/量程/上报周期） | 同设备内 `code` 唯一（部分唯一索引，排除已删） |
| `dc_rule` | 数采规则（定时采集/变化上报/阈值报警） | — |
| `dc_sample` | 采集流水，只增不改 | 索引 `(point_id, collect_at desc)` |
| `dc_alarm` | 报警工单（超限产生，人工处理留痕） | 索引 `(state, occur_at desc)` |
| `dc_status_log` | 在线/离线切换日志，在线率依据 | 索引 `(device_id, changed_at desc)` |

与源表差异：

- 表名 `bs_dc_*` → `dc_*`（light-mes 不加业务前缀）。
- `char(1) 'Y'/'N'` → `boolean`；`datetime2` → `timestamp(0)`；`SYSDATETIME()` → `now()`；
  `IDENTITY(int)` → `bigint generated by default as identity`。
- `asp_user1/2 + asp_time1/2 + asp_cancel` → `create_by/create_time/update_by/update_time + cancelled`
  （与 light-mes 其它表一致）。
- 台账类五张表（网关/设备/采集点/规则/报警）按项目规则预留 30 个 `ext_*` 扩展列；
  `dc_sample`、`dc_status_log` 是只增不改的流水/日志，不预留（写明理由，避免为了规则把写放大）。
- 首批台账只登记真实存在的三台设备（电子秤 DZ-001 / 扫码枪 FX-001 / 车间看板 KB-001），
  **不造任何采样值与报警**；未接硬件前页面如实显示「离线 / 待配置」。

## 3. 接口（`/api/px/dc/*`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/config` | 登录 | KPI + 网关表 + 设备五连表 + 检查项定义 |
| POST | `/gateway/save`、`/gateway/delete` | 管理员 | 保存/删除网关（删除先解绑设备） |
| POST | `/device/save`、`/device/delete`、`/device/debug` | 管理员 | 设备台账维护；删除连带软删采集点/规则；调试时间刷新 |
| GET | `/points`、`/rules` | 登录 | 采集点 / 规则列表（可按设备过滤） |
| POST | `/point/save`、`/point/delete`、`/rule/save`、`/rule/delete` | 管理员 | 采集点与规则维护 |
| GET | `/monitor` | 登录 | 设备列表 + 当前值 + 最新 10 条流水 + 报警 |
| GET | `/alarms` | 登录 | 报警分页（状态/级别/设备过滤） |
| POST | `/alarm/handle` | 登录 | 处理报警（写 `handled_by/at/note`，只改状态不删记录） |
| GET | `/stats` | 登录 | 在线率、按设备时长、按日趋势、报警分布 |
| POST | `/ingest` | `X-DC-Key` | 硬件批量上报 `{deviceCode, values:[{pointCode,value}]}` |
| GET/POST | `/ingest/text` | `X-DC-Key` | 串口帧文本上报（透传模块用） |
| POST | `/heartbeat` | `X-DC-Key` | 心跳，刷新在线并写状态日志 |

硬件侧三条在 `SecurityConfig` 里 `permitAll`（电子秤/网关没有登录账号），鉴权在
`DcService.requireGatewayKey`：设备必须绑定启用中的网关，且请求头 `X-DC-Key` 等于该网关
`dc_gateway.api_key`（未绑网关/未配密钥/密钥错一律拒绝）。

## 4. 关键口径

| 事项 | 口径 | 为什么 |
|---|---|---|
| 在线判定 | 最近上报时间 + `heartbeat_seconds × 3`（下限 180 秒）之内 | 5 秒心跳的设备抖一下不该判离线；60 秒心跳 3 分钟判离线 |
| 在线率 | 只在「已知时长」上算：设备首次有痕迹（首条状态日志或首条流水）之前不计入分母 | 否则当天接入的设备会被算成「离线 29 天」 |
| 从未接入 | 无状态日志且无上报 ⇒ 时长/在线率返回 `null`，界面显示「—」 | 数据真实性口径，不编造数字 |
| 越限报警 | 采集点有上下限且值为数值时判定；越限写一条 `dc_alarm(state=未处理, level=预警)` | 与源系统一致 |
| 文本上报 | 先按现场帧 `+000.39000.00kg` 取净重，再退回「第一个带小数的数」，最后末尾整数 | 现场秤型号多，容错优先 |
| 空秤/节流 | ≤5g 视为空秤不记流水（但刷新心跳）；同一设备 1 秒最多一条 | 秤连续发送 5~10Hz，不然流水会被刷爆 |
| 流水清理 | 每 5 分钟把每个采集点只保留最新 10 条（`mes.dc.sample.retain`，≤0 关闭） | 一天 8.6 万行，监控页只用最近 10 条 |

## 5. 与源系统的差异（有意为之）

1. **权限**：源系统用 `PanelPermissionService.requireAdmin`；light-mes 用 `RoleService.isAdminUser`，
   读接口登录即可，写接口管理员。报警处理只要求登录（车间任何人都能认领）。
2. **数据键**：源系统前端 camelCase（由服务层转换）；light-mes 同样在服务层转，接口保持 camelCase，
   数据库列 snake_case，页面直接用。
3. **多语言**：源系统强制 `tt()` + `yj_translation`；light-mes 的 MPS/仓内作业等专属页面用中文直写，
   本模块跟随现状（中文直写），不进 `sys_translation`。
4. **不搬的**：源系统的 `bsp_` 体检规则、SQL Server 扩展属性、`yj_*` 面板元数据。

## 7. 未做 / 边界

- 网关协议驱动（MQTT/Modbus 真实连接）不在本模块：本平台只做**台账 + 上报接入 + 监控 + 统计**，
  真实协议由硬件网关负责，MES 侧只接收 HTTP 上报（与源系统一致）。
- 报警规则引擎只落「越限报警」；源系统的「变化上报/阈值报警」规则字段已建表，但未做规则执行器。
- 采集中间件、时序库、历史曲线不在本次范围（监控页只看最新 10 条）。
