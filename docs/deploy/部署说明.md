# light-mes 部署指南（自建网站）

## 模式速览（重要，先读）

| 场景 | 环境 | 数据/面板来源 |
|---|---|---|
| 本地开发 dev | `.env.local`（VITE_PANELX=true） | PanelX 平台测试域（203.132.49.57:6612/hscx，需平台在线） |
| **生产构建（路线①推荐）** | `.env.production.local`（VITE_MOCK=false） | **自己服务器的 Spring Boot + MySQL，不加载 SDK、不依赖平台** |
| 路线②（备选） | 平台直连/后端代理 | 网站+SDK 自托管，面板数据仍接平台实例（见 nginx-mes.conf） |

> 前端 `npm run build` 会读取 `.env.production.local`，自动产出路线①的构建包。

---

## 路线①：完全自建（前端 + Spring Boot + MySQL，无 SDK、无外部平台）

### 架构

```
用户浏览器 → nginx (服务器)
   ├── /          → 前端静态文件（dist/）
   └── /api/*     → 本机 Spring Boot :8080（登录/菜单/面板引擎 Px/业务接口）
                          └─ MySQL 8（light_mes 库）
```

### 0. 服务器环境（Ubuntu/Debian 示例）

```bash
apt update
apt install -y nginx openjdk-17-jdk mysql-server
java -version          # 确认 17+（注意：本项目编译目标 Java 17，JDK 17/21/26 均可）
systemctl enable --now mysql nginx
```

### 1. 数据库初始化

```bash
# 上传 init.sql 后执行（自动建库 light_mes + 建表 + 种子数据：admin 用户/菜单/面板配置）
mysql -uroot -p < backend/src/main/resources/db/init.sql
# 修改后端连接信息（backend/src/main/resources/application.yml 的 spring.datasource）
#   username/password 改为你的 MySQL 账号
```

### 2. 后端 jar

**本机已构建好：** `backend/target/light-mes-backend-0.1.0.jar`（32.8MB，Spring Boot fat jar，跨平台）。

服务器上重新构建（可选）：

```bash
# 需要 JDK 17+，且 JAVA_HOME 必须指向它（Windows 本机坑见文末）
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
mvn -s tools/settings.xml -q clean package -DskipTests
```

部署 + systemd 自启：

```bash
mkdir -p /opt/light-mes
cp light-mes-backend-0.1.0.jar /opt/light-mes/

cat > /etc/systemd/system/light-mes.service <<'EOF'
[Unit]
Description=light-mes backend
After=network.target mysql.service

[Service]
WorkingDirectory=/opt/light-mes
ExecStart=/usr/bin/java -jar /opt/light-mes/light-mes-backend-0.1.0.jar
Restart=on-failure
RestartSec=5
Environment=SPRING_DATASOURCE_PASSWORD=你的MySQL密码

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload && systemctl enable --now light-mes
curl http://127.0.0.1:8080/api/auth/login -X POST -H "Content-Type: application/json" -d '{"userName":"admin","password":"123456"}'   # 应返回 token
```

### 3. 前端构建 + 上传

**本机已构建好：** `light-mes/frontend/dist/`（VITE_MOCK=false 的路线①包）。

服务器上重新构建（可选）：

```bash
cd frontend
npm install
npm run build          # 自动读取 .env.production.local（VITE_MOCK=false）
```

上传：

```bash
# 本机执行
scp -r light-mes/frontend/dist user@服务器:/var/www/light-mes/dist
```

### 4. nginx（配置见 nginx-mes-standalone.conf）

```bash
scp docs/deploy/nginx-mes-standalone.conf user@服务器:/etc/nginx/conf.d/mes.example.com.conf
# 改配置里的 server_name / 证书路径
nginx -t && systemctl reload nginx
```

### 5. HTTPS

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d mes.example.com
```

### 6. 验收

浏览器打开 `https://mes.example.com` → 门户登录 `admin / 123456` →
进「生产加工单」→ 列表来自**自己后端**（F12 里 /api/* 都是 200，无任何 kwaidoo/203.132.49.57 请求）。

见 `nginx-mes.conf`（/wp-core、/wp-file 反代到平台实例）。前提：平台稳定在线、有面板配置。

## 附：Windows 本机构建踩坑记录

1. **JAVA_HOME 指向 JDK 8 导致编译失败**：本机 `JAVA_HOME=D:\Program Files\Java\jdk1.8.0_111`（JDK 8），
   而 `PanelxService.java` 用了 instanceof 模式匹配（Java 16+ 语法）。**修复**：pom.xml 已加
   `<maven.compiler.release>17</maven.compiler.release>`，构建时确保 JAVA_HOME 指向 JDK 17+：
   ```powershell
   $env:JAVA_HOME='C:\Program Files\Java\jdk-26.0.2'
   & tools\apache-maven-3.9.9\bin\mvn.cmd -s tools\settings.xml -q clean package -DskipTests
   ```
2. **Vite 端口占用**：5173 被占时自动换端口（5174/5175…），看启动日志里的实际地址。
3. **Windows 防火墙**：局域网访问需放行对应端口（vite 5173 / 后端 8080）。
4. **生产构建与 dev 模式差异**：dev（.env.local）走平台测试域；生产（.env.production.local）走自建后端——两者互不影响。
