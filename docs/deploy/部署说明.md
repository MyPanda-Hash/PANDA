## 模式速览

| 场景 | 环境 | 数据/面板来源 |
|---|---|---|
| 本地后端（默认） | `VITE_PANELX_PROXY` 为空 | 浏览器 `/api` → Spring Boot `/api/px/*` → MySQL |
| PanelX 后端代理 | `VITE_PANELX_PROXY=true` | 浏览器 `/api/panelx/*` → Spring Boot 网关 → PanelX 平台 |

> 构建前通过环境变量或 `.env.production.local` 明确设置 `VITE_PANELX_PROXY`。浏览器在两种模式下都不加载 PanelX 浏览器 SDK。

## 路线一：完全自建（前端 + Spring Boot + MySQL）

### 架构

```
用户浏览器 → nginx (服务器)
   ├── /          → 前端静态文件（dist/）
   └── /api/*     → 本机 Spring Boot :8080（登录/菜单/面板引擎 Px/业务接口）
                          └─ MySQL 8（light_mes 库）
```

### 0. 服务器环境（Ubuntu/Debian 示例）

```bash
apt update
apt install -y nginx openjdk-17-jdk mysql-server
java -version          # 确认 17+（注意：本项目编译目标 Java 17，JDK 17/21/26 均可）
systemctl enable --now mysql nginx
```

### 1. 数据库初始化

```bash
# 上传 init.sql 后执行（自动建库 light_mes + 建表 + 种子数据：admin 用户/菜单/面板配置）
mysql -uroot -p < backend/src/main/resources/db/init.sql
# 修改后端连接信息（backend/src/main/resources/application.yml 的 spring.datasource）
#   username/password 改为你的 MySQL 账号
```

### 2. 后端 jar

**本机已构建好：** `backend/target/light-mes-backend-0.1.0.jar`（32.8MB，Spring Boot fat jar，跨平台）。

服务器上重新构建（可选）：

```bash
# 需要 JDK 17+，且 JAVA_HOME 必须指向它（Windows 本机坑见文末）
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
mvn -s tools/settings.xml -q clean package -DskipTests
```

部署 + systemd 自启：

```bash
mkdir -p /opt/light-mes
cp light-mes-backend-0.1.0.jar /opt/light-mes/

cat > /etc/systemd/system/light-mes.service <<'EOF'
[Unit]
Description=light-mes backend
After=network.target mysql.service

[Service]
WorkingDirectory=/opt/light-mes
ExecStart=/usr/bin/java -jar /opt/light-mes/light-mes-backend-0.1.0.jar
Restart=on-failure
RestartSec=5
Environment=SPRING_DATASOURCE_PASSWORD=你的MySQL密码

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload && systemctl enable --now light-mes
curl http://127.0.0.1:8080/api/auth/login -X POST -H "Content-Type: application/json" -d '{"userName":"<管理员账号>","password":"<管理员密码>"}'   # 应返回 token
```

### 3. 前端构建 + 上传

**本机已构建好：** `light-mes/frontend/dist/`（本地后端模式构建包）。

服务器上重新构建（可选）：

```bash
cd frontend
npm install
npm run build          # 根据 VITE_PANELX_PROXY 生成对应模式构建包
```

上传：

```bash
# 本机执行
scp -r light-mes/frontend/dist user@服务器:/var/www/light-mes/dist
```

### 4. nginx（配置见 nginx-mes-standalone.conf）

```bash
scp docs/deploy/nginx-mes-standalone.conf user@服务器:/etc/nginx/conf.d/mes.example.com.conf
# 改配置里的 server_name / 证书路径
nginx -t && systemctl reload nginx
```

### 5. HTTPS

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d mes.example.com
```

### 6. 验收

浏览器打开 `https://mes.example.com` → 门户登录 `admin / 123456` →
进「生产加工单」→ 列表来自**自己后端**（F12 里 /api/* 都是 200，无任何 kwaidoo/203.132.49.57 请求）。

## 路线二：PanelX 后端代理

前端设置 `VITE_PANELX_PROXY=true`，所有面板请求仍先进入本地 Spring Boot：

```text
浏览器 /api/panelx/*
  -> nginx /api/*
  -> Spring Boot PanelxController
  -> PanelxGateway
  -> PanelX 平台
```

平台地址、业务域、应用码和凭据配置在 `application.yml` 的 `mes.panelx` 节，并通过生产环境变量注入敏感值。nginx 不再把 `/wp-core` 或 `/wp-file` 直接暴露给浏览器。生产环境必须收紧 `/api/panelx/**` 鉴权，并确认平台可用性、超时和失败降级策略。

## 自动部署规则（一键部署，2026-08-20 固化）

> 目标：任何一台全新 Ubuntu 22.04+ 服务器（仅需 root SSH），一条命令完成
> 「打包 → 上传 → 解压 → 装环境 → 建库 → systemd → nginx → 全量验证」。
> 已用于 <服务器IP>（阿里云 ECS）实测通过。

### 方式 A：Windows 本机一键（推荐）

```powershell
# 前提：本机有构建产物（jar / dist / init.sql），首次运行自动装 Posh-SSH 模块
cd E:\INCER\light-mes\docs\deploy
.\deploy-auto.ps1 -ServerIp <服务器IP> -Password '你的root密码'
# 可选：-Domain mes.example.com（有域名时传给 nginx server_name）
```

脚本流程：
1. **本机打包**：从 `light-mes` 取 jar / init.sql / dist / deploy-route1.sh 打 zip
2. **SCP 上传** → `/opt/light-mes/`
3. **解压**：自动装 unzip，dist 移到 `/var/www/light-mes/dist`
4. **跑 deploy-route1.sh**：装 nginx+JDK17+MySQL → 初始化 light_mes → systemd 服务 → nginx 站点（前台执行，超时 900s）
5. **兜底**：若脚本某步退出码非 0，自动用 printf 重建 systemd/nginx 配置
6. **全量验证**：三个服务 active、登录接口 code:200、前端 200、数据库 4 表计数

### 方式 B：服务器手动（无 Windows 侧工具时）

同下方"标准部署流程"，文件用 WinSCP/scp 传。

### 自动部署注意规则（踩坑固化）

1. **不要在服务器上 nohup 后台跑 deploy-route1.sh**：脚本依赖前台 stdin 的 heredoc；
   后台执行时 heredoc 写文件会失败（service 文件为空/缺失）。要么前台跑（推荐），
   要么用已改成 printf 写法的**新版脚本**（v2，见下）。
2. **`cp: same file` 会触发 set -e 提前退出**：jar 已在目标位置时 cp 返回非零，
   脚本 3/5 步直接终止且**不报错**（日志只到 cp 警告）。已修复：同文件跳过复制。
3. **重跑脚本时 MySQL root 密码已是 root**：`mysql -uroot`（无密码）报
   `Access denied (using password: NO)`。已修复：先探测无密码可连则跳过 ALTER。
4. **Posh-SSH 的 SCP 目标参数是"目录"**：`Set-SCPItem -Destination '/etc/nginx/sites-available/'`
   表示放进该目录（保留源文件名），不是目标文件路径；文件已存在才会被当作目标。
5. **Posh-SSH 的 Set-SFTPItem 目标必须已存在**：先 `touch` 或传 /tmp 再 mv。
6. **新服务器先装 unzip**：部署包 zip 需要它解压（脚本已自动处理）。
7. **安全组**：服务器内 curl 全通但公网打不开 → 阿里云安全组放行 TCP 80（ECS 在
   「安全组-入方向」，轻量服务器在「防火墙」）。

### deploy-route1.sh v2 变更说明

| 变更 | 原因 |
|---|---|
| heredoc → printf 写 systemd/nginx 配置 | nohup 后台执行时 heredoc 失效 |
| cp 同文件跳过 | `cp same file` 返回非零触发 set -e 静默终止 |
| MySQL 密码探测后设置 | 重跑幂等（不再 Access denied） |
| nginx 目录 mkdir -p | Ubuntu nginx 默认无 sites-available（1.18 用 conf.d 时） |

## 附：Windows 本机构建踩坑记录

1. **JAVA_HOME 指向 JDK 8 导致编译失败**：本机 `JAVA_HOME=D:\Program Files\Java\jdk1.8.0_111`（JDK 8），
   而 `PanelxService.java` 用了 instanceof 模式匹配（Java 16+ 语法）。**修复**：pom.xml 已加
   `<maven.compiler.release>17</maven.compiler.release>`，构建时确保 JAVA_HOME 指向 JDK 17+：
   ```powershell
   $env:JAVA_HOME='C:\Program Files\Java\jdk-26.0.2'
   & tools\apache-maven-3.9.9\bin\mvn.cmd -s tools\settings.xml -q clean package -DskipTests
   ```
2. **Vite 端口占用**：5173 被占时自动换端口（5174/5175…），看启动日志里的实际地址。
3. **Windows 防火墙**：局域网访问需放行对应端口（vite 5173 / 后端 8080）。
4. **开发与生产模式必须显式一致**：两者都通过 `VITE_PANELX_PROXY` 选择本地后端或 PanelX 后端代理。历史 `VITE_MOCK`、`VITE_PANELX` 和浏览器直连配置已删除，不应再加入新环境文件。

## 附：2026-08-19 首次服务器部署实战问题记录

> 目标机：阿里云 Ubuntu 22.04（iZbp16e6o8svk57kbp4kfvZ），2C4G。
> 部署方式：本机打部署包 zip → WinSCP/scp 上传 → 服务器解压 → 脚本/手动部署。
> 共踩 5 个坑，均已解决；**修复已同步回本仓库**（init.sql、部署包、本脚本）。

### 坑 1：scp 命令在服务器上执行（用户操作失误，非环境问题）

**现象**：把本机的 `scp E:\... root@服务器IP:/opt/light-mes/` 命令粘贴到服务器终端执行，
报 `ssh: Could not resolve hostname 服务器IP / e`。
**原因**：上传命令必须在 **Windows 本机**执行（文件在 E:\ 盘，服务器访问不到）；
`E:\`、`服务器IP` 是占位符，不能照抄。
**解决**：本机用 WinSCP 拖拽上传（推荐），或本机 PowerShell 里执行 scp（输真实 IP + 密码）。

### 坑 2：unzip 未安装

**现象**：`unzip light-mes-deploy.zip` 报 `Command 'unzip' not found`。
**解决**：`apt install -y unzip`（阿里云镜像，秒装）。

### 坑 3：init.sql 语法错误 1064 —— 缺逗号（源码 bug，已修复）

**现象**：脚本第 2 步导入数据库报：
```
ERROR 1064 (42000) at line 322: ... near '(4121, 'ROUTE', 'ROUTE-002', '{"编号":"ROUTE-002","工艺路线编码":"GY-002' at line 116
```
**原因**：`form_data` 表多行 INSERT 中 `ROUTE-001`(id=4120)、`ROUTE-002`(id=4121)
两条记录行**末尾漏了逗号**，SQL 提前截断。报错 `at line 116` = INSERT 语句内第 116 行
（文件第 437 行）。Windows 本地库是早期版本建的，没重跑过该文件，所以本地没暴露。
**修复**：`init.sql` 补上两处逗号（已修复入库）。若遇到旧部署包，可手工检查
`VALUES` 记录行是否都以 `,` 结尾：
```bash
# 服务器上检查：找以 ')' 结尾且不是 '),' 或 ');' 的 VALUES 行
grep -nE "^\(\d+, " init.sql | grep -vE ",\s*$" | grep -vE ";\s*$"
```

### 坑 4：脚本第 2 步重跑报 Access denied（幂等性问题）

**现象**：数据库已导入成功后，重跑 `deploy-route1.sh`，第 2 步报：
```
ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: NO)
```
**原因**：脚本首次运行已设置 root 密码，重跑时 `mysql -uroot`（无密码）
连不上。这是**幂等重跑的正常现象**，不是错误。
**处理**：跳过脚本第 2 步，手动续跑第 3~5 步（systemd 服务、nginx、验证），
或使用安全方式提供当前密码后重跑。脚本应先探测连接方式，不得硬编码密码。

### 坑 5：登录 500 —— init.sql 与 jar 结构不同步（源码 bug，已修复）

**现象**：后端启动正常、nginx 正常、前端返回 200，但登录接口报：
```
Unknown column 'role_id' in 'field list'
```
**原因**：jar 代码（8/19 构建）中 `SysUser` 实体有 `roleId`/`deptId` 字段，
`RoleService` 依赖 `sys_role`/`sys_role_panel`/`sys_dept` 三张表；
但 `init.sql` 的 `sys_user` 表**缺 role_id、dept_id 列**，且**从未建过那三张表**
（本地库是历史版本建的，源码文件一直没同步）。
**修复**：`init.sql` 已补齐（sys_user 加列 + 建三表 + ADMIN 角色/部门种子数据），
已修复入库。**老库升级**用补丁脚本 `docs/deploy/light-mes-patch.sql`：
```bash
mysql -uroot -p light_mes < /opt/light-mes/light-mes-patch.sql
# 注意：必须显式指定库名（脚本内 ALTER/CREATE 不带库前缀）
```
补丁内容（幂等）：
- `sys_user` 补 `role_id`、`dept_id` 列（information_schema 判断存在性）
- 建 `sys_role`（含 ADMIN 超级管理员角色，is_admin=1）
- 建 `sys_role_panel`（角色-面板授权）
- 建 `sys_dept`（11 个部门种子）
- `admin` 用户绑定 role_id=1
验证：`curl` 登录应返回 `code:200` + token + `isAdmin:true`。

### 坑 6：nginx 站点配置与验证

**现象**：`nginx -t` 通过、reload 成功，`curl http://127.0.0.1/` 返回 200。
**注意**：
- 脚本默认站点 `server_name _`（IP 访问），有域名需改 `server_name` 并做 80→443 跳转
  （参考 `nginx-mes-standalone.conf`）。
- 浏览器打不开时，检查阿里云**安全组入方向**是否放行 80（443）。

### 部署后必做（安全）

1. **设置高强度 MySQL root 密码**，并通过环境变量或凭据服务注入：
   ```bash
   mysql -uroot -p -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '<新密码>'; FLUSH PRIVILEGES;"
   # 同步改 /etc/systemd/system/light-mes.service 的 SPRING_DATASOURCE_PASSWORD，然后
   systemctl daemon-reload && systemctl restart light-mes
   ```
2. **改 admin 登录密码**：进系统右上角修改，或 SQL 更新。
3. **HTTPS**（有域名时）：`apt install -y certbot python3-certbot-nginx && certbot --nginx -d 你的域名`。
