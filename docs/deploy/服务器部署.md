# 轻 MES 服务器部署

|---|---|

本文是当前 SQL 模式的唯一部署说明。目标结构为 nginx 静态站点 + Spring Boot 服务 + PostgreSQL 16；旧服务器实测记录只保留在不入库的本地归档。

## 1. 部署结构

```text
浏览器
  -> nginx :80/:443
       /         -> /var/www/light-mes/dist
       /api/*    -> 127.0.0.1:8080
  PostgreSQL -> light_mes
                         -> 阿里云 OCR（仅扫描填单时）
```

建议环境：Ubuntu/Debian、JDK 17+、PostgreSQL 16、nginx。前端在开发机完成构建，服务器无需长期安装 Node.js。

## 2. 构建发布产物

在项目根目录执行：

```powershell
node tools/verify-project.mjs
```

需要发布的产物：

| 产物 | 目标位置 |
|---|---|
| `backend/target/light-mes-backend-0.1.0.jar` | `/opt/light-mes/light-mes-backend.jar` |
| `frontend/dist/` | `/var/www/light-mes/dist/` |
| `backend/src/main/resources/db/migration/V1__baseline.sql` | 已打进 jar，Flyway 首次启动自动建表，无需手工上传 |
| `docs/deploy/nginx-mes-standalone.conf` | nginx 站点配置模板 |

不要把源码目录、`.env`、数据库备份或本地浏览器 profile 一并上传。

## 3. 初始化 PostgreSQL

结构由 jar 内的 Flyway 在首次启动时创建（`db/migration/V1__baseline.sql`，26 张表 + 索引 + 注释 + `update_time` 触发器），服务器上不需要手工执行建表 SQL。只需先建库和账号：

```bash
sudo -u postgres psql <<'SQL'
CREATE DATABASE light_mes ENCODING 'UTF8' LC_COLLATE 'C.UTF-8' LC_CTYPE 'C.UTF-8' TEMPLATE template0;
ALTER DATABASE light_mes SET timezone TO 'Asia/Shanghai';
CREATE USER light_mes_app WITH PASSWORD '<数据库强密码>';
GRANT ALL PRIVILEGES ON DATABASE light_mes TO light_mes_app;
\c light_mes
GRANT ALL ON SCHEMA public TO light_mes_app;
SQL
```

从已有环境搬数据时用 `pg_dump` / `pg_restore`，不要再用 `mysqldump`：

```bash
# 源库导出（自定义格式，可用 pg_restore 选择性恢复）
sudo -u postgres pg_dump -Fc -d light_mes > /opt/light-mes/light_mes.dump
# 目标库恢复
sudo -u postgres pg_restore --no-owner --no-privileges -d light_mes /opt/light-mes/light_mes.dump
```

升级已有数据库前先备份：

```bash
mkdir -p /opt/light-mes/backup
sudo -u postgres pg_dump -Fc -d light_mes \
  > /opt/light-mes/backup/light_mes_$(date +%Y%m%d_%H%M%S).dump
```

结构变更一律追加 `db/migration/V2__xxx.sql`（Flyway 命名），不要在线上手工改表：手工改会让 `flyway_schema_history` 与实际结构脱节，下次启动校验失败。

## 4. 安装后端服务

```bash
sudo mkdir -p /opt/light-mes /etc/light-mes
sudo cp light-mes-backend-0.1.0.jar /opt/light-mes/light-mes-backend.jar
sudo chown -R root:root /opt/light-mes
```

生成随机 JWT 密钥，并把运行变量放入仅 root 可读的文件：

```bash
openssl rand -hex 64
sudo install -m 600 /dev/null /etc/light-mes/light-mes.env
sudoedit /etc/light-mes/light-mes.env
```

`/etc/light-mes/light-mes.env` 示例：

```ini
SPRING_DATASOURCE_URL=jdbc:postgresql://127.0.0.1:5432/light_mes
SPRING_DATASOURCE_USERNAME=light_mes_app
SPRING_DATASOURCE_PASSWORD=<数据库强密码>
MES_JWT_SECRET=<openssl生成的随机值>
MES_JWT_EXPIRE_HOURS=24
# 前后端同域时用于同源访问；分离部署时改为前端实际来源，禁止使用 *
MES_CORS_ALLOWED_ORIGINS=https://mes.example.com
ALIBABA_CLOUD_ACCESS_KEY_ID=<OCR RAM用户的新AccessKeyId>
ALIBABA_CLOUD_ACCESS_KEY_SECRET=<OCR RAM用户的新AccessKeySecret>
# 可选，默认值如下
ALIBABA_CLOUD_OCR_ENDPOINT=ocr-api.cn-hangzhou.aliyuncs.com
ALIBABA_CLOUD_OCR_REQUESTS_PER_MINUTE=10
ALIBABA_CLOUD_OCR_MAX_CONCURRENT=4
```

OCR 凭据必须属于独立、最小权限的 RAM 用户，只允许调用系统实际使用的 OCR 接口。任何曾出现在聊天、工单、日志或源码中的 AccessKey 都应视为已泄露：先在阿里云控制台禁用并轮换，再把新值写入服务器环境文件。环境文件不得上传到项目目录。

创建 `/etc/systemd/system/light-mes.service`：

```ini
[Unit]
Description=Light MES backend
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/opt/light-mes
EnvironmentFile=/etc/light-mes/light-mes.env
ExecStart=/usr/bin/java -jar /opt/light-mes/light-mes-backend.jar
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

授权并启动：

```bash
sudo chown -R www-data:www-data /opt/light-mes
sudo systemctl daemon-reload
sudo systemctl enable --now light-mes
sudo systemctl status light-mes --no-pager
```

## 5. 部署前端和 nginx

```bash
sudo mkdir -p /var/www/light-mes
sudo rsync -a --delete dist/ /var/www/light-mes/dist/
sudo chown -R www-data:www-data /var/www/light-mes
```

复制 `docs/deploy/nginx-mes-standalone.conf` 到 nginx 站点目录，至少修改：

- `server_name`。
- `ssl_certificate` 和 `ssl_certificate_key`。
- 静态目录与实际部署路径不一致时修改 `root`。

```bash
sudo cp nginx-mes-standalone.conf /etc/nginx/conf.d/light-mes.conf
sudo nginx -t
sudo systemctl reload nginx
```

首次申请证书时，可先使用只监听 80 的临时站点完成域名验证，再执行：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d mes.example.com
```

Spring Boot 的 8080 端口只需监听服务器本机或由防火墙限制访问；公网仅开放 80 和 443。若后端使用其他 `MES_HTTP_PORT`，必须同步修改 nginx 的 `proxy_pass`。

## 6. 验收

```bash
# 服务状态
systemctl is-active postgresql light-mes nginx

# 后端健康检查：使用部署后已修改的管理员凭据
curl -sS http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"userName":"<管理员账号>","password":"<管理员密码>"}'

# nginx 与 SPA
curl -I https://mes.example.com/
curl -I https://mes.example.com/assets/
```

浏览器验收至少覆盖：登录、菜单权限、一个档案面板、一个业务单据、扫描填单的拍照/上传与确认回填、审批历史和一个报表。开发者工具中的业务请求必须全部指向本站 `/api/*`。手机拍照入口应通过 HTTPS 站点验收。

## 7. 更新与回滚

更新前完成数据库备份，并保留上一版 jar 和前端目录：

```bash
sudo cp /opt/light-mes/light-mes-backend.jar \
  /opt/light-mes/light-mes-backend.jar.previous
sudo cp -a /var/www/light-mes/dist /var/www/light-mes/dist.previous
```

替换产物后执行：

```bash
sudo systemctl restart light-mes
sudo nginx -t && sudo systemctl reload nginx
sudo journalctl -u light-mes -n 100 --no-pager
```

回滚时恢复上一版 jar 和 `dist`；只有数据库变更不向后兼容时才恢复数据库备份。恢复前先停止写入，并确认备份时间点和影响范围。

## 8. 安全与脚本说明

- 首次登录后立即修改初始化管理员密码。
- 数据库密码和 JWT 密钥只通过服务器环境文件或凭据服务提供，不写入仓库和命令历史。
- OCR AccessKey 只由后端环境变量或凭据服务注入；前端、接口响应和日志均不得包含 AccessKey，图片内容和未匹配的识别原文也不得写入日志或返回浏览器。
- 证书、私钥和数据库备份不进入项目目录。
- 定期检查 `journalctl`、nginx 日志、磁盘空间和 PostgreSQL 备份可恢复性。
- `deploy-auto.ps1`、`deploy-incr.ps1` 和 `deploy-route1.sh` 是历史环境辅助脚本，包含环境假设；使用前必须审查目标、凭据、数据库覆盖策略和回滚方案，不能直接当作当前生产标准执行。
