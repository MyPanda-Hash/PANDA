# 项目群聊界面 · 设计系统（Ant Design v6.6.8）

> 适用：`frontend-group/index.html` + `app.js` + `app.css`（AI 数字员工的项目群聊页）。
> 设计库：`~/.dsh/design-kits/antd`（antdVersion 6.6.8），取值为 `dsh-kit token` 实查结果。

## 1. 骨架

三栏工作界面（不是营销页）：

```
┌ topbar 48 ─────────────────────────────────────────────┐
│ ← 返回   项目群聊                      铃铛 · 账号菜单   │
├ 左侧 264 ┬ 中间自适应 ────────────────┬ 右侧 300 ───────┤
│ 我的项目群│ 群头 56（头像/名称/成员数）  │ 成员 / 我的待办  │
│ 群列表    │ 消息流（气泡 8px 圆角）      │ 列表（1px 分隔）  │
│          │ 输入区（focus 主色描边）      │                 │
└──────────┴─────────────────────────────┴─────────────────┘
```

断点：≥1025 三栏 / 901–1024 两栏 / ≤900 右栏收抽屉 / ≤640 单栏（群切换改下拉）。

## 4. 硬规则落地

1. 卡片 0 层用 1px 边框，不叠阴影；只有弹窗/浮层用 `boxShadowSecondary`。
2. 8pt 网格：栏间距 8、面板内边距 12/16/24。
3. 控件高 32、圆角 6（容器 8）、正文 14/22。
4. 同一操作区只有一个主按钮（群头是「AI 整理待办」，输入区是「发送」）。
5. 时间、计数、序号一律 `font-variant-numeric: tabular-nums`。
6. 空态给下一步（「还没有项目群 → 新建」）。
7. 不用装饰渐变、不用大色块填充、不卡片套卡片。

## 7. 气泡前景色规则（2026-11-13 修正）

**规则：气泡的前景色跟着自己的底色走，不能按「谁发的」写死。**

| 气泡 | 底色 | 前景 |
|---|---|---|
| 我的（`.msg-row--mine .bubble`） | `colorPrimaryBg`（明 `#e6f4ff` / 暗 `#15325b`） | `colorText`（明 `rgba(0,0,0,.88)` / 暗 `rgba(255,255,255,.85)`） |
| AI / 他人（`.bubble`） | `colorBgContainer` + 1px `colorBorderSecondary` | `colorText` |
| 回执「未读/已读」 | 跟随气泡 | `colorTextTertiary`，已读用 `colorPrimary` |
| 引文条 | `colorFillTertiary` | `colorTextSecondary` |

踩过的坑：旧规则把「我的气泡」写成 `background: var(--accent); color: #fff`（微信绿底白字）。
设计库升级只换了底色（改成浅蓝）没换前景色，结果**浅色主题下白字压在浅蓝底上几乎看不见**。
现在已删掉那条旧规则，前景色统一在设计库层用 token 定义；实测明色 `rgba(0,0,0,.88) / #e6f4ff`，
暗色 `rgba(255,255,255,.85) / #15325b`。

## 8. 头像与个人设置（2026-11-14）

### 能改什么

右上角账号菜单 → **个人设置**：

| 项 | 交互 | 落点 |
|---|---|---|
| 头像 | 上传（PNG/JPG/WEBP/GIF/BMP，≤5MB）、移除 | `backend/uploads/avatars/<user_id>.png`（居中裁切 256×256） |
| 昵称 | 输入 + 保存/回车 | `users.display_name`（`PATCH /api/auth/display-name`） |
| 外观 | 浅色 / 深色 / 跟随系统 | `localStorage.dnx-theme` + `:root[data-theme]` |
| 消息字号 | 小 13 / 标准 14 / 大 16 | `localStorage.dnx-chat-font` → `--chat-font`，只影响正文与输入框 |

### 为什么头像不进数据库

「有没有头像」= 文件在不在，「换没换」= 文件 mtime。省一次迁移，换头像立刻生效：

- `POST /api/auth/avatar` → PIL 校验格式、居中裁成 256×256 PNG 落盘，返回 `avatar_url`
- `DELETE /api/auth/avatar` → 删文件
- `GET /api/users/{id}/avatar` → `FileResponse` + `Cache-Control: private, no-cache` + `ETag`（mtime）
- `/api/auth/me`、群成员、群消息三处响应都带 `avatar_url` / `sender_avatar_url`

### 前端渲染约定

所有头像走同一个 `avatarNode(className, name, url, { ai })`：

- 有 `avatar_url` → `<img loading="lazy">`，加载失败自动回退姓名首字
- AI 助手恒为 `AI` 字样（不走图片）
- 顶栏 24px、消息/成员 28px、设置面板预览 64px，圆角统一 6（容器）/ 8（预览）

### 鉴权注意

群聊页是 **cookie 会话**，聊天页是 **Bearer**。头像与昵称两个接口都改成
`current_user_from_bearer_or_cookie`，否则群聊页里点保存会 401（踩过）。

## 9. 人力地图（2026-11-16）

群成员面板原来只有一行头像 + 名字 + 群角色，看不出「这个人是哪个部门的」，
邀请弹窗里同角色的人更是分不清。这一版把组织关系接进群聊。

### 数据从哪来

部门数据的唯一来源是 MES（`sys_dept` / `sys_user.dept_id`），AI 不复制一份：

| 层 | 落点 |
|---|---|
| MES 只读接口 | `GET /api/open/org/map`（`X-Open-Api-Token` + IP 白名单 + 限流，与 `/api/open/biz/*` 同一套门禁） |
| AI 客户端 | `MesClient.org_map()` → `_open_get("org", "map")` |
| AI 服务 | `app/services/org_map.py`：60 秒缓存 + 账号映射 + 降级 |
| 接口字段 | 群成员、`/groups/{id}/org-map`、`/groups/directory-users` 三处都带 `dept_id` / `dept_name` / `dept_path` / `position` |

**账号映射有回退**：先看 `mes_user_bindings.mes_username`，没有绑定就按同名
`users.username` 试一次（种子账号两边同名），仍对不上归入「未分配部门」，不猜。

**降级不是错误**：MES 没开开放接口、没配令牌或临时挂了，成员列表照常渲染，
只是没有部门分组；`org-map` 失败只让 `state.orgMap = null`，不影响群聊本身。

### 视图结构

成员页签内分两种看法，选择存 `localStorage.dnx-member-view`：

| 视图 | 内容 | 用途 |
|---|---|---|
| 人力地图（默认） | **组织架构树**：MES 的部门层级原样搬过来，成员挂在各自部门下 | 看清「谁在哪个部门、部门下还有没有下级」 |
| 平铺 | 一行一人，副标题显示「部门 · 岗位」 | 快速找某个人 |

**为什么是树而不是分组列表**：分组列表只能表达「一级部门」，`公司 → 生产部 → 熔铸车间`
这样的层级会被拍平；用户在 MES 组织架构里看到的是树，群聊里也应该一致。
语义与 MES 的 `el-tree`（`default-expand-all`）对齐：缩进 + 展开箭头 + 全量部门。

树的三条规则：

- **全量部门都在**：空部门（采购部、轧制/精整/测试车间）照样显示，名字压暗、人数 `0`。
  组织架构图要看得见编制；人少的部门凭空消失会让人以为组织被改了。
- **先人后下级**：某个部门的直属成员排在下级部门之前。反过来的话，最后一个子部门
  会把上面的人「认领」走（踩过：李计划看起来挂在了测试车间）。
- **人数是含下级的合计**：父部门显示「这个体系一共几个人」，直属 0 但下级有人的部门
  显示 0 会误导。服务端已按树先序返回，前端不重排。

其他约定：

- **可折叠**：有成员或下级的部门行可点，折叠态记在 `localStorage.group.orgCollapsed`；
  空部门也一样能展开看结构（默认展开）。
- **树里的成员行**：副标题只显示岗位（部门已在节点上），路径放 `title`。
- **AI 助手单独成组**：它不是员工、没有部门，但确实是群成员，放进「常驻助手」
  固定组，不混进部门层级；群里只有 AI 助手时不铺空架构图。
- **未分配部门单独成组**：挂在树后面的普通分组，不伪装成部门节点。

### 邀请弹窗

候选按部门路径分组（`公司 / 仓储部` 之类），同组显示人数；行内保留
`姓名（账号）` + `部门 · 岗位`，已在群的显示「已加入」而不是邀请按钮。
排序规则：部门路径字典序，「未分配部门」永远最后。

## 10. 待办弹层的 macOS 式展开（2026-11-16）

需求原话是「做成和 Mac 上一样有微弧度展开的效果」。macOS Big Sur 之后的
sheet / 弹出层有三件事一起做，缺一件就会退回成普通网页对话框：

| 动作 | 数值 | 说明 |
|---|---|---|
| 圆角收拢 | 30 → 16（120 ms 时约 17.7） | 展开时圆角更大、落定收圆，这就是「微弧度」的来源 |
| 缩放落下 | `scale .90 → 1`、`translateY -14 → 0` | 从触发点右上角方向进入（`transform-origin: top right`） |
| 时长与缓动 | 360 ms，`cubic-bezier(.32,.72,0,1)` | Apple 常用缓动，先快后慢、不带弹跳 |
| 遮罩 | `rgba(4,6,10,.55)` + `backdrop-filter: blur(6px) saturate(1.1)` | 深色下压暗 + 模糊，让弹层"浮"起来 |
| 背景下沉 | `body.sheet-open .topbar/.layout { transform: scale(.992) }` | 父界面轻微缩小；这一步最能拉开层次 |
| 阴影 | 三层：内高光 1px + 0 28px 72px + 0 10px 28px | 0 层卡片不加阴影，弹层可以 |
| 收起 | 0.2 s `cubic-bezier(.4,0,1,1)`，圆角回到 24 再消失 | 反向略快，避免拖沓 |

实现要点：

- **原生 `<dialog>` 默认 `display:none`**，直接 `close()` 看不到收起过程。所以
  `openSheet()` 先 `showModal()` 再加 `.is-opening`，`closeSheet()` 先加
  `.is-closing`、等 `animationend` 再 `close()`，并用 `setTimeout` 兜底（动画事件丢
  了也要关掉）。Esc 走 `cancel` 事件同样进入收起动画。
- **类名驱动**，不把状态压在 CSS 选择器里，关闭时能精确清 `body.sheet-open`。
- **`prefers-reduced-motion: reduce`** 时动画降到 0.01 s、背景不缩放。

验收（2026-11-16，Chrome 156 实测）：

| 检查 | 结果 |
|---|---|
| 落定态 | 圆角 16、`transform-origin` 在右上、遮罩 `blur(6px) saturate(1.1)` |
| 中途帧 | 80 ms 圆角 19.9 / scale .972；180 ms 16.6 / .995；280 ms 16.1 / .999 |
| 关闭后 | `dialog.open === false`，`body.sheet-open` 已移除 |
| 1440 / 375 | 无横向滚动；375 下弹层 341×778、圆角 16 |
| 帧截图 | `_scratch/group-org-map-20261116/sheet-expand-frames.png`、`sheet-host-375.png` |

只作用于待办事件弹层（`.dialog--sheet`）。邀请成员、个人设置仍是 antd 规范
的 8px 圆角对话框；要统一成 macOS 手感的话，给对应 `<dialog>` 加同一个类即可。

### 10.1 窗口行为：可拖动 / 可缩放 / 可固定（2026-11-16 追加）

待办弹层从「模态对话框」改成了「类 macOS 浮窗」，因为需求要的是**页面和窗口一起用**：
拖到旁边、边看群消息边处理待办。

| 能力 | 交互 | 落点 |
|---|---|---|
| 拖动 | 按住标题栏拖 | 位置记 `localStorage.group.eventsSheet` |
| 缩放 | 四边 + 四角共 8 个手柄 | 尺寸同上；最小 420×340，且整窗必须在视口内 |
| 固定 | 标题栏图钉（`aria-pressed`） | 固定后点页面别处不收起；再点解除 |
| 最大化 | 双击标题栏 | 铺满视口留 8px，再双击还原到原尺寸 |
| 关闭 | 标题栏 ×、Esc、铃铛再点一次、未固定时点页面别处 | 都走收起动画 |

实现要点与踩过的坑：

- **改成非模态**：`showModal()` 会吞页面交互并带遮罩，与「边拖边看」冲突；现在用
  `show()`，页面照常可点。代价是 `cancel` 事件不触发，Esc 得自己接。
- **`overflow` 分层**：手柄要比窗口边缘外露 3px，而窗口内容要按 16 圆角裁剪。
  放在同一层会被裁掉、点击落到页面上（表现为「一拖角就关窗」）。现在外层的
  `<dialog>` 负责定位与动画、内层 `.sheet` 负责圆角/边框/阴影/裁剪，手柄挂外层。
- **夹取要夹整窗**：只夹左上角时，拖动后右下角会跑出视口，手柄点不到。现在
  `sheetClampRect` 同时约束 `left/top + width/height` 不超出 `innerWidth/innerHeight`。
- **手机上不做浮窗**：`<640px` 时默认铺满（`vw-16 × vh-72`），缩放手柄隐藏；
  最小尺寸跟着视口让路，避免 420 的最小宽把 375 屏撑出横向滚动。
- **层级**：窗口 `z-index: 50`，高于侧栏和列表，低于全屏员工知识库（60）。
- **拖动/缩放期间**给 `body` 加 `sheet-dragging` / `sheet-resizing`，禁掉文字选中，
  光标保持 grabbing / 对应方向。
