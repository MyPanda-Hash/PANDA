## 11. 文档维护规则

1. 规范性内容写入对应规范文件；工作过程和验证证据写入日志，不在两处重复维护。
2. 当前行为以“生效”文档为准；“调研基线”和“历史记录”只解释来源与演进过程。
3. 新业务面板先归入生产、库存、质量、审批或报表场景，再添加设计文件。
4. 文档统一使用 UTF-8、单一一级标题和 [文档编写规范](文档编写规范.md) 定义的排版。
5. 修改文档后运行 `node tools/docs-audit.mjs`，确保结构、编码、链接和归类完整。
