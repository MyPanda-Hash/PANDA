本文描述当前 Spring Boot + MySQL 后端。系统只保留 SQL 链路，不依赖外部 PanelX 服务，也不提供 Mock 运行模式。

## 1. 总体结构

```text
浏览器 /api/*
  -> SecurityConfig + JwtAuthFilter
  -> Controller
  -> Service
  -> MyBatis-Plus Mapper
  -> MySQL light_mes
```

| 层 | 主要实现 | 职责 |
|---|---|---|
| 配置与安全 | `config/` | JWT、Spring Security、CORS、分页和异常归一化 |
| 接口 | `controller/` | 参数接收和统一 `ApiResult` 返回 |
| 业务 | `service/` | 面板 CRUD、审批、权限、生单、报表和 Dashboard 聚合 |
| 数据访问 | `mapper/`、`entity/` | MyBatis-Plus 实体与查询 |
| 初始化 | `resources/db/init.sql` | 建库、建表和新环境种子数据 |

## 2. 数据权威源

| 表 | 用途 |
|---|---|
| `panel_config` | 面板字段、列表、按钮、状态和选单配置 JSON |
| `form_data` | 通用单据表头 `data`、明细 `detail_data` 和单据状态 |
| `form_approval` | 提交、通过、驳回和弃审记录 |
| `sys_user`、`sys_role`、`sys_role_panel` | 用户、角色、可见面板和审批权限 |
| `sys_dept` | 组织树与用户归属 |
| `sys_menu`、`factory` | 门户菜单和工厂信息 |
| `manu_order`、`manu_order_item` | 传统生产加工单接口使用的结构化业务表 |

运行库是当前配置和数据的权威源；`init.sql` 是新环境初始化基线。修改运行库后，应把可重复的结构和配置同步回初始化 SQL，避免新部署与现有环境漂移。

`form_data` 的业务唯一键是 `(panel_code, form_no)`。表头和明细 JSON 必须保持以下边界：

```json
{
  "panelCode": "MANU_ORDER",
  "编号": "MO-...",
  "单据状态": "草稿",
  "detail": {
    "products": [],
    "materials": [],
    "processes": []
  }
}
```

## 3. 接口分组

| 路径 | 主要职责 |
|---|---|
| `/api/auth/*` | 登录、当前用户和权限 |
| `/api/px/*` | 通用面板配置、查询、表单描述、按钮动作和删除 |
| `/api/dashboard/stats` | Dashboard 聚合数据 |
| `/api/sys/menu/*` | 菜单树 |
| `/api/sys/user/*`、`/api/sys/role/*`、`/api/sys/dept/*` | 组织和权限管理 |
| `/api/manu/order/*` | 结构化生产加工单接口 |
| `/api/portal/*`、`/api/base/factory/*` | 门户角标、公告和工厂信息 |

`PxController` 只做协议转换，通用面板规则集中在 `PxService`：

- `getPanelConfig`：读取并升级运行时配置。
- `getPermMatrix`、`getNewFormPermMatrix`、`getFormDescriptor`：生成页面权限和表单描述。
- `queryFormDataList`：按面板分类查询普通单据、单单据档案或报表。
- `callButton`：在事务中处理保存、状态变化、审批和推式生单。
- `deleteForms`：按面板编码和单号删除。

## 4. 创建和保存

1. 新建请求进入 `PxService.create/save`。
2. 后端按面板生成不重复的 `form_no`，并补齐单据日期、自动编号和配置默认值。
3. 新单状态默认为草稿；档案类面板按其启用规则保存。
4. 更新时以 `编号` 定位原记录。请求未携带明细时保留原 `detail_data`，禁止写成空值。
5. 保存前完成必填、编号、来源单和业务约束校验。

编号生成不得使用记录总数推算。新增前缀在 `PxService.generateFormNo` 登记，并依赖数据库唯一键处理并发冲突。

## 5. 状态与审批

```text
草稿 --审核--> 已审核 --弃审--> 草稿
草稿 --提交审批--> 审批中 --审批通过--> 已审核
                         +--审批驳回--> 草稿
已审核/生产中 --手工完工--> 已完工
可执行状态 --中止--> 已中止 --取消中止--> 草稿
```

- 所有状态变化由后端再次校验，前端置灰不能代替服务端规则。
- 提交、通过、驳回和弃审写入 `form_approval`，操作人从当前 JWT 身份取得。
- 审批通过和驳回需要当前角色对该面板拥有审批权限。
- BOM 等特殊面板的业务校验在状态写入前执行；失败时整个 `callButton` 事务回滚。

## 6. 选单与生单

选单配置存于目标面板的 `selectConfig`，来源单查询必须限定为已审核。表头、明细和编码映射由配置描述，后端负责最终有效性检查。

推式生单由 `PxService.callButton` 分发到 `createXxxFromYyy`：

1. 校验来源单存在且状态允许。
2. 校验所需明细非空。
3. 映射目标表头和明细，并补齐必填默认值。
4. 通过 `insertGenerated` 创建目标草稿。
5. 返回目标 `panelCode` 和新编号供前端定位。

新增流转时不得只加前端按钮；必须同时加入服务端分支、来源状态校验、字段映射、编号前缀和回归测试。

## 7. 参照、单单据和报表

- 基础档案参照也通过 `/api/px/queryFormDataList` 查询，不建立前端本地选项副本。
- `metadata.singleDoc=true` 的档案只保存一张 `form_data`，数据行位于首个明细页签。
- `ReportPanelRegistry` 定义只读报表配置；`ReportQueryService` 从当前已生效业务单据构建报表行。
- 报表查询默认忽略草稿等未生效状态，分页上限由服务端控制。
- Dashboard 通过 `DashboardController` 聚合业务单据、待办、进度和档案统计。

## 8. 身份、权限与错误

- `/api/auth/login` 和登录页所需的工厂列表允许匿名访问，其余接口需要 JWT。
- 密码使用 BCrypt；服务端无状态，不创建 HTTP Session。
- 管理员角色拥有全部面板和审批权限；普通角色由 `sys_role_panel` 控制可见面板和 `can_approve`。
- JWT 密钥必须由 `MES_JWT_SECRET` 覆盖，数据库凭据通过 Spring 环境变量注入。
- `IllegalArgumentException` 映射业务码 400，`IllegalStateException` 映射业务码 409，其他异常映射业务码 500；客户端同时检查 HTTP 状态和 `ApiResult.code`。
- 日志和异常消息不得输出密码、Token、Cookie、完整连接串或敏感业务数据。

## 9. 后端扩展清单

1. 确定功能属于通用 `PxService`、专属 Service 还是只读报表。
2. 先定义数据权威源和唯一键，再实现接口。
3. 写操作放入事务，校验发生在落库前。
4. 新面板同步 `panel_config`、`init.sql`、角色可见性和编号规则。
5. 新审批面板同步审批集合、状态矩阵和权限测试。
6. 新生单链路覆盖成功、来源未审核、来源不存在和明细为空场景。
7. 运行后端打包，并通过 `node tools/verify-project.mjs` 做整体验证。
