# light-mes 代码分层规范（通用引擎层 / 业务层）

| 属性 | 内容 |
|---|---|
| 文档类型 | 开发规范 |
| 适用场景 | 通用架构与 SDK |
| 维护状态 | 生效 |
| 最后整理 | 2026-08-24 |
| 文档导航 | [文档中心](README.md) |

> 目标：把「写一次、处处复用」的引擎代码与 MES 业务代码彻底分开，为后续抽包（npm 包 / Spring Boot starter）打地基。

## 一、分层总览

```
┌─────────────────────────────────────────────────────────┐
│ 业务层 business/  （每个项目只写这一层）                  │
│   面板配置 engine.js · 业务接口 api.js · 菜单 menus.js   │
├─────────────────────────────────────────────────────────┤
│ 壳层（本项目定制，通用性中等）                            │
│   layout/ 门户壳 · views/ 业务页面 · stores/ · router/  │
├─────────────────────────────────────────────────────────┤
│ 通用引擎层 core/  （写一次，跨项目复用）                  │
│   env.js 模式开关 · request.js · sdk.js · panel-engine.js│
│   views/ 引擎视图（列表/表单/参照弹窗/登录）             │
└─────────────────────────────────────────────────────────┘
```

依赖方向（只能向下）：

```
business ──→ core          （允许）
壳层     ──→ business/core （允许）
core     ──→ business      （禁止！）
```

## 二、前端分层（frontend/src/）

### core/ —— 通用引擎层

| 文件 | 职责 | 说明 |
|---|---|---|
| `env.js` | 运行模式开关（USE_MOCK / USE_PANELX / USE_PANELX_PROXY…） | 由 Vite 环境变量决定，业务层转发使用 |
| `request.js` | axios 基建（baseURL / token 拦截器 / 错误处理） | 从 api/ 迁入 |
| `sdk.js` | PanelX SDK 封装 + 后端代理伪 SDK | 从 panelx/ 迁入 |
| `panel-engine.js` | 面板引擎内核：unwrap/errMsg/mapType/parseJson/adaptPanelConfig/adaptMeta/adaptFormData/panelxButtonGroups/platformCall | 从 engine.js 抽取 |
| `views/` | 引擎视图：PanelxList / PanelxForm / PanelxLogin / NewVoucherDialog / RefPickDialog | 由面板配置驱动，与业务面板解耦 |

**规则（core/ 内强制）**：
1. 禁止 import `@/business/**` 或任何业务文件
2. 新增通用能力只进 core/；业务配置只进 business/
3. 面板码映射、面板注册表由业务层持有（core 不写死任何业务面板码）

### business/ —— 业务层（MES 专属）

| 文件 | 职责 |
|---|---|
| `engine.js` | 面板配置注册表 + 分发链 + mock 数据 + 平台面板码映射（PANEL_MAP） |
| `api.js` | 业务接口封装 + 门户 mock 数据（原 api/index.js） |
| `menus.js` | MES 菜单树（原 config/menus.js） |

### 壳层（暂留在原位置）

- `layout/`：T+ 门户壳（通用性中等，含 T+ 定制 token，抽包时参数化）
- `views/`（login/dashboard/modules/error）：业务页面
- `stores/`：`tabs.js`、`app.js` 已通用（可迁 core），`user.js` 属业务
- `router/`、`styles/`：项目编排层

## 三、后端分层（com.mes/）

### 通用引擎层（将来抽 mes-engine-starter）

| 类 | 说明 |
|---|---|
| `PxController` / `PxService` | 本地面板引擎（配置驱动 CRUD） |
| `PanelxController` / `PanelxService` / `PanelxGateway` / `PanelxConfig` / `PanelxProperties` / `PanelxApiException` | PanelX 平台网关 |
| `entity/PanelConfig`、`entity/FormData` + mapper | 元数据驱动数据表 |
| `dto/ApiResult` | 统一返回体 |
| `config/GlobalExceptionHandler`、`MybatisPlusConfig` | 通用基建 |

### 业务层

| 类 | 说明 |
|---|---|
| `ManuOrder*`、`SysUser`、`SysMenu`、`Factory` 全套 | MES 业务模块 |
| `AuthController`、`PortalController`、`MenuController`、`FactoryController` | 门户业务接口 |
| `dto/LoginRequest`、`LoginResponse` | 业务 DTO |
| `resources/db/init.sql` | 业务建表 + 种子数据 |

## 四、已知耦合点（待拆清单）

| 耦合点 | 现状 | 拆法 |
|---|---|---|
| `core/views/*` import `@/business/engine` | 引擎视图依赖业务注册表 | 抽包时改为「引擎对象注入」（初始化时传入 engine） |
| `core/sdk.js` 的 `PANELX_CONFIG` 默认指向 demo.kwaidoo.com | core 内含平台默认值 | 业务层初始化时覆盖 |
| `layout/` 含 T+ 硬编码 token（#289be5 等） | 壳层绑定 T+ 皮肤 | 抽壳时提取主题配置 |
| `stores/app.js`/`tabs.js` 与 `user.js` 混放 | 通用/业务状态同目录 | phase 2 拆分 |

## 五、抽包路线图

- **Phase 1（本次已完成）**：core/ 与 business/ 物理分离 + vite 别名 `@core` + 内核抽取
- **Phase 2**：core/ 抽独立包（npm workspace 或独立仓库 `light-mes-core`）；后端引擎抽 `mes-engine-starter`；stores 拆分
- **Phase 3**：面板配置外部化（后端下发 / JSON 文件），新项目 = 引包 + 配面板 + 写 Service

## 六、维护规则

1. 业务代码禁止写进 core/；core/ 新增文件必须通过「无业务 import」检查
2. 新面板 = 配置（business/engine.js 或后端 panel_config），不写新页面组件（除非引擎不支持的新控件 → 先加到 core/views）
3. 任何改动验证：前端 `vite build` + 后端 `mvn package`（不通过不提交）
