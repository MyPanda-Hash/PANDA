# 轻 MES × 数字员工：会查、会写、会提醒的制造业务工作台

> 一句话：把"配置驱动的轻 MES"从记单据的系统，升级成能读懂资料、能查业务数据、能自动成稿、能按时提醒的车间数字员工。
> 结构化事实仍由 MES 独占（单据、审批、库存、质量链路），数字员工只负责理解、检索、成稿与提醒，不直接改账。

## 一、为什么要把两者结合

| 现状痛点 | MES 单独做不到 | 数字员工单独做不到 | 结合后的效果 |
|---|---|---|---|
| 工艺卡、检验标准、客户规范散在共享盘 | 只能存单据字段 | 有文档库但没有业务上下文 | 问"这个件首检按哪条标准"，直接带标准原文与条款出处回答 |
| 质量问题要人翻单据、拼周报 | 数据齐但要人查、人抄 | 会写但没有数据 | 选时间段，自动拉检验数据 + 不合格品记录，出质量周报草稿 |
| 生产日报靠班长手填 | 有数据没有表达层 | 有模板没有数据源 | 每天 8:00 自动汇总并推送到企业微信/钉钉 |
| 新人上手靠带 | 有单据流程没有解释 | 会解释但看不到单据 | 对着真实单据问"这张单下一步该谁审"，给出依据 |
| 汇报材料临时抱佛脚 | 有报表没有设计 | 会做 PPT 没有口径 | 从 MES 口径直接生成月度汇报 PPT/PDF |

结论：MES 是**事实源**，数字员工是**表达层 + 知识层**。两者不重叠，删掉任何一个都不成立。

## 二、能力拼图

### 2.1 MES 提供（已具备）

| 能力 | 说明 |
|---|---|
| 配置驱动面板 | 列表 / 表单 / 明细 / 参照 / 选单 / 导入 / 审批共用一套运行时，面板与按钮由 `panel_config` 驱动 |
| 单据与审批 | 审批状态与审批记录同事务推进；最近一条待审批提交为判据；已审批判定统一用 `isDocApproved()` |
| 生单与选单 | 生单推式（按钮动作落库并返回新编号）、选单拉式（来源须已审核） |
| 库存口径 | 以 `STOCK_STATUS` 实时聚合，禁止静态现存量快照 |
| 质量链路 | `ARRIVAL_IN / FINISH_INSPECT / FIRST_INSPECT / PROCESS_INSPECT_APPLY → INSPECTION / PROCESS_INSPECTION → PURCHASE_IN / FINISH_IN` |
| 权限 | 11 项动作（view/query/add/edit/delete/export/print/audit/price/review/adjust），角色-面板按动作授权 |
| 已有 AI 入口 | 扫描填单：`POST /api/ocr/scan-form` + `OcrFormMapper`，识别结果必须人工确认才落库 |
| 工程约束 | 中文数据键跨端契约、表格列偏好、显示层 i18n（`tt()`）、375/768/1440 响应式 |

### 2.2 数字员工提供（已在本地实例验证）

| 能力 | 落地形态 |
|---|---|
| 对话式工作台 | 流式回复、多会话、聊天历史检索、用户记忆 |
| 空间与文档库 | 空间隔离的文档、临时附件、上传策略（本地实例已关闭 MinIO 分支） |
| 文档理解 | PDF/Word/Excel/PPT/图片解析；LibreOffice + poppler 预览；Tesseract 中文 OCR（`chi_sim+eng`） |
| 混合检索与溯源 | 词法 + 知识图谱 + 向量（sqlite-vec）融合；回答带引用，可 `expand_citation` 回到原文 |
| 实体与项目上下文 | `match_entities`、`get_project_context`、`get_chat_history_context` |
| 智能体工具集 | 约 30 个 `nexus_*` 工具：列空间/文档、检索证据、预览文档、读图/读演示、会话摘要、用量与系统概览、交付文件、日程提案等；另有 `browser_read_page` 与 `http_request` |
| 生成与交付 | 内置技能：`dashi-ppt`（12 套主题 PPT）、`pptx`（python-pptx 编辑与渲染验收）、`minio-upload`（同名下载链接）、`agent-browser`（网页读取）、`open-meteo-api`（天气/环境数据）；线上版本另含标书/方案/报价/报告类写作技能 |
| 定时与提醒 | 日程提案（`nexus_propose_schedule`）+ 定时运行，可推送钉钉 / 企业微信 |
| 治理 | 角色与权限申请、数据审计、用量与预算（单次运行成本上限、并发准入队列）、模型端点与密钥管理 |
| 多媒体 | AVATAR 级语音：TTS（`x4_yezi`）/ ASR；图片生成与视频生成接口 |

## 三、六个典型场景

| # | 场景 | 谁用 | 输入 | 输出 | 状态 |
|---|---|---|---|---|---|
| 1 | 标准与工艺问答 | 检验员、工艺员、班组长 | 检验规范、工艺卡、客户标准入库 | 带条款出处的答案，可点开原文 | 文档侧**直接可用**，需导入资料 |
| 2 | 单据问答与待办解释 | 班组长、计划员 | 单据号或自然语言描述 | "这张单卡在哪、下一个审批人是谁、依据哪条规则" | **需对接** MES 只读查询 |
| 3 | 质量周报/8D 草稿 | 质量工程师 | 时间段 + 产品线 | 汇总表 + 原因分析草稿 + 整改建议（人工定稿） | **需对接** + 写作技能 |
| 4 | 生产日报定时推送 | 车间主任 | 每日 8:00 触发 | 产量/异常/待审单据摘要，推到企业微信或钉钉 | **需对接** + 定时任务 |
| 5 | 月度汇报材料 | 厂长、经营层 | 指标口径 + 时间范围 | PPT/PDF，含图表与口径说明 | 生成侧**直接可用**，数据需对接 |
| 6 | 扫描录单校验 | 仓管、检验员 | 拍照/上传单据 | OCR 预填字段 + 数字员工提示"疑似超差/缺项"，人工确认后落库 | MES 已有 OCR；**增强需对接** |

## 四、集成设计要点（这是要做的开发）

1. **只读查询工具化**：把 MES 现有面板查询、单据明细、库存聚合、质量链路查询封装成若干 `nexus_*` 工具，schema 直接来自 `panel_config`（中文数据键即事实源，避免模型编字段）。
2. **写操作只出草稿**：任何新增/修改/审核一律产出"待确认草稿 + 操作预览"，落库仍走 MES 按钮动作与审批门禁，数字员工没有直连写权限。
3. **权限贯通**：数字员工侧按 MES 的 11 项动作与角色-面板矩阵裁剪工具可见性；建议单点登录（MES 签发 → 数字员工校验），审计两边都留痕。
4. **口径对齐**：库存取 `STOCK_STATUS` 实时聚合、已审批取 `isDocApproved()`，禁止在提示词里另立口径。
5. **部署形态**：MES（Spring Boot + MySQL）与数字员工（FastAPI + 模型运行时 + nginx）同机或同域反代；本机已验证：`nginx:18091 → backend:8000`，SQLite/PG 二选一（生产建议 PostgreSQL）。
6. **成本与限流**：单用户并发、单次运行成本上限、模型端点限流必须开启，日报/周报类定时任务设预算硬停。

## 五、边界（对外要讲清楚）

- 数字员工**不替代审批人**，不直接改账、不改配置、不越权读别人的空间。
- 结构化数据以 MES 为唯一事实源；库存、审批状态不允许出现第二份快照。
- 所有结论必须可溯源：有引用就带链接/单据号，没有来源就明说"查不到"。
- 私有化部署：资料、单据、对话不出内网；模型端点可指向内网推理服务。
- 权限不足、数据为空、模型不可达都必须给中性提示，不静默失败。

## 六、分阶段落地建议

| 阶段 | 范围 | 验收标准 |
|---|---|---|
| P0（1–2 周） | 资料入库 + 标准问答；质量/生产日报模板入库 | 20 份规范可检索，问答引用命中率可人工抽检通过 |
| P1（3–4 周） | MES 只读工具 5 个（单据查询、明细、库存、检验记录、待审列表） | 单据问答准确率 ≥90%，越权访问 0 |
| P2（4–6 周） | 定时日报推送 + 质量周报/汇报 PPT 生成 | 定时任务连续 5 天无失败，成稿人工修改率 <30% |
| P3 | 扫描录单增强、审批要点提示 | 录单耗时下降可量化，误判可回溯 |

## 七、一句话卖点（可直接对外）

1. **会查**：问的是业务问题，答的是带出处的数据，不是胡说八道。
2. **会写**：周报、汇报、标书、PPT 从 MES 口径直接成稿，人只做定稿。
3. **会提醒**：日报、待审、异常按时推送到人，不靠人记得去点。
