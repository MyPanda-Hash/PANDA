# 项目群聊（AI 数字员工内）

> 代码：`backend/app/models/group_chat.py`、`backend/app/services/group_chat.py`、
> `backend/app/services/group_assistant.py`、`backend/app/services/plain_llm.py`、
> `backend/app/api/group_chat.py`、`frontend-group/`
> 迁移：`alembic/versions/20261111_0102_project_group_chat.py`

## 1. 它解决什么

有账号的员工由**项目组长建群**、拉人进群，在群里发**文字、文档、图片、语音**。
群里常驻一个 AI 助手：读聊天记录、读附件正文，整理出**待办**，按角色派给具体成员，
成员的「我的待办」里就能看到、能标记完成。

## 2. 数据模型

| 表 | 作用 | 关键点 |
|---|---|---|
| `project_groups` | 项目群 | `owner_user_id` 组长，`status` = active/archived |
| `project_group_members` | 成员 | `role` = owner/manager/member，`last_read_message_id` 算未读 |
| `project_group_messages` | 消息 | `kind` = text/image/file/voice/ai/system，`parts_json` 放结构化片段 |
| `project_group_attachments` | 附件 | 本地磁盘存放，`extracted_text` 存抽出的正文 |
| `project_group_ai_runs` | 分析记录 | 成功失败都留痕，`error` 记录原因，便于重试 |
| `group_todos` | 待办 | `assignee_user_id` + `status`，带 `source_message_id` 可回溯 |

与个人对话（`chat_sessions`，按 `owner_user_id` 私有）**完全分开**。

**AI 助手是每个群的固定成员**：没有真实账号，由接口在成员列表里合成一条
（`role=assistant`，显示「AI 助手 / 常驻助手」）。所以新建群立刻就有助手在群里，
不需要额外邀请；它也不占用 `member_count` 的人力计数。

## 2.1 群的长期记忆

长对话不能全塞给模型，否则上下文爆掉、重点被稀释。做法是**滚动纪要**：

| 表 | 作用 |
|---|---|
| `project_group_memories` | 每个群一行：`summary`（≤300 字纪要）、`covered_message_id`、`covered_message_count` |

- 每次分析，模型可以返回 `memory`：把「已有纪要 + 这段新消息」合并成一段新纪要
- 存库时记下覆盖到哪条消息；**覆盖数是累计的**（上一轮已覆盖的 + 这轮新增的）
- 下次拼上下文时只给「纪要 + 纪要之后的消息」（最多 40 条），不再重复灌完整历史
- 群详情接口返回 `memory_summary` / `memory_message_count`，页面顶部显示「已记住前 N 条」
- 没有纪要时退回给最近 80 条原始消息

## 3. 权限

| 操作 | 谁能做 |
|---|---|
| 建群 | 任何已登录账号（建完即为组长） |
| 邀请成员 | 组长、管理员 |
| 任命管理员 | 只有组长 |
| 移除成员 | 组长可移除任何人；管理员只能移除普通成员；本人可自行退出 |
| 发消息 / 传文件 / 看历史 | 群成员 |
| AI 整理待办 | 群成员 |
| 归档 / 删除群 | 只有组长 |
| 改自己待办状态 | 被指派人；组长可关别人的 |

**群是成员制，系统管理员也不例外**：不加入就读不到任何消息（`require_member` 不判断 `user.role == "admin"`）。这是刻意的——后台管理员不该能静默翻阅项目讨论。

## 4. 接口

前缀 `/groups`，待办前缀 `/todos`。全部支持 `Authorization: Bearer` 或登录 cookie。

```
GET    /groups                          我的群（含未读数）
POST   /groups                          建群
GET    /groups/{id}                     群详情 + 成员
PATCH  /groups/{id}                     改群名/说明（组长或管理员）
DELETE /groups/{id}                     删群（组长）
POST   /groups/{id}:archive             归档（组长）
GET    /groups/directory-users?q=       邀请时搜账号
POST   /groups/{id}/members             邀请（组长/管理员）
DELETE /groups/{id}/members/{user_id}   移除/退出
GET    /groups/{id}/messages?after=&before=&limit=
POST   /groups/{id}/messages            发消息（text/file/image/voice，可带 reply_to_message_id）
DELETE /groups/{id}/messages/{mid}      撤回（本人 2 分钟内 / 组长管理员任意）
POST   /groups/{id}:read                上报已读到哪一条
POST   /groups/{id}/attachments         上传（≤25 MB，multipart；语音会自动转写）
POST   /groups/{id}/attachments/{aid}:transcribe   语音补转写（配好 key 后重试）
GET    /groups/{id}/attachments/{aid}   下载（仅成员）
POST   /groups/{id}:analyze             AI 整理待办（?sync=false 转后台）
GET    /groups/{id}/runs                分析历史（含失败原因）
GET    /todos                           我的待办
PATCH  /todos/{id}                      改状态 pending/accepted/doing/done/dismissed
```

## 5. AI 助手怎么工作

```
analyze_group()
  ├─ build_context()   最近 80 条消息 + 成员名单 + 每个附件的正文节选（1500 字）
  ├─ complete_chat()   走 data_guard 脱敏 → POST 端点 → 还原占位符
  ├─ parse_analysis()  强制 JSON；容忍 ```json 围栏；坏 priority 归 normal
  ├─ 指派解析          按成员「姓名/账号」精确匹配 → 退化到子串 → 再退化给组长
  ├─ 去重              同群同人同标题：未关闭的不重复建；7 天内刚完成的也不重建
  └─ 回群              发一条 kind=ai 的消息，parts_json 带 group_analysis 片段
```

**触发方式**（三类，命中任意一类就出手）：

| 类型 | 判定 | 例子 |
|---|---|---|
| 点名 | 含 `@AI` / `@助手` | `@AI 这周要做什么` |
| 问情况 | 含「进度/待办/谁/多少/什么时候…」或结尾是问号 | `最新的销售订单谁提交的？` |
| **安排事情** | 含任务动词（对接/排产/采购/发货/跟进/检验/补齐/补一下…） | `中天客户又要下单一批订单，销售去对接一下` |

第三类是最初漏掉的：一开始只认「提问」，导致**在群里安排工作完全没反应**——
陈述句没有问号也不含问句关键词，AI 根本没被唤醒。

纯闲聊（「好的收到」「嗯」「哈哈」）仍然不触发，避免刷屏。

**安排任务时**：即使没有问号，AI 也要把这件事整理成待办并指派给合适的人
（销售类给业务员、库存采购给仓管、排产给计划/车间、质检给质检员），
reply 回一句「已记录，派给 XX」。
找不到匹配角色时**不乱派**，派给组长并在风险里说明「群里没有仓管」。

**AI 回答什么**：`reply` 字段。触发时服务端会把**这句话本身**放到上下文末尾，
并标注「=== 需要你现在回答的这条消息 ===」，同时要求「只回答这条、不要复述清单、
不要重复上一轮说过的」。不这么做模型会把整段背景复述一遍——两条不同的问题得到
一模一样的回复（实测踩过）。

不同问法给的回答也不同：问「谁负责」就点名指派人或说明无人认领，问「还差什么」只列
未完成项，问「什么时候」报截止日期。上下文里固定带一段「待办概览」——

```
待办概览：未完成 3 条，已完成 1 条，其中逾期 1 条
  - [进行中] 确认机架图纸公差 / 王组员 / 11-20
  - [已完成] 补齐来料检验记录 / 李管理
```

所以它答「进度怎么样」时会报数量、报卡点、报谁在跟，而不是复述聊天记录。
`reply` 为空时（没人在问）才退回旧的「这轮没有新待办」模板。

**模型不可用时不编造**：没有端点返回 503；端点挂了返回 502 并把原因写进 run 记录，群里不会出现假待办。

## 5.1 群助手能查 MES 业务数据

**问题**：问「最新的销售订单谁提交的？」，AI 回答「聊天记录里没有，需要有人去系统里查」——
把问题推回给人，等于没解决问题。

**原因**：群助手只能读聊天记录、待办和成员名单，没有任何业务数据通道。

**改法**：给它一条只读的 MES 查询通道（`services/group_tools.py`）。

```
问题 → 关键词识别该查哪个面板 → 查 MES → 结果塞进上下文 → 模型作答
```

| 面板 | 触发词 |
|---|---|
| SO_ORDER 销售订单 | 销售订单、订单、客户下单、业务员 |
| MANU_ORDER 生产工单 | 生产工单、工单、排产、车间、加工单 |
| PU_ORDER 采购订单 | 采购订单、供应商 |
| ARRIVAL_IN 到货单 | 到货、来料、检验 |
| STOCK_STATUS 库存 | 库存、存量、仓库、缺料 |

单号（`SO-20261112-004` 这类）会直接定位面板并作为查询关键词。
闲聊不触发查询。

**为什么不靠模型自己决定要不要查**：试过让模型输出 `need_query`，它仍然回复
「我查不到」——模型倾向于保守作答。改成代码先查、把数据交给它，稳定得多。

**安全边界**：

- 只读，不写 MES
- **字段白名单**：每张单只回固定几列，`detail`（单据正文）、金额等一律不出去
- 复用主动监控那套凭据（`MES_OPEN_API_TOKEN`），未配置时明确报错而不是瞎猜

实测（销售一部群）：

```
问：最新的销售订单谁提交的？
答：最新的是 11-12 那 4 张单（SO-20261112-001~004，客户华东铝业、中天精工、
    西部材料），提交人都是 sales，业务员是王销售，审核人 planner，状态都已审核。
```

```
问：现在包装木箱库存有多少
答：MES 库存里没有包装木箱这一项，只查到 45#圆钢 5708.47、6061铝锭 8409.88…
    可能是没建编码或不在这个仓库。
```

第二条同样是「查了但没这条」，而不是「我查不到」。

## 6. 文件与语音

| 类型 | 处理 |
|---|---|
| `.txt/.md/.csv/.log/.json/.xml/.yaml` | 直接解码（utf-8 → gb18030），存入 `extracted_text`，AI 能读 |
| 图片 | 存盘 + 可下载；**不发给云端视觉模型**（遵守图片出网策略），AI 读不到画面内容 |
| 语音 | **上传时服务端自动转写**，转写结果同时作为消息正文，AI 直接读文字；未配 key 时 `pending`，可补转写 |
| 其它（pdf/docx/xlsx…） | 存盘可下载，`extract_status=skipped`，AI 读不到正文 |

**语音的处理方式**（2026-11-11 起）：

- 用户按住说话 → 浏览器录音 → 上传 → **服务端立即调 DashScope 转写**
  （`qwen-audio-3.0-asr-flash`，配置项 `DASHSCOPE_API_KEY`）
- 转写结果写进 `extracted_text`，同时**作为消息正文**，群里直接看到文字
- AI 读的是这段文字，不需要人去点「转写」或再发一次
- 未配 key 时消息附件标「未转写（语音识别未配置）」，音频仍可播放；
  配好后调 `POST /groups/{id}/attachments/{aid}:transcribe` 补转写，不用重录

**这是当前最大的限制**：正式需求里「分析文件」主要指 PDF/Word/Excel。要真正支持，需要把 `document_processor` 的解析能力接到附件抽取上（本地已有 LibreOffice/tesseract 镜像能力，但本机未装）。

## 7. 前端为什么是独立页面

`doc-nexus-ai/frontend/` **只有构建产物**（`dist/`，2.0 MB、44 个压缩 chunk、0 个 sourcemap），
没有源码，无法往里加页面。Docker 里也没有对应镜像（只有 mysql / azure-sql-edge）。

所以采用两层做法，**原 bundle 一个字节都不改**：

1. `frontend-group/`：一个无构建步骤的静态页（`index.html` + `app.css` + `app.js`），
   由 `serve-ai-web.mjs` 挂在 `http://localhost:18091/group`，复用同一个 `/api` 反代和登录 cookie。
2. `frontend-group/nav-inject.js`：由 `serve-ai-web.mjs` 在响应 `index.html` 时注入，
   运行时在侧边栏克隆一个导航项改成「项目群聊」。找不到导航栏时退化成左下角悬浮按钮。

好处：原应用升级不影响；不满意随时删掉 `serve-ai-web.mjs` 里那几行注入即可回退。

## 7.1 消息流交互（微信式）

群聊页按 IM 的常见习惯组织，减少一眼扫读的成本：

| 行为 | 说明 |
|---|---|
| 气泡朝向 | 自己的消息靠右、绿色气泡；别人的靠左、灰白气泡，带小尖角 |
| 头像与昵称 | 别人的消息显示头像和昵称；自己的不显示昵称 |
| 连续消息合并 | 同一人 5 分钟内连发，只画一次头像和昵称，气泡收紧 |
| 时间分隔 | 间隔超过 5 分钟或跨天时插入时间条（`10:08` / `昨天 16:53` / `11月8日 09:20`） |
| AI 消息 | 独立底色 + 「AI 助手」昵称，和人的消息区分开，但仍是一条气泡 |
| 贴底显示 | 消息少时从底部往上排；自己发消息后强制滚到底 |
| 输入区 | 左侧工具图标（文件/语音）+ 自动增高输入框 + 发送键；**Enter 发送 / Shift+Enter 换行**，空内容时发送键禁用 |
| 语音 | 录制时按钮变红并显示计时，停止后自动上传、转写、发消息 |
| 表情 | 输入区右侧笑脸按钮，48 个常用符号，插入到光标处 |
| @ 提及 | 输入 `@` 弹出成员列表（支持边打边筛），点选插入「@姓名」 |
| 引用 | 右键/长按消息 → 引用，输入框上方出现引用条，发出去带引用块 |
| 撤回 | 本人 2 分钟内可撤；组长/管理员可撤任意消息；撤回后留一条系统提示 |
| 图片 | 点缩略图弹大图；附件点击在新窗口打开原图 |
| 已读回执 | 自己的消息下方显示「已读 N / 未读」：N = 已读到该条的其他成员数 |
| 未读分割 | 进入群时在第一条未读消息上方显示「以下为新消息」，看到底部自动上报已读 |

**已读回执**：自己的消息下面显示「未读 / 已读 N/M / 全部已读」，M 是除自己外的成员数。
滚到底自动上报读到的最后一条，不逐条记已读，避免消息多时写放大。

「已读」的口径是成员表里的 `last_read_message_id`：成员滚到消息列表底部时前端上报
`POST /groups/{id}:read`，后端只存"读到哪一条"，不逐条记已读，避免消息多时写放大。

## 8. 配置

| 变量 | 作用 |
|---|---|
| 模型端点 | 后台「模型端点」或 `POST /admin/model-endpoints`，capability=chat，需 openai 兼容 `chat_completions` |
| `DASHSCOPE_API_KEY` | 语音转写。**当前未配置**，语音只存不转；配好即自动生效，并可用 `:transcribe` 补历史语音 |
| `DOC_NEXUS_DATA_MASK_MODE` | 默认 `mask`；云端端点自动脱敏，回环/私网原样发送 |
| `DOC_NEXUS_DATA_MASK_MEDIA_POLICY` | 默认 `block`，图片不出网（所以群聊图片不送视觉模型） |

### DeepSeek 官方端点参考配置（2026-11 官网）

| 字段 | 值 |
|---|---|
| 供应商标识 | `deepseek` |
| 接入方式 | **OpenAI 兼容接口**（选「OpenAI」会被强制成 Responses 协议，助手用不了） |
| API 协议 | `chat_completions` |
| 能力 | `chat` |
| Endpoint URL | `https://api.deepseek.com/v1` |
| 模型 | `deepseek-flash`（默认；支持视觉）、`deepseek-v4-pro`（不支持视觉） |
| 上下文 / 最大输出 | 1,000,000 / 384K |
| 超时 | 端点 `timeout_ms` 会被实际采用（默认 30000 偏短） |

旧的 `deepseek-chat` / `deepseek-reasoner` 已不是官网当前模型名，别再用。

**两个请求参数是必需的**（`group_assistant` 会自动带上）：

```json
{"response_format": {"type": "json_object"}, "thinking": {"type": "disabled"}}
```

- 不带 `thinking: disabled` 时，DeepSeek 默认开启思考模式，`max_tokens` 会被推理烧光，
  正式答案是**空字符串**（实测 2048 token 时稳定复现）。
- `response_format: json_object` 让模型保证输出合法 JSON；识别不出 JSON 时它会把内容
  换成空格，所以 `plain_llm` 对空内容直接报错，不把空串丢给解析器。
- `thinking` 只在 provider 含 `deepseek` 时发送，避免其他 OpenAI 兼容服务因未知字段 400。

## 10. 已知限制

1. PDF/Word/Excel **不抽正文**，AI 读不到（见 §6）。
2. 图片不送视觉模型（策略默认拦截），AI 读不到画面。
3. 语音需要 `DASHSCOPE_API_KEY` 才能转写；未配时 AI 读不到。
4. 没有实时推送，靠 5 秒轮询增量拉取；高并发下要换成 SSE/WebSocket。
5. 没有 @提醒、消息撤回、已读回执明细、跨群搜索。
6. 前端是自建页，**不在原 React 应用的构建里**，原厂若升级出群聊功能，需要决定保留还是切回。
7. 去重按标题字面比较：模型如果换一种说法描述同一件事，仍会建出第二条。
8. 模型端点必须 `chat_completions` 协议；Anthropic `messages` 端点会明确报错，不静默降级。

## 11. 用多个 MES 账号模拟多人

MES 里有 6 个账号，其中 5 个可作为群成员：

| MES 账号 | 姓名 | 角色 |
|---|---|---|
| `admin` | 管理员 | 系统管理员 |
| `sales` | 王销售 | 销售员 |
| `planner` | 李计划 | 计划员 |
| `keeper` | 张仓管 | 仓管员 |
| `worker` | 赵车间 | 车间调度 |
| `qc` | 孙质检 | 质检员 |

镜像到 AI 侧的脚本（与 MES 单点登录同一套 `mes_auth.sync_user`，本地密码是随机值，
真实认证只走 MES）：

```python
from app.core import database
from app.services import mes_auth
with database.transaction() as db:
    mes_auth.sync_user(db, {"userName": "sales", "realName": "王销售", "isAdmin": False})
```

模拟多人发言不必让每个人真的登录，直接给他们签发本地访问令牌即可：

```python
from app.core.security import create_access_token
from app.models.auth import User
with database.transaction() as db:
    user = db.query(User).filter(User.display_name == "王销售").one()
    token = create_access_token(user.id, user.role, user.auth_version)
```

注意：脚本必须在 `doc-nexus-ai/backend/` 目录下跑，否则读不到同一个 `.env`，
JWT 密钥不同，签出来的令牌一律 401（踩过）。

## 12. 开通语音识别（需要人工操作一次）

代码这边已经接好，缺的只是一把阿里云百炼的 key。

1. **开通百炼**：<https://bailian.console.aliyun.com/> 用阿里云账号登录，按提示开通
   「百炼大模型服务」（需实名，开通后按量计费，不调用不花钱）。
2. **拿业务空间 ID**：控制台里切到业务空间 / 空间管理，能看到形如 `llm-xxxxxxxxxxxxxxxx`
   的 **Workspace ID**。
3. **建 API Key**：控制台右上角头像 → API-KEY → 创建，复制 `sk-` 开头的串。
   北京和新加坡的 key 不通用，注意地域。
4. **确认模型可用**：模型广场搜 `qwen-audio-3.1-asr-flash`（或 3.0）。
5. **写进 `.env`**（`doc-nexus-ai/.env`）：

```bash
DASHSCOPE_API_KEY=sk-你的key
DOC_NEXUS_DASHSCOPE_ASR_URL=https://<WorkspaceId>.cn-beijing.maas.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation
DOC_NEXUS_DASHSCOPE_ASR_MODEL=qwen-audio-3.1-asr-flash
```

6. **重启 AI 后端**，然后在群聊页按住说话。

注意三点：

- 仓库里原来那个 URL 的 WorkspaceId（`llm-o2dmtl9qx5a7ssmk`）**不是你的空间**，必须替换。
  官方也支持旧域名 `https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/generation`，
  workspace 域名不通时可退回去试。
- 单次音频**最长 5 分钟**，前端录到 4 分 30 秒自动收尾；超限会标「语音超过识别上限」。
- 录音格式用 **WAV 16 kHz 单声道**（`frontend-group/audio-wav.js` 自己编码）。
  浏览器默认的 `webm` 不在 ASR 的 `format` 支持列表里，直接用会被拒。
- 计费按音频时长，约 0.00022 元/秒（北京 ≈ 0.8 元/小时，以官方价格页为准）。
