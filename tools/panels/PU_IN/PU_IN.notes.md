### 2.3 detail.tabs[0].fields（18 个明细字段，key=items）
条形码（文本）/ 仓库*（参照 WH，默认 原料仓）/ 项目（参照 PROJ）/ 存货名称*（参照 INV，refMap 带出 编码/规格/采购单位）/ 存货编码（文本）/ 规格型号（文本）/ 数量*（小数）/ 材质（下拉框）/ 采购单位*（下拉框 件/kg/套/升）/ 计量单位组合（文本 computed）/ 批号（文本）/ 折扣%（小数，默认 0）/ 单价*（小数）/ 税率%（小数，默认 13）/ 含税单价（computed）/ 金额（computed）/ 税额（computed）/ 含税金额（computed）。

**calc 计算链**（金额 computed + calc 链，对齐真实 T+ 价税分离）：
```
含税单价 = 单价 * (1 + 税率% / 100)
金额     = 数量 * 单价
税额     = 数量 * (含税单价 - 单价)
含税金额 = 金额 + 税额
计量单位组合 = 数量（显示占位）
```
summaryItems：数量合计 / 金额合计 / 税额合计 / 含税金额合计。

## 五、注意事项

1. gridTabs 列名 = 明细字段名（规范 §八.8.1 历史事故：列与明细字段对不上会空白）；本配置 gridTabs[0] 16 列、gridTabs[1] 9 列均 ⊆ detail.tabs[0].fields（18 个）已验证。
2. 真实列「智能选单」（RowSelectVoucher）是 T+ 行内选单按钮列，非数据字段，本配置未建字段定义（列表按文本兜底渲染空值）；「存货图片」同按规范 §四.布尔/图片列 处理（未入 gridTabs[0]）。
3. 查询区真实为 8 项，本配置 6 项（补 业务员/项目 参照、去 票据类型/供应商编码/应付余额 到表头字段），符合任务 3-6 个要求。
4. 审批：任务指定 单据状态 三态（草稿/已审核/已中止），审核组用 审核/弃审 直接过审；若后续要并入审批流，把 PU_IN 加进 `APPROVAL_PANELS`（engine.js L11434）即可自动补「审批」组与「审批中」状态，无需改本配置。
5. 未实现按钮（引入常用单据/设置默认功能/生成采购发票/生成付款申请单/生成凭证/查找/刷新/导出/退出 等）保留占位，点击走 engine.UNIMPLEMENTED 提示（规范 §三.5），界面与 T+ 保持一致。
6. 界面风格：无卡通/表情/装饰（规范 §四/§14.4 定稿）。
